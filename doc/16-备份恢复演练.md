# 16 · 备份恢复演练

> 备份没被恢复过就等于没有备份。本篇记录**一次真实做过的恢复演练**:用了哪份备份、每条判据的实际观测值、踩到的环境限制,以及复现步骤。

## 为什么需要这篇

`scripts/backup.sh` 从上线起每天在跑,连续 14 天日志全绿——但那只证明**脚本没报错**,不证明**恢复出来能用**。数据库与对象存储是两份独立快照,脚本自己也在注释里承认它们不是同一瞬间(bag 里可能多几个没有行的对象、少几个有行没对象的引用)。这些不确定性只能靠真的恢复一次来暴露。

## 判据

判定标准必须落在**可核对的字节与计数**上,不能是"服务起来了":

| # | 判据 | 通过条件 |
|---|---|---|
| 1 | pg 恢复 | `pg_restore` 退出码 0,无 ERROR |
| 2 | 库内计数 | `nodes` / `blobs` / `users` / `shares` / 文件节点数与生产一致 |
| 3 | 库对象自洽 | 库里每个 `blobs.sha256` 都能在对象备份里找到对应路径;反之亦然(零缺失、零孤儿) |
| 4 | 对象字节完整 | 备份里的对象文件与生产卷里的同名文件 sha256 逐个一致 |
| 5 | 异地副本完整 | 异地副本与本地副本的 sha256 一致 |
| 6 | 应用可用 | 用**生产真实账号密码**能登录;`usedBytes` 与备份时刻一致;抽查文件下载后 sha256 与库内 `node.sha256` 一致 |

## 2026-09-18 演练记录

**用的备份**:`db-2026-09-18.dump`(72363 B)+ `minio-2026-09-18.tar.gz`(32770594 B),从**异地副本**(`yuyun:/srv/gopan-backup/`)拉取——刻意不用本地那份,否则验证不到异地链路。

| 判据 | 实际观测 | 结果 |
|---|---|---|
| 1 | `pg_restore` 退出码 0,`ERROR` 行数 0 | 通过 |
| 2 | 恢复库 `29\|24\|1\|1\|21`,生产库 `29\|24\|1\|1\|21` | 完全一致 |
| 3 | 库内 blob 24 个,tar 内对象 24 个;缺失 0、孤儿 0 | 通过 |
| 4 | 生产卷与备份逐文件比对:38 个文件(24 个 `xl.meta` + 14 个 `part`)**全部一致** | 通过 |
| 5 | tar 与 dump 的 sha256 本地/异地相同(`348d614d…`) | 通过 |
| 6 | 登录成功;`usedBytes=19422882` `quota=5368709120` `admin=true`;根目录 8 项(含中文目录名);下载 6 个文件(11MB PDF / 8MB PDF / 149B PNG / 两张截图 / 一张 jpeg),sha256 **全部一致** | 通过 |

演练还顺带验证了 **schema 前滚**:备份时 goose 版本 15,与当前一致;历史遗留提示——若二进制版本更高,启动时会自动跑迁移(迁移只加不减,这条策略在恢复场景同样成立)。

**结论:备份链路可用。** 从异地副本到可登录、可列目录、可下载且字节一致,全链路走通。

## 踩到的两个环境限制(不是备份问题)

演练选择在本机 WSL 上做,和生产有两处不兼容,值得记下来:

1. **PostgreSQL 版本**:本机是 16.15,生产是 17。`pg_restore` 拒绝读取 PG17 生成的 dump(报 `unsupported version (1.16) in file header`)。绕法:在服务器的 PG17 容器里执行 `pg_restore -f -` 把 dump 转成纯 SQL,再拿到低版本上执行。
2. **PG17 新增语法**:转出来的 SQL 含两处低版本不认的东西,执行前需要过滤:
   - `\restrict` / `\unrestrict` 元命令(PG 17.6 起 `pg_dump` 会写,PG16 的 psql 直接语法错误)
   - `SET transaction_timeout = 0`(`transaction_timeout` 是 PG17 新增 GUC)

   ```bash
   grep -v -E '^\\(un)?restrict|transaction_timeout' db.sql > db-clean.sql
   ```

**真正的事故恢复应该在同版本 PG17 上做**(直接用 `docker compose exec postgres`),上面两条只在"想在本机低版本上演练"时才会遇到。

## 复现步骤

```bash
# 1. 从异地副本取件(不要用本地那份,否则验证不到异地)
mkdir -p /tmp/drill && cd /tmp/drill
scp -o BatchMode=yes yuyun:/srv/gopan-backup/db-<日期>.dump .
scp -o BatchMode=yes yuyun:/srv/gopan-backup/minio-<日期>.tar.gz .

# 2. 只看不改:在服务器上对着临时库恢复(绝不碰 gopan 库)
cd /opt/gopan
C="docker compose -f docker-compose.prod.yml"
$C exec -T postgres createdb -U gopan gopan_drill
$C exec -T postgres pg_restore -U gopan -d gopan_drill --clean --if-exists < /var/backups/gopan/db-<日期>.dump
# 判据 2:与生产对照计数
$C exec -T postgres psql -U gopan -d gopan_drill -tAc \
  "select (select count(*) from nodes)||'|'||(select count(*) from blobs)||'|'||(select count(*) from users)"

# 3. 判据 3:库里的 blob 引用必须都能在对象 tar 里找到
tar tzf /tmp/drill/minio-<日期>.tar.gz > /tmp/tarlist.txt
$C exec -T postgres psql -U gopan -d gopan_drill -tAc "select sha256 from blobs" \
  | tr -d '\r' | grep -E '^[0-9a-f]{64}$' | sort -u > /tmp/db_shas.txt
grep -oE '^\./gopan/blobs/[0-9a-f]{2}/[0-9a-f]{64}/$' /tmp/tarlist.txt \
  | sed 's|^\./gopan/blobs/[0-9a-f]*/||; s|/*$||' | sort -u > /tmp/tar_shas.txt
comm -23 /tmp/db_shas.txt /tmp/tar_shas.txt   # 必须为空
comm -13 /tmp/db_shas.txt /tmp/tar_shas.txt   # 孤儿(GC 未清,无害)照实记录

# 4. 判据 4:对象字节与生产卷逐文件比对
VOL=$(docker volume ls -q | grep miniodata | head -1)
VP=$(docker volume inspect $VOL --format '{{.Mountpoint}}')
cd "$VP" && find gopan/blobs -type f \( -name 'part.*' -o -name 'xl.meta' \) -exec sha256sum {} \; | sort -k2 > /tmp/prod.txt
mkdir -p /tmp/dc && tar xzf /tmp/drill/minio-<日期>.tar.gz -C /tmp/dc
cd /tmp/dc && find gopan/blobs -type f \( -name 'part.*' -o -name 'xl.meta' \) -exec sha256sum {} \; | sort -k2 > /tmp/bak.txt
diff /tmp/prod.txt /tmp/bak.txt && echo "字节一致"

# 5. 判据 6:起一个隔离实例做端到端(用独立库、独立 MinIO 端口与数据目录)
#    注意 MinIO 是小对象内联、大对象分 part 存储,不要拿单个 part 的 sha256 去比对象名 ——
#    那会得出"全部不匹配"的错误结论。要比就比"备份的字节 vs 生产的字节"。
#    端到端可用 scripts/smoke 里的思路:登录 -> children -> node.downloadUrl -> sha256 比对。

# 6. 收尾(必做)
$C exec -T postgres dropdb -U gopan gopan_drill
rm -rf /tmp/drill /tmp/dc /tmp/tarlist.txt /tmp/*_shas.txt
```

## 节奏

- 每次改 `scripts/backup.sh` **之后必跑一次**。
- 常规**每季度一次**。
- 不自动化:演练要起隔离实例、结果要人看,做成定时任务只会得到"自动通过"的假信心。

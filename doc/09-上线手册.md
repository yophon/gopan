# 09 · 上线手册

从裸机到可用,目标 20 分钟。前提:一台有公网 IP 的 Linux 主机、一个解析到它的域名、装好 Docker(含 compose 插件)。

## 部署档位

同一份 `docker-compose.prod.yml`,靠 `.env` 里的 `COMPOSE_PROFILES` 决定跑几个容器。选档看两件事:内存多大、80/443 有没有被占。

| | 档 A · 全家桶 | 档 B · 精简 |
|---|---|---|
| 适合 | 4G+ 内存,机器上没别的反代 | 2G 小机,或宿主已有 nginx 占着 80/443 |
| `COMPOSE_PROFILES` | `office,caddy` | 留空 |
| 容器 | postgres、minio、gotenberg、gopan、caddy | postgres、minio、gopan |
| 常驻内存 | ~800MB(Gotenberg 里的 LibreOffice 占大头) | ~350MB |
| 反代与证书 | 容器里的 Caddy 全自动 | 宿主 nginx,证书自己签(见 `deploy/nginx/gopan.conf.example`) |
| Office 在线预览 | 有 | **没有**——点开提示下载,图片/视频/PDF/文本预览照常 |

关 Gotenberg 必须同时在 `.env` 里显式写 `GOPAN_GOTENBERG_URL=`(空值)。后端据此知道本次部署不提供 Office 转换:不再入队转换任务、预览状态直接回 `UNAVAILABLE`,前端给下载引导。漏了这行的话,任务会排队等一个不存在的服务,一路 failed 到重试上限。

小机上想保留 Office 预览也行:`COMPOSE_PROFILES=office`(不要 caddy),并给 `GOTENBERG_MEM_LIMIT=512m` 上枷锁——但 swap 要留够。

## 首次部署

```bash
# 1. 拿代码
git clone git@github.com:yophon/gopan.git /opt/gopan && cd /opt/gopan

# 2. 准备配置:.env.example 里两档各一段,选一档改
cp .env.example .env && vi .env
mkdir -p secrets && openssl rand -base64 48 > secrets/jwt_secret
# 容器里 gopan 跑在 uid 10001(非 root),secret 必须给它读:属主 10001 + 400。
# 留成 root:root 600 的话,gopan 会以 "permission denied" 反复重启。
chown 10001:10001 secrets/jwt_secret && chmod 400 secrets/jwt_secret && chmod 600 .env

# 3. 构建 + 启动(国内机器给构建加代理:在 compose 的 build.args 里放开 GOPROXY 注释)
docker compose -f docker-compose.prod.yml up -d --build

# 4. 档 B 才需要:配宿主 nginx(档 A 的 Caddy 自动签证书,跳过这步)
cp deploy/nginx/gopan.conf.example /etc/nginx/conf.d/pan.example.com.conf
vi /etc/nginx/conf.d/pan.example.com.conf     # 改域名、证书路径
acme.sh --issue -d pan.example.com -w /var/www/html
nginx -t && systemctl reload nginx

# 5. 验证
docker compose -f docker-compose.prod.yml ps          # 全部 healthy
curl -fsS https://pan.example.com/healthz             # ok
```

打开 `https://{域名}` 注册首个账号,然后完整走一遍:上传一张图(看列表缩略图)→ 上传一个 100MB 文件(看分片进度)→ 同文件再传(秒传)→ 双击预览 → 建分享并访客下载 → 文件夹打包下载 → 生成应用密码用 rclone/Finder 挂 `https://{域名}/dav` 传一个文件 → 打开“Agent 接入”创建只读 API Key并用它初始化 `/mcp`。全通即上线完成。

MCP/OAuth 发现也应从公网域名返回公网地址:

```bash
curl -fsS https://pan.example.com/.well-known/oauth-protected-resource
curl -fsS https://pan.example.com/.well-known/oauth-authorization-server
curl -sS -D- -X POST https://pan.example.com/mcp -o /dev/null
# 最后一条应为 401,WWW-Authenticate 含公网 resource_metadata URL
```

**收尾**:把首个账号提为管理员(之后建号/调配额都在界面里做,不用再碰 psql):

```bash
docker compose -f docker-compose.prod.yml exec gopan gopan admin promote <你的用户名>
```

然后 `.env` 里 `GOPAN_REGISTER_OPEN=false`,`up -d` 生效;装备份 cron(见下)。

## 架构与端口

```
档 A  浏览器 ──443──▶ Caddy(容器) ──┬── /gopan/* ──▶ minio:9000   (分片直传/预签名直取)
                                    └── 其余      ──▶ gopan:8080   (GraphQL / MCP / OAuth / WebDAV / SPA)

档 B  浏览器 ──443──▶ nginx(宿主) ──┬── /gopan/* ──▶ 127.0.0.1:19000  (MinIO)
                                    └── 其余      ──▶ 127.0.0.1:18080  (gopan)

backend 网(internal,不通公网):postgres、minio、gotenberg、gopan
```

档 B 里 gopan 和 MinIO 各绑一个 **127.0.0.1** 端口给宿主 nginx 转发(`GOPAN_HTTP_BIND` / `MINIO_S3_BIND` 可改,端口撞了就换)。两档都一样:数据库、MinIO 控制台、pprof 一概不对外。

**预签名与反代的约定**(改动前先读):预签名 URL 是 `https://{域名}/{bucket}/{key}?X-Amz-…`,S3 V4 签名把 Host 和路径都签进去了。所以反代按 `/gopan/*`(bucket 名)转发 MinIO,**不剥前缀、透传 Host**。若改 `GOPAN_S3_BUCKET`,必须同步改 Caddyfile 或 nginx 的路由。nginx 侧还有两个坑:`proxy_set_header Host $host`(默认会改写成 upstream 名,一改就 403)、`client_max_body_size ≥ 32m`(分片 16MB,默认 1m 直接卡死上传;`/gopan/` 里另设 5g——Agent 的单 PUT 直传整个文件一个请求体,32m 会让 32–64MB 的 Agent 上传 413)——模板 `deploy/nginx/gopan.conf.example` 里都写好了。另外 `GOPAN_S3_REGION` 保持与 MinIO 一致(默认 us-east-1)——region 显式配置后 minio-go 才不会向 public endpoint 发 GetBucketLocation 探测。`/gopan/*` 的响应还要加两个头:`Content-Security-Policy: sandbox; default-src 'none'; …` 与 `X-Content-Type-Options: nosniff`(两份模板都已写好)。预签名地址与站点同源,对象响应却不经过 gopan、没有站点的 CSP,上传的 svg / html 被直接打开时脚本会以站点身份运行;后端也已把内联预签名的响应类型显式改写(脚本类按纯文本返回、svg 加 attachment),反代这层是兜底。**验证方式**:`curl -sI '<任一预览地址>'` 能看到这两个头。MCP/OAuth 元数据也依赖原始 Host 与 `X-Forwarded-Proto/Host`,代理必须按模板透传、后端必须配好下面的 `GOPAN_TRUSTED_PROXIES`,否则 Agent 会发现内网 `http://gopan:8080` 或 `http://` 开头的地址。

反代还会影响**客户端 IP**。后端默认只信 `RemoteAddr`,而它在反代后面拿到的是容器网关地址,所以经反代部署时必须让 `GOPAN_TRUSTED_PROXIES` 覆盖反代所在网段(compose 已给 docker 私有网段的默认值)。不配的后果是静默的:登录/验密/WebDAV 限速退化成"全站共用一个桶"——一个人试错密码会把所有人挡在门外;登录设备页记的 IP 也没有意义。nginx 模板里已经透传了 `X-Forwarded-For`,后端侧配对即可。**验证方式**:登录一次,在"登录设备"页看到的应该是自己的公网 IP 而不是 `172.x`。

同一个开关也管 OAuth / MCP 的对外地址:只有请求来自可信代理时,后端才认 `X-Forwarded-Proto` / `X-Forwarded-Host`,其余来源带的这两个头一律丢掉,防止绕过反代直连端口的客户端伪造它们、污染返回给别人的 metadata。所以没配时,经 https 反代访问的 MCP 客户端会拿到 `http://` 开头的 issuer,OAuth 授权失败。

镜像约 490MB,大头是静态 ffmpeg/ffprobe 双二进制(~210MB;apt 版依赖树更夸张,会到 730MB)。对单机自部署这是一次性拉取成本,不再压缩。v3.2 起运行层多了 poppler-utils + poppler-data(内容搜索提 PDF 文字,中文 PDF 靠 poppler-data 的 CMap);走 `Dockerfile.prebuilt` 只换二进制的,第一次构建会在老运行层上补装一次(apt,不编译),之后就是一次检查。

## 升级

```bash
cd /opt/gopan && git pull
docker compose -f docker-compose.prod.yml up -d --build gopan
```

数据库迁移在 gopan 启动时自动执行(goose,幂等)。前端 embed 在二进制里,无独立发布物。

**无 Docker 的开发机(例如 Windows 上只有 Go 与 pnpm)**:不在小内存服务器上 build(doc/10),改为本地交叉编译二进制、服务器上只 COPY 一层:

```bash
# 开发机
cd web && pnpm install --frozen-lockfile && pnpm build && cd ..
rm -rf server/cmd/gopan/dist && cp -r web/dist server/cmd/gopan/dist
(cd server && CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags='-s -w' -o ../gopan-linux ./cmd/gopan)
scp gopan-linux Dockerfile.prebuilt <host>:/opt/gopan/
# 服务器(先 git pull 让代码与镜像一致)
cd /opt/gopan && docker build -f Dockerfile.prebuilt -t gopan:latest . \
  && docker compose -f docker-compose.prod.yml up -d --no-build gopan
```

`Dockerfile.prebuilt` 以现有 `gopan:latest` 为基础层(运行时 + 静态 ffmpeg 不变),只替换 `/usr/local/bin/gopan`。`gopan-linux` 已在 `.gitignore`。旧二进制那一层不会去掉,每次部署镜像涨 30 MB 左右(`docker history gopan:latest` 可见);攒多了在网好的机器上用完整 `Dockerfile` 重建一次再推过去。

**升到 v3.3(离线下载与压缩包)**:不加系统包,只换二进制(+2.3 MB),迁移 00023 启动时自动跑。在 `.env` 里加一行 `GOPAN_FETCH_DENY=<这台机器的公网 IP>` 再 `up -d`(compose 已透传 `GOPAN_FETCH` / `GOPAN_FETCH_DENY` / `GOPAN_FETCH_RATE`);gopan 容器本来就挂在能出网的 edge 网络上。上线后拿内网地址试一次离线下载,应失败为「这个地址不允许访问」。

浏览器上传 staging 版本有额外升级要求：停止旧服务后部署新二进制及前端，旧版未完成上传需要重新上传；不要混跑旧、新服务。见 [上传一致性修复与兼容说明](./15-浏览器上传一致性修复.md)。

## 回滚

```bash
git checkout <上一个 tag 或 commit>
docker compose -f docker-compose.prod.yml up -d --build gopan
```

迁移策略是**只加不减**:旧版二进制跑在新 schema 上安全(多出的表/列不碍事),所以回滚不需要动数据库。除非发布说明里明确标注了不兼容迁移——那种发布必须先备份再升。

## 安卓安装包发布

安卓 App 的「检查更新」读本站的 `/api/app/android/latest`,安装包也从本站下:仓库是私有的,App 不能匿名读 GitHub Releases。
`docker-compose.prod.yml` 已经把宿主的 `./android-release` 只读挂到容器的 `/data/android-release`,并设好 `GOPAN_APP_RELEASE_DIR`。
目录里没有 `latest.json` 时接口回 404,App 提示「这个站点没有提供安卓安装包」。

发版时先放安装包,`latest.json` 最后整体替换,手机就不会看到一个指向不存在文件的版本:

```bash
# 开发机
scp gopan-3.0.0.apk <host>:/opt/gopan/android-release/
# 服务器
cd /opt/gopan/android-release
APK=gopan-3.0.0.apk
cat > latest.json.tmp <<EOF
{"versionCode":30100,"versionName":"3.0.0","apk":"$APK",
 "sha256":"$(sha256sum "$APK" | cut -d' ' -f1)","size":$(stat -c %s "$APK"),
 "notes":"一两句更新说明","publishedAt":"$(date -u +%FT%TZ)"}
EOF
mv latest.json.tmp latest.json
curl -fsS https://pan.example.com/api/app/android/latest          # 版本号与 sha256 对得上
curl -sSI https://pan.example.com/api/app/android/latest.apk      # 302 到当前安装包
```

- `versionCode` 必须与安装包里的一致(`android/app/build.gradle.kts`),App 只在它比自己大时提示更新。
- 接口只认 `latest.json` 声明的那一个文件(同目录、`.apk` 结尾),并要求 64 位十六进制的 `sha256`;不合法时回 500 `bad_release`,App 显示「检查更新失败」。
- 每次请求现读,不用重启 gopan。旧安装包留着不碍事、也下不到,确认新版没问题再删。
- `/api/app/android/latest.apk` 是给首次安装的固定链接,总是 302 到当前安装包。
- 安装包由 gopan 直接输出(不走 MinIO 预签名,约 5 MB,支持 Range),反代不需要额外配置。
- 不发安卓包的实例删掉 compose 里的 `GOPAN_APP_RELEASE_DIR` 与挂载两行,接口回 404 `not_configured`。

## 磁盘维护

这台 39G 的小盘上,吃空间的常常不是数据而是 Docker 的构建缓存 —— 每次 `up -d --build` 都会往里堆几百 MB 到几 GB(实测一次重建能堆出 4.3G)。先看清再动手:

```bash
df -h /                  # 整体水位
docker system df         # 镜像 / 容器 / 卷 / 构建缓存各占多少,以及各自可回收量
journalctl --disk-usage  # systemd 日志(默认无上限,能长到几 G)
```

回收:

```bash
docker builder prune -af               # 构建缓存(代价:下次构建慢一点)
journalctl --vacuum-size=500M          # 日志收到 500M
```

**第一条已经进了 cron**(每周日 5 点,保留 7 天内的缓存),不用手动跑,除非磁盘告急。`/etc/systemd/journald.conf` 里的 `SystemMaxUse=500M` 是永久上限,否则日志会慢慢长回来。

**红线:不要用 `docker system prune -a` / `docker image prune -a` / `docker volume prune`。**
这台机器上除了 gopan 还跑着别的项目(sub2api 及其 Postgres/Redis),那三条命令会删掉所有"当前没有运行中容器"的镜像与卷,把别的服务一起干掉。要删就点名删。

**回滚镜像的轮换**:每次上线后打一个新 tag,并删掉最旧的那个,保持只有一两个:

```bash
docker tag gopan:latest gopan:rollback-$(date +%Y%m%d)-$(git rev-parse --short HEAD)
docker image ls --format '{{.Repository}}:{{.Tag}}' | grep gopan   # 确认后点名删最旧的
```

## 备份与恢复

```bash
# 每日 4 点备份,保留 7 份(db dump + minio 卷 tar)
crontab -e
0 4 * * * cd /opt/gopan && ./scripts/backup.sh >> /var/log/gopan-backup.log 2>&1

# 小盘(如 13G):备份是全量快照,7 份 ≈ 7 倍用量,会把盘写满 → 连带打挂同机所有服务。
# 保留 2 份,并强烈建议配异地备份(见下)。
0 4 * * * cd /opt/gopan && KEEP_DAYS=2 ./scripts/backup.sh >> /var/log/gopan-backup.log 2>&1
```

脚本自带水位预检:待备份量 × 1.2 超过可用空间就直接中止(exit 1)、不写一个字节——宁可这次不备份,也不能把盘写满。

**异地备份**(防整机故障)按手上有什么选一种:

**① 有第二台机器时首选:rsync over ssh。** 增量推送、可续传,对端不需要装任何服务端程序,只要一个 sshd。

一次性准备(在**备份机**上):装 rsync、建备份目录、把**主机的**公钥追加进 `~/.ssh/authorized_keys`(用 `>>` 追加,别覆盖已有的)。然后在**主机**的 `~/.ssh/config` 里给备份机起个别名,并确认免密在**非交互**下可用 —— cron 里既没有 tty 也没有 ssh-agent,交互式能连不代表 cron 能连:

```bash
cat >> ~/.ssh/config <<'EOF'
Host yuyun
    HostName <备份机IP>
    User root
    IdentityFile /root/.ssh/id_ed25519
    IdentitiesOnly yes
EOF
ssh-keyscan -t ed25519 <备份机IP> >> ~/.ssh/known_hosts   # 首次
ssh -o BatchMode=yes -o ConnectTimeout=10 yuyun "echo ok"  # 必须成功
```

cron 行加 `BACKUP_OFFSITE_SSH`:

```bash
0 4 * * * cd /opt/gopan && KEEP_DAYS=2 BACKUP_OFFSITE_SSH=yuyun ./scripts/backup.sh >> /var/log/gopan-backup.log 2>&1
```

- 异地默认落在 `/srv/gopan-backup`(`BACKUP_OFFSITE_DIR` 可改),默认保留 30 天(`BACKUP_OFFSITE_KEEP_DAYS` 可改)。每天新增量很小(实测 minio tar 14.5~21.8MB + db dump 约 68KB),30 天约 550MB。
- **刻意不用 `rsync --delete`**:本地留 2 份、异地留 30 份是两套策略,异地的旧副本不该被本地策略带着删。
- 异地失败**不影响本地备份**,但会打警告、写 `.offsite-fail`,并以**退出码 9** 收尾(9 = 本地成功、仅异地失败)。没配 MTA 的 cron 不会因此发信,所以要么定期人查,要么另外接告警。
- 查状态:`./scripts/backup.sh --status` —— 打印本地最新 dump、异地上次成功时间、异地目录实况。

**② 没有第二台机器:rclone。** 装 rclone 并 `rclone config` 配一个远端(任意 S3/R2/网盘),cron 行加环境变量即可:

```bash
0 4 * * * cd /opt/gopan && BACKUP_REMOTE=r2:gopan-backup ./scripts/backup.sh >> /var/log/gopan-backup.log 2>&1
```

恢复(新机或事故后):

```bash
docker compose -f docker-compose.prod.yml up -d postgres minio   # 先只起存储
docker compose -f docker-compose.prod.yml exec -T postgres \
    pg_restore -U gopan -d gopan --clean --if-exists < /var/backups/gopan/db-<日期>.dump
VOLUME=$(docker volume ls -q | grep miniodata)
docker run --rm -v "$VOLUME":/data -v /var/backups/gopan:/backup debian:bookworm-slim \
    sh -c 'rm -rf /data/* && tar xzf /backup/minio-<日期>.tar.gz -C /data'
docker compose -f docker-compose.prod.yml up -d
```

db 和 minio 备份不是同一瞬间的快照,恢复后可能有少量 blob 行找不到对象(下载 404)或对象没有行(等 GC 清)。凌晨备份窗口里这个缝隙极小,自用可接受。

异地副本的恢复步骤完全一样,只是先把文件拉回来:`scp -r yuyun:/srv/gopan-backup /tmp/restore`,再把上面的 `/var/backups/gopan` 换成 `/tmp/restore`。

**定期演练**:备份没被恢复过就等于没有备份。至少每季度在一台**非生产**实例上按上面步骤真恢复一次,并用"备份库里的 blob 引用能否在对象 tar 里找到、抽样的文件 sha256 是否对得上"来判定通过与否。完整判据与实战记录见 `doc/16-备份恢复演练.md`。

## 排障

| 症状 | 先看 |
|---|---|
| 整体不可用 | `docker compose -f docker-compose.prod.yml ps`,谁不 healthy 看谁的 logs |
| gopan 反复重启 + secret permission denied | `secrets/jwt_secret` 属主不是容器 uid:`chown 10001:10001 secrets/jwt_secret && chmod 400` |
| 上传/预览 403 | 预签名与反代约定被破坏:bucket 名、Host 透传、SSL 配置三查(见上) |
| 上传卡住不动 | MinIO healthy?浏览器 Network 里分片 PUT 的实际报错 |
| Office 不出预览 | 先确认档位:`.env` 里没有 office profile 就是**故意关的**(预览应显示 UNAVAILABLE 引导下载)。开了还不出:gotenberg 容器日志;`requestPreview` 后 tasks 表该 blob 的 office_pdf 行 status/last_error |
| 视频无封面 | gopan 容器里 `ffmpeg -version`;tasks 表 video_cover 行 last_error |
| MCP 客户端一直未授权 | 先 curl 两个 `/.well-known/oauth-*` 地址;确认返回公网 HTTPS,再看 `/mcp` 的 `WWW-Authenticate` |
| OAuth 授权后回调失败 | client redirect URI 必须与 DCR 注册值完全一致;非 loopback 必须 HTTPS,PKCE 必须 S256 |
| Agent 上传停在 processing/verifying | 查 `transfer_sessions.status/fail_reason`;确认 worker 运行、staging 对象存在且用户配额足够 |
| 日志/设备页里的客户端 IP 都是 172.x | `GOPAN_TRUSTED_PROXIES` 没覆盖反代所在网段。它不报错、只静默记错;配好后重新登录一次才会记到真实 IP |
| MCP 客户端授权失败,`/.well-known/oauth-authorization-server` 里的地址是 `http://` | 同上:反代不在 `GOPAN_TRUSTED_PROXIES` 里,后端不认 `X-Forwarded-Proto` |
| 离线下载全部失败「这个地址不允许访问」 | 宿主机若跑着 fake-ip 代理(Clash 等),域名都解析到 198.18.x.x,被当成保留地址拒绝:设 `GOPAN_FETCH_ALLOW_PRIVATE=true`。否则看是不是链接本身指向内网 |
| 离线下载卡在「排队中:等待重试」 | 源站 5xx 或网络断了,按 30 秒 × 次数退避,最多 3 次;`user_jobs` 表看 `error_message` |
| 压缩包一直「正在读取目录」 | tasks 表该 blob 的 `archive_index` 行;压缩的 tar 很大时要整包解一遍才列得出 |
| 性能问题 | pprof 只绑容器内 127.0.0.1:6060:`docker compose exec gopan curl -s localhost:6060/debug/pprof/profile?seconds=10 > /tmp/prof` 再取出分析 |

日志是 JSON(slog),`docker compose logs -f gopan | grep -v '"msg":"http"'` 过滤访问日志看业务事件。日志里不打 token、密码、预签名 URL。

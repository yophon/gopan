# 09 · 上线手册

从裸机到可用,目标 20 分钟。前提:一台有公网 IP 的 Linux 主机、一个解析到它的域名、装好 Docker(含 compose 插件)。

## 部署档位

同一份 `docker-compose.prod.yml`,靠 `.env` 里的 `COMPOSE_PROFILES` 决定跑几个容器。选档看两件事:内存多大、80/443 有没有被占。

| | 档 A · 全家桶 | 档 B · 精简 |
|---|---|---|
| 适合 | 4G+ 内存,机器上没别的反代 | 2G 小机,或宿主已有 nginx 占着 80/443 |
| `COMPOSE_PROFILES` | `office,caddy` | 留空 |
| 容器 | postgres、minio、gotenberg、gopan、caddy | postgres、minio、gopan |
| 常驻内存 | ~800MB(Gotenberg 里的 LibreOffice 占大头) | ~350MB |
| 反代与证书 | 容器里的 Caddy 全自动 | 宿主 nginx,证书自己签(见 `deploy/nginx/gopan.conf.example`) |
| Office 在线预览 | 有 | **没有**——点开提示下载,图片/视频/PDF/文本预览照常 |

关 Gotenberg 必须同时在 `.env` 里显式写 `GOPAN_GOTENBERG_URL=`(空值)。后端据此知道本次部署不提供 Office 转换:不再入队转换任务、预览状态直接回 `UNAVAILABLE`,前端给下载引导。漏了这行的话,任务会排队等一个不存在的服务,一路 failed 到重试上限。

小机上想保留 Office 预览也行:`COMPOSE_PROFILES=office`(不要 caddy),并给 `GOTENBERG_MEM_LIMIT=512m` 上枷锁——但 swap 要留够。

## 首次部署

```bash
# 1. 拿代码
git clone git@github.com:yophon/gopan.git /opt/gopan && cd /opt/gopan

# 2. 准备配置:.env.example 里两档各一段,选一档改
cp .env.example .env && vi .env
mkdir -p secrets && openssl rand -base64 48 > secrets/jwt_secret
# 容器里 gopan 跑在 uid 10001(非 root),secret 必须给它读:属主 10001 + 400。
# 留成 root:root 600 的话,gopan 会以 "permission denied" 反复重启。
chown 10001:10001 secrets/jwt_secret && chmod 400 secrets/jwt_secret && chmod 600 .env

# 3. 构建 + 启动(国内机器给构建加代理:在 compose 的 build.args 里放开 GOPROXY 注释)
docker compose -f docker-compose.prod.yml up -d --build

# 4. 档 B 才需要:配宿主 nginx(档 A 的 Caddy 自动签证书,跳过这步)
cp deploy/nginx/gopan.conf.example /etc/nginx/conf.d/pan.example.com.conf
vi /etc/nginx/conf.d/pan.example.com.conf     # 改域名、证书路径
acme.sh --issue -d pan.example.com -w /var/www/html
nginx -t && systemctl reload nginx

# 5. 验证
docker compose -f docker-compose.prod.yml ps          # 全部 healthy
curl -fsS https://pan.example.com/healthz             # ok
```

打开 `https://{域名}` 注册首个账号,然后完整走一遍:上传一张图(看列表缩略图)→ 上传一个 100MB 文件(看分片进度)→ 同文件再传(秒传)→ 双击预览 → 建分享贴到微信(出卡片)→ 访客下载 → 文件夹打包下载。全通即上线完成。

**收尾**:把首个账号提为管理员(之后建号/调配额都在界面里做,不用再碰 psql):

```bash
docker compose -f docker-compose.prod.yml exec gopan gopan admin promote <你的用户名>
```

然后 `.env` 里 `GOPAN_REGISTER_OPEN=false`,`up -d` 生效;装备份 cron(见下)。

## 架构与端口

```
档 A  浏览器 ──443──▶ Caddy(容器) ──┬── /gopan/* ──▶ minio:9000   (分片直传/预签名直取)
                                    └── 其余      ──▶ gopan:8080   (GraphQL / SPA / /s / /pack)

档 B  浏览器 ──443──▶ nginx(宿主) ──┬── /gopan/* ──▶ 127.0.0.1:19000  (MinIO)
                                    └── 其余      ──▶ 127.0.0.1:18080  (gopan)

backend 网(internal,不通公网):postgres、minio、gotenberg、gopan
```

档 B 里 gopan 和 MinIO 各绑一个 **127.0.0.1** 端口给宿主 nginx 转发(`GOPAN_HTTP_BIND` / `MINIO_S3_BIND` 可改,端口撞了就换)。两档都一样:数据库、MinIO 控制台、pprof 一概不对外。

**预签名与反代的约定**(改动前先读):预签名 URL 是 `https://{域名}/{bucket}/{key}?X-Amz-…`,S3 V4 签名把 Host 和路径都签进去了。所以反代按 `/gopan/*`(bucket 名)转发 MinIO,**不剥前缀、透传 Host**。若改 `GOPAN_S3_BUCKET`,必须同步改 Caddyfile 或 nginx 的路由。nginx 侧还有两个坑:`proxy_set_header Host $host`(默认会改写成 upstream 名,一改就 403)、`client_max_body_size ≥ 32m`(分片 16MB,默认 1m 直接卡死上传)——模板 `deploy/nginx/gopan.conf.example` 里都写好了。另外 `GOPAN_S3_REGION` 保持与 MinIO 一致(默认 us-east-1)——region 显式配置后 minio-go 才不会向 public endpoint 发 GetBucketLocation 探测,那个地址对服务端是不可达的(内网无出网)。

镜像约 490MB,大头是静态 ffmpeg/ffprobe 双二进制(~210MB;apt 版依赖树更夸张,会到 730MB)。对单机自部署这是一次性拉取成本,不再压缩。

## 升级

```bash
cd /opt/gopan && git pull
docker compose -f docker-compose.prod.yml up -d --build gopan
```

数据库迁移在 gopan 启动时自动执行(goose,幂等)。前端 embed 在二进制里,无独立发布物。

## 回滚

```bash
git checkout <上一个 tag 或 commit>
docker compose -f docker-compose.prod.yml up -d --build gopan
```

迁移策略是**只加不减**:旧版二进制跑在新 schema 上安全(多出的表/列不碍事),所以回滚不需要动数据库。除非发布说明里明确标注了不兼容迁移——那种发布必须先备份再升。

## 备份与恢复

```bash
# 每日 4 点备份,保留 7 份(db dump + minio 卷 tar)
crontab -e
0 4 * * * cd /opt/gopan && ./scripts/backup.sh >> /var/log/gopan-backup.log 2>&1

# 小盘(如 13G):备份是全量快照,7 份 ≈ 7 倍用量,会把盘写满 → 连带打挂同机所有服务。
# 保留 2 份,并强烈建议配异地备份(见下)。
0 4 * * * cd /opt/gopan && KEEP_DAYS=2 ./scripts/backup.sh >> /var/log/gopan-backup.log 2>&1
```

脚本自带水位预检:待备份量 × 1.2 超过可用空间就直接中止(exit 1)、不写一个字节——宁可这次不备份,也不能把盘写满。

**异地备份**(可选,防整机故障):装 rclone 并 `rclone config` 配一个远端(任意 S3/R2/网盘),cron 行加环境变量即可:

```bash
0 4 * * * cd /opt/gopan && BACKUP_REMOTE=r2:gopan-backup ./scripts/backup.sh >> /var/log/gopan-backup.log 2>&1
```

恢复(新机或事故后):

```bash
docker compose -f docker-compose.prod.yml up -d postgres minio   # 先只起存储
docker compose -f docker-compose.prod.yml exec -T postgres \
    pg_restore -U gopan -d gopan --clean --if-exists < /var/backups/gopan/db-<日期>.dump
VOLUME=$(docker volume ls -q | grep miniodata)
docker run --rm -v "$VOLUME":/data -v /var/backups/gopan:/backup debian:bookworm-slim \
    sh -c 'rm -rf /data/* && tar xzf /backup/minio-<日期>.tar.gz -C /data'
docker compose -f docker-compose.prod.yml up -d
```

db 和 minio 备份不是同一瞬间的快照,恢复后可能有少量 blob 行找不到对象(下载 404)或对象没有行(等 GC 清)。凌晨备份窗口里这个缝隙极小,自用可接受。

## 排障

| 症状 | 先看 |
|---|---|
| 整体不可用 | `docker compose -f docker-compose.prod.yml ps`,谁不 healthy 看谁的 logs |
| gopan 反复重启 + secret permission denied | `secrets/jwt_secret` 属主不是容器 uid:`chown 10001:10001 secrets/jwt_secret && chmod 400` |
| 上传/预览 403 | 预签名与反代约定被破坏:bucket 名、Host 透传、SSL 配置三查(见上) |
| 上传卡住不动 | MinIO healthy?浏览器 Network 里分片 PUT 的实际报错 |
| Office 不出预览 | 先确认档位:`.env` 里没有 office profile 就是**故意关的**(预览应显示 UNAVAILABLE 引导下载)。开了还不出:gotenberg 容器日志;`requestPreview` 后 tasks 表该 blob 的 office_pdf 行 status/last_error |
| 视频无封面 | gopan 容器里 `ffmpeg -version`;tasks 表 video_cover 行 last_error |
| 性能问题 | pprof 只绑容器内 127.0.0.1:6060:`docker compose exec gopan curl -s localhost:6060/debug/pprof/profile?seconds=10 > /tmp/prof` 再取出分析 |

日志是 JSON(slog),`docker compose logs -f gopan | grep -v '"msg":"http"'` 过滤访问日志看业务事件。日志里不打 token、密码、预签名 URL。

## 配置速查(全部 GOPAN_ 前缀)

| 变量 | 默认 | 说明 |
|---|---|---|
| DB_URL | 必填 | Postgres 连接串 |
| JWT_SECRET / JWT_SECRET_FILE | 必填,≥32 字节 | 生产用 _FILE 走 secrets |
| S3_ENDPOINT / S3_PUBLIC_ENDPOINT | 127.0.0.1:9000 / 同内部 | 内部操作地址 / 预签名对外地址 |
| S3_USE_SSL / S3_PUBLIC_USE_SSL | false / 继承内部 | 生产:内 false 外 true |
| S3_KEY / S3_SECRET / S3_BUCKET | gopan / … / gopan | 改 bucket 须同步 Caddyfile |
| S3_REGION | us-east-1 | 显式 region,跳过 GetBucketLocation 探测 |
| REGISTER_OPEN | true | 建号后关掉 |
| DEFAULT_QUOTA | 100GB | 每用户配额(字节) |
| PART_SIZE | 16MiB | ≥5MiB(S3 规定) |
| TRASH_TTL | 720h | 回收站保留期 |
| GOTENBERG_URL | — | Office→PDF 服务地址。**置空 = 本次部署关闭 Office 预览**(不再入队转换,前端引导下载) |
| FFMPEG_PATH / FFPROBE_PATH | ffmpeg / ffprobe | 缩略图、封面、时长,镜像里已带 |
| LISTEN / PPROF_LISTEN | :8080 / 127.0.0.1:6060 | pprof 永不对外 |

**compose 侧变量**(不带 GOPAN_ 前缀,只影响容器怎么跑,不进应用配置):

| 变量 | 默认 | 说明 |
|---|---|---|
| COMPOSE_PROFILES | 空 | `office` 开 Gotenberg,`caddy` 开自带反代;两个都写 = 全家桶 |
| GOPAN_HTTP_BIND / MINIO_S3_BIND | 127.0.0.1:18080 / :19000 | 宿主反代的转发目标,端口冲突时改 |
| GOPAN_MEM_LIMIT / MINIO_MEM_LIMIT / PG_MEM_LIMIT / GOTENBERG_MEM_LIMIT | 0(不限) | 容器内存上限,小机建议逐个设 |
| PG_SHARED_BUFFERS / PG_MAX_CONNECTIONS | 128MB / 100 | 2G 机器可压到 32MB / 30 |

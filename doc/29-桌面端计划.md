# 29 · 桌面端计划(Windows)

> 结论先行:桌面端只做浏览器做不到的那部分。主窗口直接打开线上的网页版(界面与功能和网页一致,网页更新桌面端立刻跟着有),外壳用 **Tauri 2** 补上原生能力:关窗口缩到托盘、后台传输不停、文件夹下载到本地目录、传输助手常驻托盘并弹通知、快捷键截图传图床、资源管理器右键上传。先只做 Windows,和网页、安卓用同一个版本号一起发布。

## 一、目标与边界

**目标**:一个 Windows 程序,装上就能用网页版的全部功能;另外:

1. 关掉窗口缩到托盘,传输接着跑,退出要从托盘菜单退;
2. 下载文件夹时逐个文件存到电脑上选的目录(保留目录结构,不打 zip,没有 2 GB 限制),断点续传、校验 sha256;上传电脑上的文件、文件夹不怕刷新页面;
3. 传输助手常驻:托盘点开一个小窗(最近消息、输入框、把文件拖进来就发);手机发来消息、文件时弹系统通知;
4. 截图上传:全局快捷键调出系统截图框选,截好自动传到图床,直链或 Markdown 复制到剪贴板;
5. 资源管理器右键「上传到 gopan」「发到传输助手」。

**不做**(这一版):

- macOS、Linux(打包签名要那台机器;Tauri 本身跨平台,以后要做不用重写);
- 本地文件夹双向同步、挂载成盘符(WebDAV 已能挂;同步坑多,见 doc/28);
- 本地软件编辑、存盘自动传回新版本(放第二版,见第九节);
- 代码签名证书:先不买。未签名的安装包第一次运行会弹「Windows 已保护你的电脑」,点「更多信息 → 仍要运行」;发布页写清楚。

**后端改动最小**:GraphQL、上传协议、图床接口原样复用;只加桌面端的发布与更新接口,见第五节。

## 二、为什么是「网页 + 原生外壳」

| 方案 | 界面 | 代价 | 结论 |
|---|---|---|---|
| 全原生(WinUI 3 / C#) | 全部重写 | 工作量接近安卓原生重写;以后网页每加一个功能要写第三份;安装包 30~80 MB | 不选 |
| C# 外壳 + WebView2 | 网页 | 效果同 Tauri,安装包大(.NET 运行时) | 不选 |
| Electron | 网页 | 安装包 100 MB 以上 | 不选 |
| **Tauri 2(Rust 外壳 + WebView2)** | 网页 | 安装包 5~10 MB;托盘、全局快捷键、通知、自动更新、开机启动、单实例都有官方插件;本机已有 Rust 1.97 与 WebView2 运行时 | **选它** |

## 三、技术选型

| 项 | 选择 | 说明 |
|---|---|---|
| 外壳 | Tauri 2,Rust stable | `desktop/` 目录,单独的 Cargo 工程 |
| 主窗口 | 加载线上网页(默认 `https://drive.979687.xyz`,设置里可改成自部署的地址) | 同源,登录 cookie、刷新逻辑都不用改;网页更新不用重新发桌面版 |
| 本地页面 | 连接页(检查服务器、连不上时改地址重试)、设置窗口 | 打包在程序里的两个静态页;传输助手小窗就是网页的会话页(`/chat?embed=1`) |
| 网页 ↔ 原生 | Tauri IPC,只对配置的服务器域名开放一小组 `desktop_*` 命令(运行时按设置加 capability) | 网页拿不到任意文件读写、命令执行这类能力 |
| 后台工作 | 放在 Rust 里:传输引擎、新消息检查 | 隐藏窗口里网页的计时器会被内核降频(最长一分钟一次),后台的事不靠它 |
| HTTP | reqwest(rustls) | 预签名 PUT/GET、Range 续传;GraphQL 手写少量查询 |
| 本地状态 | SQLite(rusqlite,自带编译):传输队列;设置是程序配置目录里的 `settings.json` | 杀进程、重启后接着传 |
| 插件 | tray(内置)、single-instance、global-shortcut、dialog、opener、autostart、updater、window-state、process | 都是 Tauri 官方插件;系统通知用 tauri-winrt-notification,剪贴板用 arboard,右键菜单写注册表用 winreg,「发送到」快捷方式用 windows 的 COM 接口 |
| 安装包 | NSIS,按用户安装(不要管理员权限),内嵌 WebView2 引导程序 | Windows 11 自带 WebView2 |
| 自动更新 | Tauri updater,更新包用 minisign 密钥签名;私钥放 `releases/gopan/`(和 APK 签名证书一起,不进仓库) | 这个签名只防更新包被篡改,不是 Windows 代码签名 |
| 测试 | Rust 单元测试(队列状态、Windows 文件名、退避、轮询间隔、命令行参数、通知文案);网页 vitest;本机跑开发版连本地服务端走一遍 | 开发版用另一个程序标识,不和装好的、正在用的那份抢单实例 |

## 四、登录与凭据

- 登录就是网页版的登录(Yophon ID 或密码),在主窗口里完成;WebView2 的 cookie 存在程序自己的数据目录,下次打开仍是登录状态。
- 原生这边**不存任何凭据**。要调接口时(传输、检查新消息)通过 IPC 向网页要当前的 access token,网页按原有逻辑在快过期时刷新后给出;网页那边是事件驱动,不受隐藏窗口降频影响。
- 网页登出 / 会话失效时通知原生:停掉传输、清空队列与本地临时文件(下一个登录的可能是别人)。
- 小窗里的网页有自己的会话,原生只认主窗口交来的 token;两个窗口共用一份 WebView2 数据,登录状态是一样的。
- 打开站外链接(分享出去的链接、帮助页等)交给系统浏览器;Yophon ID 的登录跳转留在主窗口里。

## 五、后端与仓库改动

**服务端**(小):

- `GET /api/app/desktop/latest`:Tauri updater 认的 JSON(版本、说明、发布时间、`windows-x86_64` 的安装包地址与签名);`GET /api/app/desktop/info`(发布页用);`GET /api/app/desktop/<安装包名>`、`GET /api/app/desktop/latest.exe`(固定下载链接)。代码在 `httpx/desktopupdate.go`,发布目录 `GOPAN_APP_RELEASE_DIR/desktop/`(`latest.json` + 安装包)。
- UA 里带 `gopan-desktop/<版本>` 的请求(窗口里的网页和程序自己都带):传输助手消息来源记成 `desktop`(网页、安卓显示「电脑」),登录设备显示「Windows 桌面端」。
- 传到传输助手文件夹的文件:消息来源跟着发起上传的那个请求走。上传会话里存下来源,worker 定稿时取回;以前定稿时一律记成 web,桌面端发的文件会被自己当成「别的设备发来的」弹通知。
- 发布页 `/app` 加「下载 Windows 版」(Windows 电脑上首屏就是它),写明 SmartScreen 提示怎么点。

**网页**(小):`web/src/desktop/` 桥接层,在桌面端里才生效,浏览器里什么都不做:

- 提供 access token、登录登出通知(`bridge.ts`);
- 「下载」在桌面端交给原生:文件、文件夹、多选都原样下到设置里的下载目录,菜单里另有「下载到…」先选目录(`nodeDownload.ts`,文件页、最近、搜索、预览、传输助手都走它);
- 传输抽屉里多一组「本机」:原生的下载与上传(暂停 / 继续 / 重试 / 取消 / 打开 / 在文件夹中显示)(`transfers.ts`);
- 右键菜单「上传到 gopan…」时在主窗口里选云端文件夹,沿用「移动到」的文件夹选择框(`pick.ts`、`DesktopUploadPicker.vue`);
- 小窗(`/chat?embed=1`)只显示会话,不要导航、上传抽屉、播放条;点到别处(文件所在的文件夹等)交给主窗口打开;
- 上传在桌面端交给原生(3.15.0):选文件、选文件夹、拖进来、拖进传输助手,网页照旧走自己的流程(问同名替换、认拖进哪个文件夹),只在入队那一步把 File / FileSystemHandle 用 WebView2 的 `postMessageWithAdditionalObjects` 交给外壳,外壳读出本地路径交给传输引擎(`handoff.ts` / `handoff.rs`)。网页不报路径,外壳只认 WebView2 交来的对象,网页造不出指向任意文件的 File。主窗口不开 Tauri 的拖放处理,网页自己的拖放(把文件拖进文件夹移动)照旧;粘贴的截图仍走网页上传;
- 「用本地程序打开」(3.15.0):文件右键、预览右上角;外壳下到缓存目录、用默认程序打开,之后盯着这份副本,存盘后传成新版本(`edits.ts` / `edits.rs`,见第六节);
- 账户菜单里加「桌面端设置」,打开外壳自己的设置窗口(服务器地址、下载目录、截图快捷键、复制格式、新消息通知、右键菜单、开机启动)。

截图上传不经过网页:原生直接用网页交来的 token 传 `/api/img/upload`,再把结果复制到剪贴板。

**仓库**:新增 `desktop/`;发版流程(doc/09)加桌面安装包;CHANGELOG 照旧一份。

## 六、工程结构

```
desktop/
  package.json            Tauri CLI(开发依赖)
  src/                    本地静态页:连接页 index.html、设置 settings.html
  src-tauri/
    Cargo.toml
    tauri.conf.json       窗口、安装包、updater 公钥
    capabilities/         本地页面的权限;远程网页的权限运行时按服务器地址加(bridge.rs)
    windows/hooks.nsh     卸载时清掉右键菜单、「发送到」与开机启动项(自动更新时不清)
    src/
      main.rs / lib.rs    启动、插件、单实例(右键菜单交来的参数也在这里接)
      ui.rs / tray.rs     窗口(关闭 = 隐藏、站外链接交给系统浏览器)、托盘(单击小窗、双击主窗口)
      bridge.rs           连接服务器、放行它的 IPC;desktop_* 命令(打招呼、交 token、开窗口)
      auth.rs / api.rs    网页交来的 token;GraphQL 与 UA
      transfer/           传输引擎:队列(db.rs,SQLite)、下载(download.rs,Range 续传、sha256)、上传(upload.rs,initUpload → 分片 PUT → completeUpload,同名文件夹合并进去)、文件名(names.rs)
      handoff.rs          网页交来的文件(WebView2 postMessageWithAdditionalObjects)→ 本地路径 → 上传
      edits.rs            用本地程序打开:缓存副本、每 2 秒看一眼、存盘停下后传回(替换上传,旧内容进历史版本);打开期间云端变了就另存「(电脑上的修改)」
      chat.rs             新消息检查(登录着时 10 秒一次),系统通知
      clipsend.rs         剪贴板发到传输助手(快捷键 / 托盘):复制的文件 → 上传,图片 → PNG 上传,文字 → 一条消息(超过 4000 字节存成 .txt)
      capture.rs          全局快捷键 → ms-screenclip 截图 → 盯剪贴板 → 传图床 → 复制结果
      shell.rs            右键菜单与「发送到」的注册、清理;命令行参数(--upload / --send)攒成一批
      settings.rs / prefs.rs  设置的读写与设置窗口的命令
      updater.rs / notify.rs  自动更新、系统通知
```

## 七、里程碑

每一步单独可发版。

### D1 · 能装能用

- Tauri 工程、主窗口加载网页、登录状态保留、窗口位置大小记住;
- 关窗口缩到托盘;托盘菜单:打开 gopan、退出;单实例(再双击图标只是把窗口叫出来);
- 首次启动填服务器地址(默认生产地址),连不上时给提示页与重试;
- 站外链接用系统浏览器打开;开机启动开关;
- 安装包(NSIS)、自动更新(updater + 服务端 `/api/app/desktop/`)、发布页下载按钮、发版流程。

**验收**:本机安装 → 登录 → 关窗口在托盘 → 重新打开仍登录;发一个新版本,旧版本里自动提示并更新成功;卸载干净。

### D2 · 传得稳

- 原生传输引擎:下载文件 / 文件夹到电脑(选目录、保留目录结构、续传、校验、同名处理),上传电脑上的文件 / 文件夹(分片、秒传、续传);队列持久化,重启后接着传;
- 网页的「下载」在桌面端走原生;传输抽屉显示原生任务;托盘图标提示进度,传完弹通知(点开所在文件夹)。

**验收**:下一个几 GB、几百个文件的文件夹,中途断网、退出程序再打开都能接着下完,内容校验一致;同样规模的上传。

### D3 · 传输助手常驻

- 托盘菜单「传输助手」、单击托盘图标打开小窗(屏幕右下角):最近消息、输入框、把文件拖进小窗就发、收到的文件点开 / 另存;
- 新消息系统通知(自己从这台电脑发的不提醒);点通知打开小窗。

说明:Windows 的托盘图标本身接不住拖进来的文件,所以「拖到托盘发送」改成「拖进小窗发送」。

**验收**:手机发一条文字和一张图,电脑几秒内弹通知,小窗里能看到、能打开;往小窗拖三个文件,手机上收到。

### D4 · 截图上传

- 全局快捷键(默认 `Ctrl+Alt+Q`,设置里可改;避开 QQ / 微信常用的 `Ctrl+Alt+A`)调出系统截图框选(Windows 自带的截图工具,`ms-screenclip:`);截好图进剪贴板后自动传到图床;
- 复制格式可选:直链 / Markdown / HTML;传完弹通知;
- 另一个快捷键「上传剪贴板里的图片」(先用别的工具截好的)。

**验收**:按快捷键框选一块屏幕,几秒内剪贴板里是能打开的 Markdown 链接,图床文件夹里多了这张图。

### D5 · 右键菜单

- 文件、文件夹右键「上传到 gopan…」(弹小窗选目标文件夹)、「发到传输助手」;同时放进「发送到」菜单(多选一次传全部);
- 安装时注册、卸载时清理。Windows 11 的新式右键菜单要给程序加包标识(签名的 MSIX 稀疏包),这一版先放在「显示更多选项」和「发送到」里。

**验收**:资源管理器里多选 5 个文件右键上传,进同一个任务批次;发到传输助手的在手机上能看到。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 隐藏窗口里网页的计时器被降频 | 后台的事全在 Rust 里;网页只在被调用时给 token、做上传图床这类一次性的事 |
| 远程网页拿到原生能力的安全面 | 只对配置的服务器域名开放,命令只有 `desktop_*` 一小组,参数全校验;不开放任意文件读写与命令执行;文件路径只来自原生的选择对话框 |
| 未签名安装包被 SmartScreen 拦 | 发布页写清楚怎么点;装的人多了以后再考虑买证书 |
| 通知点击回到程序:未打包程序的通知需要开始菜单快捷方式与 AppUserModelID | 安装包建快捷方式并设好 ID;开发版里点通知可能没反应,以安装版为准 |
| Windows 11 新式右键菜单要包标识 | 先用经典菜单与「发送到」 |
| updater 私钥丢失就没法给老版本推更新 | 私钥和 APK 签名证书放在一起备份,写进发版手册 |
| WebView2 常驻内存约 150 MB | 小窗与主窗口共用一个进程;主窗口隐藏时不释放(要保登录与网页状态),在文档里说明 |

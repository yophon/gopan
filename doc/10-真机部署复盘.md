# 10 · 真机部署复盘

2026-07-12,第一次把 gopan 装进真机(racknerd 小鸡:2 核 2G,39G 盘剩 13G,机器上已经跑着 blog/board 等一堆站)。
doc/09 是"该怎么做",这篇是"当时踩了什么、为什么"。**部署新机器前先扫一遍这里,能省一小时。**

结论先行:M1~M6 全绿的代码,在一台从没部署过的机器上仍然连炸三处——全部是"开发机上恰好成立、干净环境里不成立"的假设。

## 一、干净 clone 构建必挂:codegen 产物没入库

Dockerfile 的前端阶段写着:

```dockerfile
# codegen 产物已提交进仓库,这里只需 vite 构建
```

但 `.gitignore` 里躺着 `/web/src/api/gen/`。两句话直接打架,而**开发机上感受不到**:本地 `make gen` 生成过这些文件,`docker build` 的 context 从工作区拿,构建照样过。只有在一台干净 clone 的机器上才会暴露——`pnpm build` 找不到 `src/api/gen/graphql.ts`,构建当场失败。

修:产物入库(与 Dockerfile 注释一致)。改 GraphQL schema 后记得 `make gen` 并把产物一起提交。

**教训**:生成物要么入库、要么在构建里生成,不能"假设它在"。而"注释写了 A、配置做的是 B"这种矛盾,只有干净环境能验出来——开发机永远是脏的。

## 二、gopan 反复重启:secret 属主不对

手册原来写:

```bash
openssl rand -base64 48 > secrets/jwt_secret && chmod 600 secrets/jwt_secret
```

镜像里 gopan 跑在非 root 的 uid 10001(`useradd -r -u 10001 gopan`),而 root:root 600 的文件挂进容器后,uid 10001 读不了:

```
{"level":"ERROR","msg":"fatal","err":"read GOPAN_JWT_SECRET_FILE: open /run/secrets/jwt_secret: permission denied"}
```

一秒重启一次,`ps` 里永远是 `Restarting`。

坑在于:compose 的 secrets **支持 `uid`/`gid`/`mode` 字段,但那是 swarm 专属**,非 swarm 的 `docker compose up` 直接忽略,文件权限原样透传。所以只能改宿主上的属主:

```bash
chown 10001:10001 secrets/jwt_secret && chmod 400 secrets/jwt_secret
```

**教训**:非 root 容器 + 挂载文件 = 永远先想 uid 对不对。compose 文档里"支持"的字段,要看清楚是不是 swarm-only。

## 三、小内存机器不能在机上构建

`docker compose up -d --build` 是手册里的标准动作,但在 2G 机器上它会跑 `pnpm install` + `vue-tsc` + `vite build` + `go build`——node 构建轻松吃 1~2GB。这台机器可用内存只有 1.1G,swap 1G 还用掉了 3/4。

真正的风险不是"构建失败",而是**构建触发 OOM killer,把同机的 blog、board 一起杀掉**。为一个新服务的部署赔上已经在跑的服务,不划算。

改成别处构建、把镜像整个搬过去:

```bash
# 开发机(arm64 Mac)交叉构建 amd64
docker buildx build --platform linux/amd64 -t gopan:latest --load .
docker save gopan:latest | gzip -1 | ssh <host> 'gunzip | docker load'
# 服务器只做启动,不 build
docker compose -f docker-compose.prod.yml up -d --no-build
```

为此 Dockerfile 里两个构建阶段钉在 `--platform=$BUILDPLATFORM`(构建机原生架构跑,不进 QEMU),Go 用 `GOARCH=${TARGETARCH}` 交叉编译,只有最终运行时层是目标架构。整个构建里唯一被 QEMU 模拟的是运行时层那句 `apt-get install ca-certificates curl`,几十秒的事。

**教训**:"在服务器上 build"是个只对宽裕机器成立的默认动作。小机器上,构建是比运行更重的负载,而且它的爆炸半径覆盖整台机器。

## 四、端口与反代:别人先到

- **8080 被占**(sub2api)。gopan 改绑 `127.0.0.1:18080`,MinIO 绑 `127.0.0.1:19000`,都做成 `.env` 变量。
- **80/443 被宿主 nginx 占**。compose 自带的 Caddy 起不来,也不该起——机器上已经有一套 acme.sh + nginx 的证书体系,再塞一个 Caddy 就是两套证书管理打架。Caddy 挪进 `caddy` profile,不激活即不存在。

换 nginx 后有两个 Caddy 时代不存在的坑(模板 `deploy/nginx/gopan.conf.example` 里都写死了):

1. `proxy_set_header Host $host` —— nginx 默认把 Host 改写成 upstream 名。S3 V4 预签名把 Host 签进了签名,一改就 403。
2. `client_max_body_size 32m` —— 默认 1m,分片是 16MiB,不改就是所有上传 413。

**教训**:自部署项目的 compose 默认"整机独占"(自带反代、自带证书、抢 80/443),但真实的个人服务器往往已经住着别的服务。所以"独占"必须是可关的档位,不能是硬编码。

## 五、Office 预览不是删掉,是关掉

Gotenberg 里的 LibreOffice 常驻 300~500MB,是全家桶里最大的内存开销。2G 机器上装不下,得关。

但"关"不能只是不起容器:service 层照样会往 `tasks` 表里入队 `office_pdf`,worker 拿到任务,去连一个不存在的 `http://gotenberg:3000`,失败、重试、直到重试上限。用户看到的是转圈然后"转换失败",数据库里堆一批死任务。

正确的关法是让后端知道自己被裁剪了:`GOPAN_GOTENBERG_URL` 置空 = 本次部署不提供 Office 转换。此时 service 层不入队,预览状态直接回 `UNAVAILABLE`(新增的 TaskStatus 值),前端显示"本站未开启 Office 在线预览,请下载查看"。已经转好的历史产物照常能看——关的是转换能力,不是已有数据。

**教训**:功能降级要设计成后端的"已知状态",而不是让它以"依赖挂了"的形式表现出来。前者是明确的产品行为,后者是 bug 的样子。

## 六、几个小的

- **本地 dig 不可信**。开发机挂着 fake-ip 模式的代理,`dig` 任何域名都返回 `198.18.x.x`,连不存在的子域名也"解析"得出来。查 DNS 一律去服务器上查。
- **服务器 curl 也不可信**。这台机器出网被透明代理劫持,`curl https://drive.979687.xyz/healthz` 报 self-signed;而 `openssl s_client -servername` 直连本机 443 拿到的是正常的 Let's Encrypt 证书。验证本机站点用 `--noproxy '*' --resolve <域名>:443:127.0.0.1`,别被中间人骗了。
- **配额默认 100GB,盘只有 13G**。个人云盘的默认值是按"有块大盘"写的。磁盘和 Postgres、日志、其它站点共享同一分区时,盘满是**全机一起宕**,不只是云盘挂。上线前必调:这台设 5GB。
- **smoke 要跟着档位走**。M3 smoke 硬断言"Office 一定转成 DONE",在精简档下是假失败。改成读到 `UNAVAILABLE` 就走另一条断言(验证不入队),两种部署都能跑。

## 检查清单(下次装新机直接照着走)

- [ ] 目标机 `free -m`、`df -h`、`ss -lntp | grep -E ':(80|443|8080)'` 三查,决定档位与端口
- [ ] 内存 < 4G:别在机上 build,开发机 `buildx --platform linux/amd64` + `docker save | ssh docker load`
- [ ] `.env` 选档(`COMPOSE_PROFILES`),关 Gotenberg 时**务必**同时写 `GOPAN_GOTENBERG_URL=`
- [ ] `GOPAN_DEFAULT_QUOTA` 按实际剩余磁盘调,别用默认 100GB
- [ ] `chown 10001:10001 secrets/jwt_secret && chmod 400`
- [ ] 宿主反代:Host 透传 + `client_max_body_size ≥ 32m`,证书用机器上已有的那套
- [ ] `up -d --no-build` 起,`docker compose ps` 全 healthy,`curl 127.0.0.1:18080/healthz`
- [ ] smoke 打真机:`GOPAN_API=https://<域名>/query python3 m2_transfer.py`(其余同理)
- [ ] 建完首个账号 → `GOPAN_REGISTER_OPEN=false` → `up -d` 生效
- [ ] 备份 cron 装上(`scripts/backup.sh`)

# 33 · 助手

> 在 gopan 里放一个能动手的 AI 助手：「把上个月的发票挑出来放进『报销』」「这份合同讲了什么」「给旅行照片建个能上传的分享发给我」。助手跑在客户端里（内核是 tau），用的是 gopan 自己的 MCP 工具；服务器存 key、存对话、可选地转发模型请求。

## 一、用的人看到的

### 入口

- 网页（桌面端窗口里就是网页）：侧栏顶上通知铃铛旁边一个「助手」按钮（手机上在顶栏），从右边拉出面板，任何页面都能开；电脑上面板贴在右边、主内容让出位置，开着也能继续点文件列表。
- 安卓：「我的」顶上的「助手」；文件页顶栏的魔棒；多选后「更多 → 问助手」。
- 面板知道你在看什么：当前文件夹、选中的文件会作为上下文带上（「我在看 /旅行照片，选了 3 个文件」），所以可以直接说「把这几个改成日期开头」。

### 能做的

- 找：按名字、内容、类型、时间找文件；读文本、PDF、Office 文档并总结、对比、摘抄。
- 整理：建文件夹、移动、复制、改名（含批量）、放进回收站、从回收站恢复、解压。
- 分享：建分享 / 直链 / 收集链接、列出、吊销；分享能开「对方上传」。
- 其它：给传输助手发消息、查动态、查容量、网页剪藏、把网上的文件存进来。
- 不做：管理后台的事（用户、配额、站点设置）；看图（第一版不传图片给模型）。

### 助手的权限

「MCP 访问」里固定有一项「助手」，排在 API Key、OAuth 授权前面，删不掉。和别的凭证一样按权限分组设置，只是每组不是勾 / 不勾，而是三选一：

| 权限 | 管的工具 | 默认 |
|---|---|---|
| 查看文件 | 列目录、搜索、读文件内容、查容量 | 允许 |
| 修改文件 | 建文件夹、移动、复制、改名、恢复、解压 | 询问 |
| 删除文件 | 放进回收站 | 询问 |
| 存入文件 | 网页剪藏、把网址上的文件存进来 | 询问 |
| 查看分享 | 列出分享、直链、收集链接 | 允许 |
| 管理分享 | 建 / 吊销分享、直链、收集链接 | 询问 |
| 传输助手 | 读消息 / 发消息 | 读允许、发询问 |
| 查看动态 | 动态、MCP 访问记录 | 允许 |

- **允许**：直接做。
- **询问**：先弹一张确认卡，写清楚要做什么、动哪些（「移动 12 个文件到『报销』」），按钮「允许」「这次对话都允许」「不行」。
- **拒绝**：这组工具不给模型看，也调不了。
- 顶上一个总开关「停用助手」，关了所有设备上的助手都用不了。
- 也能像别的凭证一样「设置目录范围」，只让助手动某个文件夹。
- 动态里来源写「助手」，同一轮回答做的事合成一批，可以一键撤回（沿用现有的撤回）；「MCP 访问记录」里也有助手的每次调用。
- 把「管理分享」「存入文件」改成「允许」时提示一句：这两组能把东西发到外面（公开链接、访问任意网址），助手读到的文档里要是藏着坏指令，可能被利用。

### key 与模型

- **站点提供**：管理员在后台配一个或几个模型服务（比如 DeepSeek），家里人登录就能用，不用自己申请 key。管理员给每人设每日用量（token 数，0 = 不限）。
- **自己的**：每个人可以加任意多个自己的模型服务（名字、类型、地址、key、模型列表），在面板顶上一点就能切换服务和模型；用自己的不占站点额度。
- key 存在服务器上（加密），换设备不用重填。

### 怎么连模型：转发 / 直连

每台设备、每个客户端都能选，设置在「助手 → 连接方式」，**按设备记**（同一个账号，家里电脑直连、网吧电脑转发）：

- **经服务器转发**（默认）：模型请求发给 gopan，gopan 带上 key 转给模型服务。key 不下发到这台设备，适合公共电脑、别人的电脑；浏览器也不受跨域限制。代价是多绕一跳、服务器多一份流量。
- **直接连接**：设备直接请求模型服务，key 下发到这台设备内存里（不写进浏览器存储）。延迟低，服务器不经手模型请求。
  - 安卓和桌面端不受跨域限制，直连总能用。
  - 浏览器里要模型服务允许跨域（Anthropic 允许，很多 OpenAI 兼容服务不允许），或者你自己把浏览器的跨域关了。连不上时提示「这家不让浏览器直连，改用转发」并给一个切换按钮。
- **站点提供的 key 只能转发**：直连要把 key 交给设备，家里每个人就都能把管理员的 key 拿走。自己的 key 两种都行。

### 对话记录

- 存在 gopan 上：换设备接着聊；设备上不留记录，公共电脑上用完退出登录就干净了。
- 面板左侧是对话列表（标题取第一句话），能改名、删除；不占网盘容量。

## 二、整体结构

```
客户端（网页 / 桌面端 / 安卓）
  └─ tau 内核（Agent）
       ├─ 模型请求 ──转发──▶ gopan  POST /api/ai/{服务 id}/… ──▶ 模型服务
       │            └直连────────────────────────────────────▶ 模型服务
       ├─ 工具（ext-mcp-http）──▶ gopan  /mcp（登录凭证 + 助手的权限）
       └─ 对话记录 ──▶ gopan  GraphQL（按条追加）
```

- 对话的循环（发模型、调工具、再发）在客户端里跑，服务器不常驻 agent，2 GB 的机器扛得住。
- 工具就是现有的 MCP 工具，不另写一套；外面的 Claude / Cursor 用的也是它们，修一处两边都好。

## 三、服务端

### 模型服务与 key

- 新表 `ai_providers`：`id`、`owner_id`（空 = 站点提供）、`name`、`kind`（`openai` = Chat Completions 兼容 / `anthropic` / `google` / `openai-responses`，与 tau 的四种 provider 对应）、`base_url`、`models text[]`（第一个是默认）、`key_enc bytea`、`created_at`、`updated_at`。
- key 用 AES-GCM 加密，密钥从 `GOPAN_JWT_SECRET` 用 HKDF 派生（用途串 `gopan-ai-key`）；换了 JWT 密钥，已存的 key 解不开，后台和设置页标出「key 失效，请重填」。
- GraphQL：
  - `aiProviders`：自己的 + 站点的，不带 key；站点的标 `site: true`。
  - `createAiProvider` / `updateAiProvider` / `deleteAiProvider`：自己的；管理员另有 `admin…` 一组管站点的。key 只写不读，改的时候留空就是不变。
  - `aiProviderKey(id)`：直连用，只对自己的服务返回明文；站点的一律拒绝。
  - `aiUsage`：今天用了多少、站点给的上限。
- 新表 `ai_usage`：`user_id`、`day`、`provider_id`、`requests`、`input_tokens`、`output_tokens`。站点额度按它判；后台用户列表多一列「助手用量」。直连用的是自己的 key，不记。

### 转发

- `POST /api/ai/{providerId}/{path...}`，只认登录用户的 `Authorization: Bearer`。
- 只放行这类服务的对话接口：`openai` 的 `chat/completions`、`anthropic` 的 `v1/messages`、`google` 的 `models/{model}:streamGenerateContent`、`openai-responses` 的 `responses`；别的路径 404。客户端的 `baseUrl` 设成 `/api/ai/{id}`，tau 原样拼路径，不用改 tau。
- 去掉客户端带来的认证头，按 `kind` 换上真 key（`Authorization: Bearer` / `x-api-key` / `x-goog-api-key`），请求体原样转发。
- 响应流式原样回写，每块 Flush；用 `http.NewResponseController` 取消 60 秒写超时（3.19.0 修好的那个 `Unwrap` 正好用上）。
- 边转边从流里抠用量（`usage` / `message_delta.usage` / `usageMetadata`），结束后记进 `ai_usage`；OpenAI 兼容的请求补上 `stream_options.include_usage`。
- 站点额度用完返回 429 `AI_QUOTA`，面板显示「今天的站点额度用完了，可以换自己的 key」。
- **防内网探测**：自己的服务只允许 `https`，连接时解析出的地址不能是内网 / 回环 / 链路本地（拨号时检查，防 DNS 换绑）。站点提供的不限（管理员可以接本机的 Ollama）。
- 每人同时最多 4 条转发中的请求，单次最长 10 分钟。

### 助手的凭证与权限

- 每个用户一行 `assistant_access`：`user_id`（主键）、`disabled`、`policy jsonb`（权限组 → `allow` / `ask` / `deny`）、`updated_at`；没有这行就按一里的默认。目录范围复用现有的 `mcpAccessRoots`（凭证类型 `assistant`）。
- 这项凭证没有自己的密钥：`/mcp` 新增认**登录凭证**（网页 / App 自己的 access token），前提是请求带 `X-Gopan-Assistant: <对话 id>`。客户端本来就有 access token，过期了照常刷新；退出登录 / 移除设备，助手立刻失效。
- 这时的身份：
  - 权限 = 策略里不是 `deny` 的那些组对应的 scope；从不含 admin。停用时 `/mcp` 直接 403。
  - 动态来源是新的 `assistant`（显示「助手」），`ref` 是对话 id，同一轮回答的改动合成一批，按批撤回。
  - MCP 访问记录照常记，凭证名「助手」。
- **拒绝由服务端管**：没给的 scope，工具不出现在 `tools/list` 里，硬调也被拒。**询问由客户端管**：服务端分不出「问过了没有」，问不问由客户端里的 tau 判（见四）。它防手滑、防模型乱来，不防有人改客户端，而改客户端的人本来就拿着这个账号的登录凭证。
- 客户端要知道每次调用归哪个权限组：每个工具的 `_meta` 里带上它可能用到的 scope（`batch_nodes` 这类看参数的，列出全部）；有一个是 `ask` 就问。另外给所有工具补上标准的 `readOnlyHint` / `destructiveHint`，外面的 MCP 客户端也能用上。
- 权限改了下一次调用就按新的来：客户端每轮开始重新取策略，服务端每次请求现查。
- 分片上传那一组（`prepare_upload` 到 `wait_upload`）和 `prepare_download` 不给助手：模型手里没有本地文件，下载地址给它只可能被拿去外发。
- `/mcp/admin` 不对助手开放。

### 对话记录

- 新表 `ai_conversations`：`id`、`user_id`、`title`、`provider_id`、`model`、`created_at`、`updated_at`。
- 新表 `ai_entries`：`conversation_id`、`seq`、`entry jsonb`，只追加。tau 的会话本来就是一条一条追加的事件，客户端按条写进来（GraphQL `appendAiEntries(conversationId, fromSeq, entries)`，`fromSeq` 对不上就报冲突，防两台设备同时写乱）。
- 列表 / 读取 / 改名 / 删除各一个接口；删对话连带删条目。每个对话最多 2 万条、单条 1 MB。

## 四、客户端（网页 + 桌面端）

- tau 内核和 MCP 扩展单独打一个按需加载的包，点开助手才下载，首屏不变大。
- `Agent` 的配置：
  - 转发：`baseUrl = /api/ai/{id}`，`apiKey` 留空（gopan 的 fetch 包一层加上登录凭证）。
  - 直连（浏览器）：`baseUrl` = 服务地址，`apiKey` 用 `aiProviderKey` 现取，只放内存；直连 Anthropic 要加 `anthropic-dangerous-direct-browser-access: true`（走 provider 的 `headers`）。
  - `kind` 选对应的 provider 扩展；工具 = `ext-mcp-http` 连同源的 `/mcp`，带登录凭证、`X-Gopan-Assistant`（对话 id）和 `X-Gopan-Turn`（这一轮回答的批次 id，同一轮的改动合成一批撤回）。这些头由 gopan 包的那层 fetch 加，tau 不用知道。
  - 建 Agent 前先直接问一次 `/mcp` 的 `tools/list`，拿每个工具 `_meta["gopan/scopes"]` 与标注，供权限判断和确认卡用。
  - 问不问用 tau 自带的那套，gopan 不另写一套判断：
    - **规则从 gopan 来**：每轮开始取服务端存的权限，翻成 tau 的规则交给它（`allow` / `ask` / `deny`，工具名 `mcp__gopan__<工具>`；一个工具属于几组时取最严的）。tau 在浏览器、App 里读不到 `settings.json`，规则只有这一个来源，设置也只在「MCP 访问」里改一处。
    - **判断在 tau 里**：tau 的 `ToolPolicy` 本来就是「允许 / 询问 / 拒绝」三态，「拒绝」的工具它自己从模型的工具列表里拿掉。以后加的本地工具（见六）也走同一套，不会出现两处各判各的。
    - **界面是 gopan 的**：tau 要问时调 `onApproval`，gopan 弹自己的确认卡，写成「移动 12 个文件到『报销』」而不是原始参数。「这次对话都允许」记在这个对话里，之后同一工具 gopan 直接答应，不落盘。
    - 服务端照样按 scope 拒，客户端被改了也越不过「拒绝」。
  - 会话仓库换成 gopan 的：读写走三里的对话接口，不落浏览器存储。
- **桌面端直连**：窗口里的网页同样会碰到跨域，所以直连时把 tau 的 `platform.fetch` 换成外壳的 `desktop_ai_fetch`。网页只给服务 id、路径和请求体；外壳用自己手上的登录凭证向服务端取这个服务的地址和 key，只放行对话接口，换上 key 用 reqwest 发出去，响应一块块经 `desktop://ai` 事件回给网页。key 不进网页，这条命令也不能拿来当任意地址的代理；站点提供的服务外壳一律拒绝。要发一版桌面安装包。
- 系统提示（中文）：你是 gopan 网盘里的助手；先查再动；批量改动前先说清楚要动哪些；路径用用户看得懂的写法；回答用用户的语言。
- 回答按 Markdown 显示（段落、列表、粗体、代码、链接），先整段转义 HTML 再加标签，链接只认 http(s)。

## 五、tau 怎么进来

- gopan 只用 tau 已有的东西：`Agent`、四种 provider、`ext-mcp-http`、工具审批、可替换的 `platform.fetch`、可替换的会话仓库。不需要给 tau 加新功能。
- 不发 npm：用本机 tau 仓库的最新提交，编译好放进 `web/src/vendor/tau/`，和代码一起提交。
  - 脚本 `web/scripts/vendor-tau.mjs <tau 仓库路径>`：用 tau 自己的 `tsconfig.build.json` 逐包编译（kernel、ext-mcp-http、三种 provider；JS + d.ts，不要 sourcemap），写 `SOURCE.md`（tau 的提交号、生成时间、每个文件的 sha256）。
  - 包名 `@yophon/tau-*` 由 `vite.config.ts` 与 `tsconfig.json` 的别名指到这里，不进 package.json，不用装。
  - 要更新 tau 就重跑脚本，换掉这个目录。
  - 这样 gopan 不依赖 tau 公开发布，别的机器拉下 gopan 也能直接构建。安卓第二步用同一个包。
- 许可证：tau 是 MIT，`LICENSE` 随编译产物一起放在 `web/src/vendor/tau/`。

## 六、以后：读本机文件

这一版不做，但结构上先留好位置，以后加不用返工。

- **能加在哪**：
  - 桌面端：Rust 提供文件读写，包成 tau 的 `FileSystem`。
  - 安卓：Kotlin 提供，用系统的「选择文件夹」授权。
  - 浏览器：只有 Chrome / Edge 电脑版能做，让用户选一个文件夹授权（和 tau 现有的 OPFS 存储用的是同一套接口），换了浏览器或清了网站数据就要重新选。Firefox、Safari、手机浏览器做不了，那些设备上不显示这组。
- **工具**：直接用 tau 自带的读、列目录、查找、搜内容，以后要改本地文件再加它的写、改。另加一个「把本机文件传到 gopan」，走各端现成的上传引擎，大文件、断点续传都有。
- **权限**：在三态表里加「读本机文件」「改本机文件」两组，和网盘的几组放一起，同样交给 tau 判。不同的是这两组**按设备记**，存在设备上，不同步：每台设备授权的文件夹不一样，也不该让网页上改一下就放开手机上的文件。默认读「询问」、改「询问」，只能动授权过的文件夹。
- **3.20.0 已经留好的**：
  - 权限判断（`web/src/assistant/policy.ts`）吃的是「权限组 + 工具元信息」，不看工具名是不是 MCP 的；确认卡的说法按工具名查表，不认识的给通用说法。
  - 服务端的权限表只放按账号同步的组；按设备记的组以后由客户端自己存，和服务端的组合在一起交给同一个判断。

## 七、不做的

- 服务器上不跑 agent：对话循环一直在客户端，关掉页面这一轮就停了。
- 第一版不传图片给模型，不做语音。
- 助手不管后台（用户、配额、站点设置），也不给它彻底删除。

## 八、分两步

1. **3.20.0**：服务端（模型服务、转发、用量、助手凭证与权限、`/mcp` 认登录凭证、工具标注、动态来源「助手」、对话记录）+ 网页面板与设置 + 桌面端 `ai_fetch`。
2. **3.21.0**：安卓。
   - QuickJS 用 dokar3/quickjs-kt 1.0.5（1.0.6 起要 Kotlin 2.4，工程是 2.2），只打 arm64-v8a 与 x86_64 两种架构。
   - QuickJS 里跑的不是另写的一套：网页的装配代码（`agent.ts` 等）改成不依赖浏览器（站点地址、平台能力都由宿主传进来），再加一个不依赖 Vue 的运行时 `runtime.ts`（对话的收发、确认、对话记录），由 `web/scripts/build-assistant-runtime.mjs` 打成一个 iife 放进 App 的 `assets/assistant/runtime.js`。改了 `web/src/assistant` 或重新编译了 tau 之后重跑。
   - App 给它注入宿主函数：网络（OkHttp，同源请求由 App 加登录凭证、401 时换一张重试；没有跨域限制，直连、转发都行）、随机数、可取消的等待、事件、确认、停止。quickjs-kt 的 evaluate 要等所有异步任务结束才返回，所以 tau 的超时计时一旦被取消，App 这边对应的等待也要跟着取消；一次调用结束时再把残留的计时与读取清掉兜底。
   - 对话在整个 App 一份（`AssistantEngine`），离开助手页这一轮也接着跑完；登出时连同 QuickJS 一起丢掉。
   - 入口：「我的」顶上的「助手」；文件页顶栏的魔棒（带上当前文件夹）；多选后「更多 → 问助手」（带上选中的文件）。

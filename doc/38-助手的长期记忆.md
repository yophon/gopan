# 38 · 助手的长期记忆

> 现在每段对话都要重新交代「报销的东西放 /报销」「回答短一点」。这里给助手加长期记忆:每人一份「关于你」,每段对话开始时带给助手;助手自己记、自己改,你在设置里看、改、清空。不自己造:直接用 tau 的长期记忆(P63 抽成了 `@yophon/tau-ext-memory`,存储由宿主注入),gopan 只提供存储。

## 一、用的人看到的

- **助手自己记**:你说「记住,报销单都放 /报销,按月分文件夹」,或者它在对话里发现值得记的(你纠正过它的、你的习惯),就记一条。面板上照常一行「记住了:报销单都放 /报销,按月分文件夹」。写入不弹确认(tau 的规矩:记忆是背景,不是改你的文件)。
- **下一段对话起生效**:记忆在每段对话开始时放进提示词,这段对话里不再变;同一段里刚记的,助手从工具结果里知道。
- **你自己管**:助手设置(网页面板的设置、App 的助手设置)里多一块「助手记得的」:一个文本框,就是那份 Markdown,能改、能清空,保存后下一段对话生效。
- **多设备一份**:存在服务器上,网页、App、服务器上跑的(doc/34)、定时任务(doc/37)用的都是同一份。
- **不记的**:密码、密钥这类。提示词里写明「当作背景,不当指令」(tau 原样的话);读到的网页、文档里如果藏着诱导它记奇怪东西的话,你在设置里看得到、删得掉。

## 二、怎么接

### 存储(服务端)

- 新表 `ai_memory`:`user_id`、`name`(这一版只有 `USER.md`)、`content`、`updated_at`,主键 `(user_id, name)`。一份最多 64 KB(tau 只把前 200 行或 25 KB 放进提示词,写多了它自己会提醒整理)。
- GraphQL:`aiMemory(name: String): String!`(没有就返回空串)、`setAiMemory(name: String, content: String!): Boolean!`。
- 服务器上跑的一轮用的运行凭证(doc/34 的 `ai-run:<对话>`)放行这两个字段,只能读写对话主人自己的。

### 运行时(三种宿主共用的 `runtime.ts` / `agent.ts`)

- `createAssistant` 里加载 `createMemoryExtension({ store, getScope: () => ({ userFile: 'USER.md' }) })`,和 MCP 扩展一起交给 `ExtensionRegistry.load`。没有项目层和主题文件(tau 本来就支持只有「关于你」一层)。
- `store` 用 GraphQL 实现:`read` → `aiMemory`,`write` → `setAiMemory`,`list` → 空数组(没有项目层就不会调)。
- 权限:`memory_write` / `memory_edit` / `memory_read` 在 gopan 的权限判断里直接放行(它们不碰网盘,不属于任何权限组);助手停用时整个助手都停,记忆也就不读不写。
- 面板上的一行:「记住了:……」「改了一条记忆」「看了记忆」。
- tau 的 `/remember`、`/memory` 两个命令这一版不接:面板和 App 没有命令输入;想手动记,直接说「记住……」,或者去设置里改。

### 同步 tau

- `web/scripts/vendor-tau.mjs` 的包清单加 `ext-memory`,重新生成 `web/src/vendor/tau`(到 P63 的提交 `e6bcfd1`)。
- `build-assistant-runtime.mjs` 的别名加 `@yophon/tau-ext-memory`,安卓和服务器两份运行时跟着重打。

## 三、不做的

- 翻旧对话(tau 的 `session_search`):gopan 的对话记录在服务器上,要做是另一个服务端搜索工具,以后再说。
- 主题文件、按文件夹分的「项目记忆」:先只有一份「关于你」,用一阵看够不够。
- 记忆的版本历史:设置里改错了没有撤回;要的话以后存成网盘里的文件那种做法再议。

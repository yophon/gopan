# 24 · 收藏、最近打开与历史版本

> 状态:**已交付**(v3.10.0,2026-10-24)。数据见 doc/04「收藏、最近打开与历史版本」,接口见 doc/05 同名一节,用法见 doc/11「文件管理」「历史版本」。

## 一、为什么做

- 常去的文件夹每次都要一层层点进去;刚看过的文件关掉预览就得重新找。网页与 App 都缺这两个入口。
- 同名覆盖(WebDAV 客户端、rclone 改写文件)以前直接丢掉旧内容,动态里的「覆盖」也撤不回。网页上传遇到同名只能自动改名,改过的文档再传一遍就多一个 `报告 (1).docx`。

## 二、做法与取舍

### 收藏与最近

- 都是节点上的一个时刻:`nodes.starred_at`、`nodes.opened_at`。节点只有一个属主,不需要单独的表。
- 不算对文件的改动:`updated_at` 不动,不记动态。节点进回收站时字段留着,列表按 `deleted_at IS NULL` 过滤,还原后照旧。
- 「最近」只记网页 / App 的显式打开(预览成功、播放、下载时客户端调 `markOpened`)。WebDAV 与 Agent 读文件不算:同步工具一跑就会把列表冲掉。只有文件,最多 100 个。
- 收藏最多列 500 个,文件与文件夹都可以。分享访客看到的 `starred` 一律是 false。

### 历史版本

- 覆盖时旧内容进 `node_versions`,**与节点同一套记账**:旧 blob 的引用与配额原样转给版本。这样 GC、配额、空间分析都不需要特殊分支,彻底删除节点时把它的版本一起收走、退账即可。
- 版本占配额,所以空间是够不够的问题:放得下新旧两份就留旧版本;放不下时退回以前的规矩(按差额算、不留旧版本),再放不下才 `QUOTA_EXCEEDED`。不会因为想留版本而让覆盖失败。
- 同步工具高频覆盖也不能无限堆积:每个文件最多 `GOPAN_VERSION_KEEP`(默认 10)个,换下来超过 `GOPAN_VERSION_TTL`(默认 30 天)的由 worker 每小时清掉。内容没变的覆盖(重传同一个文件)不留版本、不记动态。
- 恢复 = 节点与版本互换:现在的内容留成一个新版本,选中的版本回到节点上,账不变。恢复也记一条 `OVERWRITE` 动态并带上新留的版本,所以恢复本身也能撤回。
- 动态里的覆盖记下留下的版本 id,撤回覆盖就是恢复它;没留版本的(空间不够、已被清理)照旧撤不回。
- 版本只给下载、恢复、删除,不做在线预览(预览按节点走,版本没有自己的缩略图与文字索引入口;要看就下载)。

### 替换上传

- `initUpload` 加 `replace`:目标位置有同名**文件**就覆盖它(同一个节点,分享、收藏、直链都不变),旧内容进历史版本;同名的是文件夹照旧改名。秒传路径同样处理。会话上记 `replace_existing`,定稿时同名文件已经不在了就照常新建。
- 网页端只在直接传进当前文件夹(或拖到某个文件夹上)的文件上问一次「替换 / 保留两者」;传整个文件夹时子文件夹里的同名文件照旧自动改名。
- **安卓 App 这一版不做替换上传**:App 的上传队列存在本地 Room 库里,加一个字段要写数据库迁移、还要处理队列里的旧任务,收益不抵风险。App 上能看、恢复、删除历史版本。

### 顺手修的

- 彻底删除时 `DecrementBlobRefs` 用 `= ANY`,同一个 blob 在子树里被两个文件指着只退一次引用,blob 永远回收不掉(只是漏空间,不丢数据)。改成按次数退(`DecrementBlobRefN`),版本的退账也走它。

## 三、改动范围

- 服务端:迁移 00029;`service/versions.go`(覆盖、恢复、删除、清空、到期清理)、`service/quick.go`(收藏与最近);WebDAV 覆盖、浏览器上传定稿、秒传都走 `overwriteFileTx`;彻底删除与 hash 校验失败的清理带上版本;动态撤回覆盖;空间总览加历史版本;配置 `GOPAN_VERSION_KEEP` / `GOPAN_VERSION_TTL`。
- 网页:侧栏「最近」「收藏」(`QuickView.vue`);列表与卡片的星标;右键 / 工具栏 / 手机操作表的收藏;详情抽屉里的收藏按钮与「历史版本」;上传的「替换 / 保留两者」;预览与下载上报打开;空间总览的历史版本卡片。
- 安卓:文件首页顶上「收藏」「最近」两个入口(`feature/quick`);操作表的收藏与「历史版本」面板;多选菜单的收藏;星标;预览上报打开。

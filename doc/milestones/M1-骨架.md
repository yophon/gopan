# M1 · 骨架:认证 + 目录树 + 全链路类型

> commit:`ec98065`(后端)+ `b55ce57`(前端)。交付:能登录、能建文件夹、能进回收站的最小可用云盘,以及后面三个里程碑赖以生存的**代码生成链**和**单二进制交付形态**。

M1 的真正产出不是功能(目录 CRUD 没什么难的),而是把三条"合同"立起来:数据库 schema 是一份(goose 迁移),GraphQL SDL 是一份(schema.graphqls),两份合同各自生成两端类型——sqlc 生成 Go 的查询层,gqlgen 生成 Go 的 resolver 接口,GraphQL Code Generator 生成前端 TS 类型。此后任何接口改动都从改合同开始,改完 `make gen`,类型对不上直接编译失败,前后端不存在口头约定。

## 认证:双 token 细节(service/auth.go)

- **access**:HS256 JWT,15 分钟,claims 只有 `sub`(userID)+ `scope`。权限一律实时查库,JWT 只回答"你是谁"。
- **refresh**:32 字节 crypto/rand,**数据库只存 sha256**,明文只在 Set-Cookie 时出现一次。cookie 是 httpOnly + SameSite=Lax + `Path=/query`(只随 GraphQL 请求发送)。
- **旋转**:每次 refresh,旧 token 标 `used_at`,签发同 `family_id` 的新 token。
- **重用检测**:`used_at` 非空的 token 再次出现 = 被偷且双方在用 → `RevokeRefreshFamily` 吊销整族,两端都被踢。
- **登录防侧信道**:用户不存在也跑一次 bcrypt 比对(固定假 hash),响应时间不暴露用户名是否存在。
- **限速**:进程内令牌桶(`golang.org/x/time/rate`),按 `login:{ip}` / `reg:{ip}` 分桶,每 6 秒回填一个、突发 10。

## 目录树:几条不变量的落地(service/node.go + queries/nodes.sql)

- **同层不重名**(仅活跃节点):唯一索引挡不住根目录——`parent_id IS NULL` 时 NULL 不参与唯一比较。解法是表达式索引:
  ```sql
  CREATE UNIQUE INDEX idx_nodes_sibling
      ON nodes (owner_id, COALESCE(parent_id, '00000000-…0000'::uuid), name)
      WHERE deleted_at IS NULL;
  ```
- **移动不成环**:`IsDescendant` 递归 CTE 判定目标是否在自己子树内(含自身),在事务里逐个校验后 UPDATE。
- **软删/还原/硬删都是整树操作**:三条递归 CTE(SoftDeleteSubtree / RestoreSubtree / PurgeSubtree),PurgeSubtree 用 `DELETE … RETURNING blob_id` 把被删文件引用的 blob 一次带出来(M2 起用于引用计数)。
- **回收站只列顶层**:`deleted_at IS NOT NULL` 且父节点不在回收站,还原时如果原位被占,先自动改名(`xx (还原 0102-150405).ext`)再整树还原。
- **上传重名自动加后缀**:`cleanName` 循环试 `name (1)`、`name (2)`…,唯一索引做最终兜底。
- **不区分"不存在"和"不是你的"**:都返回 NOT_FOUND,防探测。

## GraphQL 层约定(httpx/server.go + graph/)

- 业务错误统一是 `service.Error{Code, Message}`,ErrorPresenter 把 Code 放进 `extensions.code`,前端按 code 分支,**不解析错误文案**;非业务错误一律打日志、对外只说"内部错误"。
- 鉴权中间件只解析 Bearer 塞进 context,**不拦截**——是否需要身份由 resolver 决定(shareInfo 这类公开查询因此不用白名单机制)。
- `FixedComplexityLimit(300)`,introspection 只在 DevMode 开。
- 分页是游标形式、offset 实现:`base64("o:<offset>")`,对外契约是游标,以后可换实现不动接口。

## 前端骨架的两个关键件

- **client.ts 单飞刷新**:模块级 Promise 去重——并发 N 个请求同时 401,只触发一次 refresh,全部共享结果后各自重放一次;刷新也失败才清状态跳登录。`plainRequest`(auth 流程专用,防递归)和 `request`(业务)严格分开。
- **登录态只存内存**:accessToken 不进 localStorage,页面刷新靠 httpOnly cookie 静默续登录(路由守卫触发 `tryRefresh`)。

## 踩坑记录

1. **sqlc 纯 Go 分析器 vs 递归 CTE**:报"column reference is ambiguous"/"table alias does not exist"。解法:CTE 内所有列全限定(`n.id`、`s.id`),最终 SELECT 不直接从递归 CTE 出,改写成 `FROM nodes x WHERE x.id IN (SELECT s.id FROM sub s)`。此后所有递归查询沿用这个模式。
2. **gqlgen 再生成会改参数名**:resolver 手写参数名会被 regen 按 schema 名改回,曾把 `idArg` 改回 `id`,静默遮蔽了同名身份变量。约定:身份变量统一叫 `ident`,不与任何 schema 参数重名。
3. **`-race` 下限速测试翻车**:race 模式 bcrypt 变慢,令牌桶悄悄回填,断言"连续失败必被限速"不成立。解法:`Auth.SetRateLimit(interval, burst)` 让测试注入极小回填间隔。顺带的教训:`go test | tail` 会拿到 tail 的退出码,管道吞掉了失败,一个红着的 commit 就这么混进去过(后来 amend 修正)。

# M8 · 规模:keyset 分页 + 子树体积统计 + 基准

> v2 第二个里程碑(计划见 doc/13)。交付:清掉 v1 的两处规模欠账——offset 分页换 keyset(合同零改动),文件夹终于知道自己多大(异步统计,最终一致)。发布 `v1.2.0`。

## 基准数字(10 万节点单目录,Apple M4,Postgres 16 容器)

| 页位 | offset(v1) | keyset(v2) | 对比 |
|---|---|---|---|
| 第 1 页 | 13.3ms | 14.7ms | 持平(首页两者同路径) |
| 第 250 页 | 26.1ms | **11.8ms** | 2.2× |
| 末页(第 500 页) | 31.3ms | **7.5ms** | 4.2×,且越深越快 |

关键不是倍数是**曲线形状**:offset 随页深线性变差(要扫过并丢弃前面所有行),keyset 平坦甚至下降(索引范围扫,起点直接定位)。10 万节点差 4 倍,百万节点就是数量级差距。
顺带发现:换 keyset 后每页成本的大头变成了 `count(*)`(total 字段每页都算,10 万行 ≈ 13ms)——记入 v2 后的优化候选(total 只在首页算或缓存)。

## 交付清单

**keyset 分页(GraphQL 合同零改动)**
- cursor 载荷:base64(JSON{版本, 排序, 方向, kind 键, 排序值, id}),对前端始终不透明;v1 的 offset 游标解不出来自动按首页处理,升级无感。
- 首页复用原查询(去 OFFSET);翻页 6 条显式 keyset 查询(NAME/SIZE/UPDATED_AT × 升降)+ 搜索/访客子树搜索/回收站各一条 After 查询。方向拆成独立查询而不是 CASE 包 WHERE——planner 才能用索引。
- folders-first 是三元组排序 `(kind DESC, 排序键, id)`,cursor 带 kind 键跨"文件夹区/文件区"边界续翻。
- SIZE 键可空(文件夹无 blob):NULLS FIRST/LAST 两侧的"之后"条件显式写全,cursor 用 `*int64` 区分"键为空"和"键为 0"。
- 游标与请求排序不匹配(翻页中途切排序)按首页处理,不报错。
- 迁移加默认排序覆盖索引 `(parent_id, kind DESC, name, id) WHERE deleted_at IS NULL`;SIZE/UPDATED_AT 仍是 top-N 排序,不为低频排序建索引(记录为取舍)。

**子树体积/数量(doc/13 方案 B:异步,最终一致)**
- 迁移 `00005`:nodes 加 `subtree_bytes / subtree_count / stats_stale` + stale 部分索引。
- 写路径标脏祖先链(一条递归 CTE UPDATE):上传(分片完成/秒传)、删除、还原、彻删、移动(新旧两条链)、复制(目标链)、谎报回收(worker)。彻删的标脏在删行**之前**——行删了就爬不了父链。建文件夹不标:不改变任何字节数。
- worker 第五个周期任务(1 分钟):批量取 stale 文件夹逐个重算。单语句 UPDATE 靠行锁与并发标脏串行化:重算窗口内的新变更会再次置脏,下一轮修正。
- GraphQL Node 加 `subtreeBytes/subtreeCount/statsStale`(可空,仅文件夹);前端大小列文件夹显示体积,stale 时显示"约 X"并弱化。

## 关键实现

- **6 条查询 vs 1 条动态 SQL 的取舍**:sqlc 是静态 SQL 世界,动态 keyset 条件要么 CASE 包 WHERE(planner 放弃索引,基准会打脸)、要么拼字符串(类型安全没了)。6 条显式查询行数多但每条都简单、可 EXPLAIN、可独立加索引——在"代码量"和"可优化性"之间选后者。
- **行类型收敛**:6 条 keyset 查询的行形状与 ListChildrenRow 完全一致,sqlc 却各生成一个 Row 类型。Go 的同构结构体可以直接转换(编译期校验字段一致),`mapSlice + store.ListChildrenRow(r)` 一行收敛,不用 unsafe 不用反射。
- **游标语义**:cursor 编码"最后一行的排序键",不是"位置"。这天然解决了 offset 分页的经典 bug——翻页过程中有人插入/删除行,offset 会跳行或重复,keyset 不会。
- **统计一致性的边界**:方案 B 的"最终一致"窗口 = 标脏到下一轮重算,最长 1 分钟。换来的是写路径零额外代价(标脏是一条索引更新)。文件夹大小本来就不是账务数字,这个交换划算;配额(used_bytes)仍是事务内强一致,两套语义不混。

## 踩坑记录

1. **泛型转换的假设**:最初写了 `convertRows[Dst](rows)` 想泛型收敛行类型——Go 泛型不支持结构体的结构性转换,编译不过。改为显式 `mapSlice(rows, func(r T) D { return D(r) })`,转换合法性由编译器逐字段验证,反而更稳。
2. **pgx 不会把 int 编码成 text**:测试里 `($4 || ' seconds')::interval` 传 int 直接报 encode plan 找不到,改 `make_interval(secs => $4::int)`。SQL 里的隐式类型混用,驱动层不兜底。
3. **测试造数的 sha 撞车**:两处造 blob 的 sha 生成式(`%064d` 对 0 和 `%063d1`)算出同一个串,唯一索引报冲突才发现。测试数据的"随手编"也要保证空间不重叠。

## 遗留

- `count(*)` 成为每页主要成本 → total 只在首页算/缓存,列为 v2 后优化候选。
- SIZE/UPDATED_AT 排序仍是 top-N 排序(无索引),大目录下这两种排序比 NAME 慢——低频路径,先记录不动。

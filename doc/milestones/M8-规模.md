# M8 · 规模(计划)

> 状态:进行中。目标见 doc/13 第五节:清掉 v1 的两处规模欠账——offset 分页与文件夹体积盲区,产出基准数字。交付 v1.2.0。

## 交付清单

**keyset 分页(合同不动)**
- cursor 从"base64 包 offset"换成"base64 包排序键元组 JSON"(order/desc/kind/排序值/id),对前端始终是不透明字符串。
- 首页复用现有查询(去 OFFSET);翻页走 6 条显式 keyset 查询(NAME/SIZE/UPDATED_AT × 升降序)——不用 CASE 包 WHERE,给 planner 留索引通道。SIZE 键可空(文件夹无 size),NULLS FIRST/LAST 两侧条件显式写。
- 搜索(含访客子树搜索)、回收站同步换 keyset(各自单一排序,一条查询)。
- cursor 与请求的 order/desc 不匹配时按首页处理(用户翻页途中切排序的场景)。
- `total` 保留(count 独立查询,列表本身不再付 offset 代价);hasMore 按"取满一页"判断。
- 迁移加默认排序的覆盖索引:`(parent_id, kind DESC, name, id) WHERE deleted_at IS NULL`——默认 NAME 升序走纯索引范围扫;SIZE/UPDATED_AT 仍是 top-N 排序,记录为已知取舍。

**子树体积/数量(方案 B:异步,最终一致)**
- 迁移 `00005`:nodes 加 `subtree_bytes / subtree_count / stats_stale`(仅 folder 有意义),stale 部分索引。
- 写路径(建目录/上传/删除/还原/彻删/移动/复制)标脏祖先链:一条递归 CTE UPDATE,`MarkAncestorsStale`;移动标新旧两条链。
- worker 新周期任务(1 分钟):批量取 stale 文件夹逐个重算(递归 CTE 汇总),单语句 UPDATE 靠行锁与并发标脏串行化——重算期间新的变更会把 stale 再置回,下一轮修正,最终一致。
- GraphQL Node 加 `subtreeBytes / subtreeCount / statsStale`(可空,只加不改);前端文件夹行显示体积,stale 时弱化显示。

**基准(数字进回顾)**
- store 包 bench:造 10 万节点单目录,offset(旧 SQL 原样保留在 bench 里)vs keyset,第 1 页 / 第 250 页 / 末页;附结论。

## 明确不做

- 三种排序各配覆盖索引(索引膨胀,收益集中在默认排序);统计的强一致(写路径祖先链事务更新,方案 A)——取舍见 doc/13。

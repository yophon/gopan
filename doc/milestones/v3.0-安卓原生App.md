# v3.0 · 安卓原生 App

> v2.6 的 Capacitor 壳在真机上问题太多:首屏等网络、WebView 的手感、键盘与返回键别扭,Yophon ID 登录还会被丢到系统浏览器。这一版推倒重做,用 Kotlin + Jetpack Compose 写原生客户端,按 doc/19 的四个阶段交付(3.0.0-p2、3.0.0-p3 两个内测包,3.0.0 正式版)。网页端的用户功能全部原生实现,另外多出后台传输、系统分享直达、「文件」App 集成与站内更新。用法与发布见 doc/18。

## 关键决策

**重做而不是修壳。** 壳的问题(白屏、键盘与返回键、登录跳出 App)都来自"网页塞进 WebView",修一个冒一个。原生客户端直接调 GraphQL 与上传协议,后端只动了上面几处。

**Yophon ID 走移动票据,不碰网页的 OIDC 回调。** 账号中心早为原生客户端设计了票据链路:App 用账号中心的 token 换一次性票据,gopan 用票据加 PKCE verifier 发自己的 refresh cookie。之后 App 与网页端是同一套会话(15 分钟 access token + 轮换的 refresh cookie),撤销设备、改密码的语义自动一致。

**传输以服务端为准。** 本地队列只记"要做什么",续传时用 `uploadSession` 问服务端缺哪些片;杀进程、换网络、重启之后不靠本地进度也能对上。状态迁移全是带前置状态的条件 UPDATE,用户刚点暂停或取消时,运行结果不会把它冲掉。

**更新由站点发,不读 GitHub Releases。** 计划里写的是读 Releases API,但仓库是私有的,匿名请求是 404。站点本来就是 App 唯一的后端:`/api/app/android/latest` 读运维放进发版目录的 `latest.json`,安装包同站下载,App 校验 SHA-256 后交给系统安装器。没有校验值的发布,服务端和 App 两头都拒绝。GitHub Releases 只留作维护者存档。

**「文件」App 里已有文件只读。** 服务端没有版本与原地覆盖写,让第三方应用"保存"到已有文件只能做成删旧传新,语义不对。只开放"另存为新文件"(写完进上传队列)和只读打开(按 SHA-256 缓存,1 GB 封顶)。

**R8 包也跑全部 E2E。** 混淆规则漏一条,炸的往往是序列化、反射、依赖注入入口这类只在运行时才暴露的地方。新增 `releaseE2e` 构建类型:与 release 同一套 R8,但 debug 签名、带测试钩子,四套 E2E 在它上面全跑一遍。测试钩子从 `BuildConfig.DEBUG` 换成专门的 `TEST_HOOKS`,R8 包也能被 uiautomator 定位。

## 验证

- 单测 267 个(JVM):认证协议(假服务端 + MockWebServer)、上传 / 下载状态机(内存版服务端与对象存储)、各页 ViewModel、更新校验、崩溃日志脱敏;lint 0 error。
- 本地全链路 E2E(模拟器 API 36 + 本机 gopan 与账号中心 + 临时 Postgres / MinIO):p1 12、p2 15、p3 18、p4 8 个场景;各阶段在 debug 包上验收,发版前在最终的 R8 包(releaseE2e)上四套全部重跑通过。
- 正式签名包:`apksigner` 证书 SHA-256 与 v2.6 相同(可覆盖安装),`release-smoke.mjs` 冷启动后拉起生产账号中心的授权页,client_id / redirect_uri / PKCE 正确。
- 服务端:`httpx` 新增发版接口测试(未配置、未发版、只发声明的文件、Range、固定链接、坏清单与缺校验值);CI 三个 job 全绿。

## 未做(有意留下)

- iOS。
- 真机验收:计划要求在华为 AAK-AN00(Android 16)上跑,做原生版期间手机一直没连上,原生版只在模拟器上验过。1 GB 文件在流量 / Wi-Fi 切换下续传、国产系统的后台限制、微信「发送文件」面板里选 gopan,都等真机补。
- 本地栈的对象存储走 SSH 隧道,大文件场景缩到几十 MB;覆盖的路径相同(杀进程、断网、Doze、秒传、Range 续传)。
- 不做同步盘;「文件」App 里已有文件不能原地改写。

# M7 · 管理端

> v2 第一个里程碑(计划见 doc/13)。交付:实例运营全部界面化——建号、配额、禁用、重置密码、概览、失败任务重排;首个管理员由 CLI 自举。发布 `v1.1.0`。

## 交付清单(对照计划,全部落地)

| 项 | 结果 |

## 关键实现

- **分享连带失效走既有咽喉**:share 有效性判断只有一个函数 `shareDead`,给它加 `ownerDisabled` 参数,Info/Access/Validate 三个入口自动全覆盖——查询层在 GetShareByToken/ByID 上 join users 带出 `(disabled_at IS NOT NULL)`。没有新增任何"检查点",不存在漏网入口。
- **首个管理员的自举路径**:环境变量方案(重启生效、配置里留敏感状态)否掉,选 CLI 子命令——服务器 shell 权限本身就是最高授权,`promote` 直接复用 goose 迁移 + sqlc 查询,全程 40 行。
- **禁用后的残留窗口**:已签发的 access token 最长再活 15 分钟(JWT 无状态,权限不塞 claims 是 M1 定的原则)。与改密码的窗口一致,记录为已知行为而不是去加黑名单表——为 15 分钟窗口引入每请求查库不划算。
- **配额验证做成行为断言**:smoke 里调完 `adminSetQuota(10 字节)` 后不是查字段,而是让该用户发起 1MB 的 initUpload、断言 `QUOTA_EXCEEDED`——验证"改了"不如验证"生效了"。
- **不能禁用自己**:单管理员实例自锁 = 只剩上服务器改库一条路,service 层直接拒。

## 踩坑记录

1. **覆盖率闸门差 0.1%**:admin.go 落地后 service 覆盖率 73.0% → 72.9%,输入校验分支(用户名长度/负配额/目标不存在)没测到。补五个断言回到 73.4%。教训:新增模块时错误分支和主干一起写测试,别等闸门报警。
2. **auth.graphql 里躺着两个一模一样的 Me 查询**:M5 时代的复制粘贴残留,codegen 静默容忍(同名同形去重)所以一直没炸。加 isAdmin 字段时发现,顺手清掉。生成链的"宽容"会替你藏错误。
3. **gqlgen 重新生成会把手工删掉的 import 加回来**:改完 schema 跑 gen,resolver 文件的 `fmt` import(panic 桩用)残留导致编译失败;而 main.go 加子命令要 `fmt` 又忘了 import。同一个符号一来一回两次编译错误——生成器管理的文件和手写文件的 import 心智要分开。

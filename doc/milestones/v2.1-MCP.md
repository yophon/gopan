# v2.1 · Remote MCP

> 在 v2.0 收官后新增的 Agent 接入版本。交付:零本地安装的 Remote MCP、Agent 自主上传下载、OAuth 2.1、API Key 与细粒度权限。协议和工具参数见 `docs/MCP.md`。

## 交付内容

| 面 | 实现 |
|---|---|
| MCP transport | `modelcontextprotocol/go-sdk` Streamable HTTP `/mcp`,stateless JSON response,16 个文件与传输工具 |
| 文件传输 | MCP 只签发任务/URL/状态;Agent 用自身 HTTP/shell 直传直取 MinIO;支持可选 SHA 秒传、single PUT、multipart、批量/文件夹 ZIP |
| OAuth | Protected Resource Metadata、Authorization Server Metadata、DCR、Authorization Code + PKCE S256、Access/Refresh Token 轮换 |
| API Key | `gopan_key_*`,明文一次性、SHA-256 落库、最多 20 条、独立吊销;兼容早期 `gopan_mcp_*` |
| 权限 | `files:read/download/upload/write/delete` 五档,逐 tool 强制检查;永久删除不开放 |
| 前端 | 账户栏 Agent 接入弹窗(API Key + OAuth grant 管理)、独立 OAuth consent 路由、权限中文映射 |
| 数据 | `mcp_tokens`、`transfer_sessions`、`oauth_clients/grants/authorization_codes/access_tokens/refresh_tokens` |

## 关键决策

**不做本地 stdio bridge**:目标是零安装。Remote MCP 与主 Go 服务同进程,Agent 只配置 HTTPS URL;OAuth 首次授权后完全自主运行。

**MCP 不承载文件字节**:模型上下文和 JSON-RPC 都不适合传二进制。`prepare_upload`/`prepare_download` 返回短期 URL,Agent 自己选择 curl、shell 或宿主提供的 HTTP 工具。控制面权限与数据面签名凭据分离。

**SHA-256 可选而非强制**:会算 hash 的 Agent 可以争取秒传;不会算也能上传到 `staging/mcp/{user}/{transfer}`,服务端完成后流式计算、最终去重并汇入既有 blob/node 模型。没有为了 Agent 放宽内容寻址和服务端校验不变量。

**OAuth 优先,API Key 兜底**:纯 API Key 方案存在首次凭据无法自举的问题。支持 OAuth 的 MCP Host 通过标准发现和 DCR 完成一次浏览器授权;Headless/CI 才使用用户预先创建的 Key。Agent 不能通过未认证 GraphQL 给自己签发 Key。

**OAuth 与 API Key 共用 scope**:两类 bearer 最终都转换成同一 `MCPPrincipal`,tool handler 不关心凭据来源。OAuth 认证额外取 token scope 与当前 grant scope 的交集,撤销 grant 立即生效。

## 上传状态机

```text
uploading → completing → finalizing → processing → verifying → ready
                                                    └──────→ failed
任一活动态 ───────────────────────────────────────────────→ aborted
```

- `completing` 单独存在,解决 MinIO multipart 合并成功但进程在写库前崩溃的恢复问题。
- `idempotency_key` 在用户范围唯一,Agent 重试不会重复建任务。
- `node_id` 使用 `ON DELETE SET NULL`:transfer 是传输记录,不能反向阻止用户永久删除文件。
- worker 清理过期 single PUT/multipart/staging,并恢复卡在 processing/verifying 的会话。

## 安全边界

- `/mcp` 401 返回 `resource_metadata`;原生 Host 无 Origin 正常访问,不可信浏览器跨源请求由 `CrossOriginProtection` 拒绝。
- OAuth public client 不存 secret,强制 PKCE S256;HTTP redirect 只允许 loopback,其他必须 HTTPS且与注册值精确一致。
- authorization code 5 分钟一次性;Access Token 1 小时;Refresh Token 30 天且一次一换。
- API Key/OAuth token/code 均只存 SHA-256;日志不记录 bearer 和预签名 URL。
- ZIP ticket 只含 userID 与指定 node IDs,10 分钟过期,不能调用 MCP/GraphQL。

## 关键实现

- **keyedLimiter 抽取**:登录、验密、打包三处原本各自一份"mu + map + rate.Limiter"的复制粘贴,统一为 service 包内共享件;重构零行为变化,靠既有集成测试兜底验证。
- **/pack 双闸的取舍**:频率闸按身份(`user:{id}` / `share:{id}`——share scope 字符串本身含唯一 id,直接当 key),并发闸是容量 2 的 channel semaphore,**满了立即 429 而不是排队**:打包是分钟级长请求,排队只会让慢的更慢。
- **深度限制**:gqlgen 只自带复杂度限制,深度自己算——AroundOperations 里递归 SelectionSet,Field 加层、inline fragment 不加层、命名 fragment 按定义展开且 seen 集防循环引用打成死递归。
- **指标基数防线**:HTTP 指标的 path 标签先归一(`/s/{token}` → `/s/:token`,SPA 一律 `/spa`),否则每个分享链接一个时间序列,基数直接爆炸。这是上指标系统最常见的自伤。
- **测试路线的选择**:upload/pack 集成测试**直连真 MinIO**(`TEST_S3_ENDPOINT`,未设跳过)而不做接口化 mock——multipart 编排、预签名、etag 回填这些行为 mock 不出来;preview 测试则相反,预签名是纯本地 HMAC 计算,假 endpoint 构造 client 即可,不需要 MinIO 在场。按被测行为选测试策略,不搞一刀切。

## 踩坑记录

1. **验证资产放临时目录,真丢了**:四套 smoke 脚本一直躺在会话级 scratchpad,会话环境重置后全部蒸发,只能凭上下文重建。收编进 `scripts/smoke/`(共享 common.py + `make smoke`),这个教训本身就是 M6 加固精神的注脚:**不进版本控制的工程资产等于不存在**。
2. **S3 桶名最小长度**:preview 测试用假 endpoint 构造 client,桶名随手写了 `"b"`——minio-go 直接拒(S3 规定 ≥3 字符),而 ForList 静默吞了预签名错误,表现为"缩略图 URL 莫名为空"。定位手段:单独探针测试把被吞的 err 打出来。
3. **测试期望自己算错**:fragment 循环用例的深度,`a { ...f }` + `f: b { ...f }`,seen 截断后是 2 不是 3——写断言前先手推一遍算法,别拍脑袋。
4. **cwd 重置 + `cat >>` = 写错仓库**:shell 每次调用重置工作目录,heredoc 追加差点把 Makefile 写进上级目录(那里根本不是 git 仓库)。多仓库纪律再次生效:写文件前显式 `cd` 绝对路径。

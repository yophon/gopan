# v2.2 · 我的设备（文件传输助手）

> 在 v2.1 Remote MCP 之上补齐的会话线。交付:浏览器端「我的设备」会话(发文本 + 传文件)、上传完成自动落消息、真实文件卡片(缩略图/预览/下载)、MCP Agent 通过 `chat_send`/`chat_list` 与浏览器写同一条消息流。GraphQL 与 schema 见 doc/05,前端见 doc/07。

## 交付内容

| 面 | 实现 |

## 关键决策

**单用户单会话,不做会话列表/未读/站内互聊**:定位是微信「文件传输助手」方向——一个设备同步介质,不是社交产品。`owner_id` 即会话键,Agent 与浏览器天然落在同一会话,不需要 sender 字段。

**附件落「我的设备」文件夹**:网盘根目录固定文件夹(可改名/移动),`users.chat_folder_id` 只存指针。改名/移动后指针仍在,幂等 `ensureChatFolder` 不重建;文件夹被永久删除(purge)后指针 SET NULL,下次上传自动重建新文件夹。

**消息 append-only**:不提供删除。`node_id` 外键 `ON DELETE SET NULL`——用户删文件不影响消息留存,消息里的文件卡片显示「文件已不存在」态,不会把整条聊天弄挂。

**保留 5s 轮询,不做 SSE/WebSocket**:单用户自己的会话,实时性要求低。vue-query `refetchInterval` 一行解决,页面不可见自动降级不耗流量;发送后 `invalidateQueries` 立即回读。

**MCP 与浏览器同通道**:`chat_send` 直接写 `chat_messages` 表,浏览器下次轮询即见。uuid v7 全局时间有序,多端并发写无需额外锁(append-only INSERT)。

## 实现要点

- `SendNode` 单事务:复用 `GetActiveNodeOwned`(owner + deleted_at IS NULL)校验,非属主/已删一律 `ErrNotFound`(防探测)。
- `EnsureFolder`:事务内 `pg_advisory_xact_lock(hashtextextended('chat-folder:'+owner))` 串行,先读指针,命中的活跃文件夹直接返回,否则建「我的设备」+ 写指针。
- 消息排序统一 `ORDER BY id DESC` 后反转;uuid v7 时间有序,id 即 (time, tiebreak),索引单键即可。
- resolver 层 `ChatMessage.node` 捕获 `NOT_FOUND` 返回 null,不把文件删除传染给消息读取。
- GraphQL 聊天接口全走 `UserFrom`(拒绝 guest scope)。

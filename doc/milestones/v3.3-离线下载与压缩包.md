# v3.3 · 离线下载与压缩包

> 按 doc/21 的计划交付两件"服务端替用户干的长活":**离线下载**——给链接,服务器在后台把文件下进网盘;**压缩包**——zip / 7z / rar / tar 不下载就看目录、预览里面的文件、一键解压。两者共用一张后台任务表、一条流式落库路径和一块「后台任务」界面;不加系统包、不加常驻组件,二进制 +2.3 MB。服务端与网页一次上线(v3.3.0),安卓 App 3.3.0 同时带上两项。

## 关键决策

**后台任务不复用 tasks 表。** `tasks` 按 blob(校验、派生物),没有属主、没有进度,也不该被一个几个 G 的下载占住:缩略图和 hash 校验要等的话,WebDAV 传的小文件就迟迟不能用。所以另开 `user_jobs`、另起 runner,默认只跑一个,长活和短活互不阻塞。

**挡内网在拨号那一刻。** 解析域名时检查挡不住 DNS rebinding(检查时一个 IP、连接时另一个),所以在 `net.Dialer.Control` 里看真正要连的地址;重定向每一跳都过这一关,不走系统代理。除了常规的私有、回环、链路本地、保留段,部署时把 VPS 自己的公网 IP 也填进拒绝名单:容器访问宿主机公网地址可能绕过只防外部的防火墙。

**压缩包目录按内容建一次。** 同一份内容(sha)只读一次目录,存进 `archive_entries`,浏览只查库;压缩的 tar 和固实 rar 要整包解一遍才列得出,放在 worker 里慢慢做,超过 4 GB 不建。每个条目记下"读到它之前要先解掉多少字节",预览前就知道够不够浅。

**解码内存在建解码器之前卡住。** 精简档容器只有 384 MB,而 7z / rar / xz 的解码内存约等于字典大小、由包自己声明。sevenzip 库允许按方法号覆盖解码器,就把 LZMA、LZMA2、PPMD、zstd 换成先看属性、再建解码器的版本;rar 和 xz 用库自带的上限选项。

**解压只建新文件夹,出错不自动重试。** 不合并、不覆盖,解错了删一个文件夹就行;自动重试会再建一个文件夹,已解出的留在第一个里,所以执行中的错误一律终态,失败时也写回已建的文件夹。

## 回滚注意

迁移只加不减,旧二进制能跑在新 schema 上(新表它不读)。回滚后排队中的后台任务停在原地,升回来会接着跑;压缩包索引保留,不必重建。

# M3 · 预览:派生物管线 + 预览模态

> commit:`921e31c`(后端)+ `2c03217`(前端)。交付:图片出缩略图和大图、视频出封面和时长、音频出时长、PDF/文本原文直出、Office 惰性转 PDF——列表有缩略图,双击有全屏预览。

## 派生管线(worker/derive.go)

verify_hash 通过后按 mime 自动入队(**只有校验过的内容才做派生**,谎报内容不浪费 CPU):图片 → thumb;视频 → media_probe + video_cover;音频 → media_probe。Office 不自动转——转 PDF 贵,大多数文件从未被预览过,等第一次 `requestPreview` 再入队。

各任务实现:
- **thumb**:`disintegration/imaging` 解码(AutoOrientation 处理 EXIF 旋转),Fit 到 256/2048(小于目标不放大),JPEG q82。超 100MB 的图直接跳过,前端用图标。
- **media_probe / video_cover**:ffmpeg/ffprobe 是外部进程,喂不了 io.Reader,给它们**内网预签名 URL**(`PresignInternalGet`,10 分钟)——ffmpeg 自己按需 Range 拉流,不用先落盘整个视频。封面取第 1 秒帧,`scale='min(640,iw)':-2`,mjpeg 管道直出。
- **office_pdf**:流式 multipart POST 到 Gotenberg `/forms/libreoffice/convert`。Gotenberg 靠扩展名识别格式,而对象 key 是 hash 没有扩展名,所以取一个引用该 blob 的节点名作为表单文件名。
- 产物统一 `saveDerivative`:Put 到 `derived/{sha[:2]}/{sha}/{kind}` + UpsertDerivative 记账。

**按源 hash 去重是这条管线的核心收益**:派生物挂在 blob 上而不是节点上,同一份 docx 全站只转一次 PDF,秒传用户直接享受现成预览。

## 列表 vs 详情:N+1 的解法(service/preview.go)

`children` 一页 200 个节点,每个都查 derivatives 表 + 问 MinIO 就是 N+1。设计文档预设 dataloader,实现时找到了更省的路子:

- **ForList(列表路径)**:**零查询**。预签名 URL 生成是纯 HMAC 计算(不打网络),直接为 `derived/…/thumb256`(视频为 cover)**乐观签发** URL——派生物可能还没生成,签了再说。前端 `<img @error>` 记下失败的节点回落图标,派生物生成后下次刷新自然出图。200 个节点的额外成本≈200 次本地 HMAC。
- **ForNode(详情路径)**:打开预览模态才走,查 derivatives 补 largeUrl/contentUrl、查 tasks 表出 Office 转换状态(PENDING/RUNNING/DONE/FAILED)、从 blob 的 media_meta 取时长。图片的 contentUrl 直接签原图(小图没有 2048 版时兜底)。

两条路径的分流标记见踩坑 1。

## 前端预览(components/preview/)

- **PreviewModal 是 AppShell 下的单例**,列表页 `openPreview(ids, index)` 唤起,composable 里只存客户端 UI 态(可见性、id 列表、下标),服务端数据归 vue-query。内容区 `:key="currentId"` 切换即整棵重建,播放器/PDF 状态不串台。
- 预签名 15 分钟即查即用:单节点查询 `staleTime: 0, gcTime: 0`,不缓存过期 URL。
- **Office 流转**:打开时 status 为空 → 自动 `requestPreview` 触发转换(Set 去重防重复触发)→ vue-query `refetchInterval` 对 PENDING/RUNNING 每 2 秒轮询,模态关闭 enabled=false 自动停 → DONE 后按 PDF 渲染,FAILED 给重试和下载。
- **PdfViewer**:pdfjs-dist 体积 ~1MB,`defineAsyncComponent` 拆独立 chunk,真预览 PDF 才拉;worker 线程解析,逐页 canvas 渲染,递增序号丢弃快速翻页产生的过期渲染结果。
- 文本预览 fetch contentUrl,截断 20 万字符防巨文件卡死;视频用 cover 当 poster;音频显示 mm:ss 时长。
- 键盘:←/→ 切换(播放器聚焦时让位给快进),Esc 关闭。

## 踩坑记录

1. **区分"列表里的 Node"和"详情里的 Node"**:preview resolver 拿到的只是 Node 对象,不知道自己在哪条路径。第一版从 gqlgen 的 FieldContext 向上爬找"路径里有没有数组下标"——在数组元素的 FieldContext 上踩了嵌入 `*ast.Field` 为 nil 的 panic。**放弃上下文嗅探**,改为显式建模:gqlgen `extraFields` 给 Node 加 `InList bool`,列表转换器 `gqlPage` 统一置位。少爬一层框架内部结构,多睡一晚好觉。
2. **残留进程假象**:一次 `cd` 失败导致旧二进制一直占着 :8080,后续所有"修复"都貌似无效——smoke 一直打在旧进程上,排查了半天代码。教训:shell cwd 每次 Bash 调用会重置,起停服务一律 `lsof -ti :8080 | xargs kill` 确认端口归属。
3. **误提交 23MB 二进制**:`server/gopan-m3` 混进了后端 commit,下一个 commit 里移除。.gitignore 早该覆盖构建产物路径。
4. **派生物去重反噬 smoke**:固定内容的 rtf 第二次跑直接命中上次的派生物缓存,"转换从 PENDING 到 DONE"的断言失效。smoke 的 rtf 内容改为每次随机。

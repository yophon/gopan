## 任务分解

### 5.1 回收站 30 天自动清理(后端)

- **方案**:worker 新增周期任务 `trash-cleanup`(每小时,与现有 periodic 模式一致)。查询回收站顶层中 `deleted_at < now() - TTL` 的根,按 owner 分组走既有 `Nodes.Purge`(事务内 PurgeSubtree + 引用计数递减 + 配额退还,一行不用重写)。
- worker 目前只依赖 store,不依赖 service——在 `worker.New` 注入 `*service.Nodes`(main 已同时持有两者,不产生循环依赖)。
- TTL 走配置 `GOPAN_TRASH_TTL`(默认 720h),测试注入小值。
- **注意**:只判定顶层的 deleted_at 即可——整树软删是同一时刻,还原过的子树不在回收站。每轮清理打日志(owner 数、节点数),上线首跑会一次性清历史存量,属预期行为。
- **验收**:集成测试伪造 deleted_at 过期 → 触发清理 → 断言节点消失、ref_count 减、used_bytes 退;未过期的不动。

### 5.2 copyNodes 复制(后端 + 前端)

内容寻址让复制几乎免费:文件复制 = 新 node 指向同一 blob,物理零拷贝。

- **schema**:`copyNodes(ids: [ID!]!, targetParentId: ID): [Node!]!`(返回新根节点)。
- **规则**,全部复用既有机制:
  - 目标必须是自己的活跃文件夹(ensureFolder);**目标不能在任一源的子树内**(IsDescendant,否则递归复制自己无限膨胀);
  - 重名走 cleanName 自动 `(1)` 后缀(仅对根;子树内部结构原样);
  - **配额预检**:先递归收集子树(复用 /pack 的 ListActiveChildrenLite 遍历),SumBlobSizes 算逻辑总量,`used + total > quota` 直接拒 QUOTA_EXCEEDED;
  - 单事务:自顶向下建新 node(新 uuid,文件带 blob_id),批量 `IncrementBlobRef` + `AddUsedBytes`;
  - **上限**:单次复制节点数 ≤ 10000,超过拒绝(INVALID_INPUT)——防单事务过大,v1 不做分批。
- 回收站里的节点不可复制(Get 已挡)。
- **前端**:DriveView 工具栏 +「复制到」右键项,复用 MoveDialog 选目标(加 mode prop 区分文案)。
- **验收**:smoke 断言复制后 used_bytes 精确增加子树逻辑大小、blob ref_count +1、MinIO 对象数不变、循环复制被拒、超配额被拒。

### 5.3 搜索 UI(前端)

后端一行不动。

- AppShell 顶部搜索框(侧栏上方或 header),防抖 300ms → `searchNodes`;
- 结果页 `/search?q=`:复用 DriveView 的表格列与图标/缩略图逻辑(抽公共组件或轻复制),点文件夹跳 `/drive/:id`,点文件开预览;`nextCursor` 出「加载更多」;
- operations 新增 `SearchNodes.graphql`(items 字段与 Children 对齐,列表路径缩略图白得)。
- **验收**:vue-tsc 干净;手测搜索→跳转→预览闭环。

### 5.4 配额展示(前端)

- AppShell 侧栏底部用户区加用量条:`el-progress` + `usedBytes / quotaBytes` 文案(formatBytes 已有);>90% 变警告色;
- 数据源 `me` 查询进 vue-query(key `['me']`),上传完成、删除/彻删、复制成功后 invalidate——uploads store 和相关 mutation 的 onSuccess 各补一行。
- **验收**:上传后不刷新页面用量条即变。

### 5.5 changePassword(后端 + 前端)

- **schema**:`changePassword(oldPassword: String!, newPassword: String!): AuthPayload!`。
- **后端**:验旧密码(bcrypt)→ 新密码同注册规则(8~72)→ 更新 hash → **`RevokeAllUserFamilies`(新 query:按 user_id 吊销全部 refresh)** → 当场重新 issuePair 返回:其它设备全部掉线,当前会话无感续命(写新 cookie)。按 IP 限速复用 `Auth.allow`。
- **前端**:AppShell 用户名点开小对话框(旧密码/新密码/确认),成功后 setAuth 新 payload + 提示"其它设备已下线"。
- **验收**:集成测试断言改密后旧 refresh 全失效、新 pair 可用、旧密码登录被拒。

### 5.6 部署上线(工件 + runbook)——M5 的重头

交付四个文件 + 一份文档,验收标准是**一台干净机器 20 分钟内从零到可用**。

1. **Dockerfile**(仓库根):两阶段。builder:node 装依赖构建前端 → 拷进 server/cmd/gopan/dist → `CGO_ENABLED=0 go build`;runtime:**debian-slim + ffmpeg**(doc/08 已定:distroless 装不了 ffmpeg,简单优先),非 root 用户,只 COPY 单二进制。目标镜像 ≤300MB。
2. **docker-compose.prod.yml**:
   - postgres、minio(各自 named volume)、gotenberg(**internal network、无出网**,防 SSRF 型文件,doc/06 要求)、gopan、caddy;
   - gopan 环境:`GOPAN_S3_PUBLIC_ENDPOINT=https://{域名}/s3`、`GOPAN_JWT_SECRET_FILE` 走 secrets(config.go 已支持)、`GOPAN_DEV_MODE` 不设(默认 false:cookie Secure、关 introspection);
   - 全部 healthcheck + `restart: unless-stopped`,gopan `depends_on: condition: service_healthy`。
3. **Caddyfile**:TLS 自动签;`/s3/*` → minio:9000(**必须 strip 前缀且保留 Host 一致性**——预签名把 host 签进签名里,MinIO 侧用 `MINIO_DOMAIN`/path-style 对齐,这是本任务最大的坑,见风险 1);其余 → gopan:8080。
4. **备份**:`scripts/backup.sh`——`pg_dump -Fc` + `mc mirror`(或直接 tar minio volume,量小阶段够用),cron 每日,保留 7 份;写明恢复步骤。
5. **runbook**(`doc/09-上线手册.md`):从裸机到可用的完整命令序列、升级流程(pull → build → `docker compose up -d --no-deps gopan`,迁移启动自动跑)、回滚(镜像 tag 回退;**迁移只加不减**,00001~00003 均无破坏性 Down 依赖)、日志与 pprof 访问方式。
- **验收**:干净 VM 上按 runbook 走完 → healthz 绿 → 注册→上传 100MB→秒传→预览→分享→访客下载→打包,全流程手测通过;`/s/{token}` 在微信里出卡片(og 直出走生产链路验证)。

### 5.7 文件夹拖拽上传(P2,前端)

- DriveView 的 drop 处理已用 `webkitGetAsEntry` 识别目录(当前跳过):改为递归 `readEntries`(注意 Chrome 每次最多返回 100 项,要循环读空)展开成 `{relativePath, file}[]`;
- 上传前按路径批量建目录(逐层 createFolder,同名容忍 NAME_CONFLICT 后查询复用),再把文件按所属目录入队——uploader 一行不改;
- 上限:单次 ≤1000 文件,超出提示分批。
- **验收**:拖一个三层目录,结构与内容完整落库。

### 5.8 图片预览缩放(P2,前端)

PreviewModal 的 IMAGE 分支加滚轮缩放 + 拖拽平移 + 双击复位(纯 CSS transform,不引库)。可裁剪,不影响 v1.0。

## 风险与对策

1. **`/s3` 反代与预签名签名不匹配**(最大风险):S3 签名 V4 把 Host 和路径都签进去,反代改写任何一样都 403。对策:`GOPAN_S3_PUBLIC_ENDPOINT` 直接配成对外域名+路径,public client 生成签名时就用最终形态;Caddy 只透传不改写 Host;上线验收里专门测"浏览器直传分片 + 直取预览"两条真实路径。搞不定的备选:MinIO 走独立子域(`s3.{域名}`),彻底绕开路径前缀。
2. **回收站清理误删**:TTL 可配 + 每轮日志 + 上线首跑前手动 `SELECT count(*)` 预估;清理走软删→彻删既有事务,不新造删除路径。
3. **copyNodes 大子树**:1 万节点上限 + 事务前预检,复制期间源被并发修改的极端情况接受"以收集瞬间快照为准"(单机自用可接受,不上锁)。
4. **debian-slim + ffmpeg 镜像体积**:预计 250MB 左右,超 300MB 再考虑 ffmpeg-static 二进制直拷。

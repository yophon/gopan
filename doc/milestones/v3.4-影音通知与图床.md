# v3.4 · 影音、通知、直链与图床

> 按 doc/22 的计划交付三件事。**影音**:先补上生产上认不出 mkv / mov / avi 的缺口,再做同名外挂字幕、跨设备续播、文件夹连播。**通知**:「你没在看的时候发生的事」进站内铃铛,也能推到 Webhook / ntfy / Bark / Telegram。**直链与图床**:任意文件一条永久公开地址,PicGo / ShareX 等能直接上传;每次访问都记账,有流量上限、来源白名单和盗刷提醒(提醒走通知)。不转码、不加系统包、不加依赖库,闲时零开销。服务端与网页一次上线(v3.4.0),安卓 App 3.4.0 同时带上三项。

## 关键决策

**直链经 Go 中转,不跳转到签名地址。** 跳转省一次拷贝,但签名地址一发出去就管不住了:吊销要等它过期,流量只能估,上限拦不住。中转让每个字节都经过计数,吊销、暂停、白名单、上限立刻生效;代价是多一次本机拷贝(MinIO 在同一台机器),对图片可以忽略。

**计数先在进程里攒。** 被盗链时每秒可能上百次访问,一次一条 INSERT 会把小机器的库打满;所以按小时 / 来源 / 明细在内存里聚合,30 秒一批写进去,退出时冲刷。上限判断用「库里的底数 + 进程内增量」,不每次查库;崩溃最多丢 30 秒的计数,可以接受。

**通知不能拖垮业务。** 收集收件的通知和落库在同一个事务里(要么都有、要么都没有),但包在 savepoint 里,通知写失败不会让外层事务变成 aborted;别处在业务提交后写,出错只记日志。推送在独立的投递表里异步发,对方慢、挂了都不影响主流程。

**MIME 补在根上。** 视频认不出不是播放器的问题,是 `blobs.mime` 一直记成了 octet-stream:预览类型、封面、时长、直链的内联与否都跟着错。所以先补自带表、再回填存量,其余功能才有意义。

**图床密钥是一种 API Key,但不能混用。** 它放在 PicGo 一类工具的配置文件里,最容易泄露;所以只给「往图床文件夹传图、拿直链」这一项,读不了、列不了网盘,新建时还会发「新的访问凭据」通知。

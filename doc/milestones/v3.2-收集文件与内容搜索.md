# v3.2 · 收集文件与内容搜索

> 按 doc/20 的计划交付两件事:**收集文件**——对文件夹开链接,别人不用注册就能往里传、看不到里面已有的内容;**内容搜索**——按 PDF、Office、文本里的文字找文件,中文不装数据库扩展。收集文件是 gopan 第一次开放不登录的写入,上线前先堵了一个同源脚本的口子(P0)。服务端与网页一次上线(v3.2.0),安卓 App 3.2.0 同时带上两项。

## 交付内容

## 关键决策

**收集链接不复用分享。** 分享的访客令牌能读整棵子树。收集用新 scope,现有读接口的访客分支都只认 `share:` 前缀,新令牌天然被拒——不用逐个接口加判断,httpx 有一条测试用真 GraphQL handler 把读接口和属主接口挨个调一遍确认。

**访客没有秒传,也不传 sha256。** 匿名访客能借秒传探测"某份内容是否有人存过";而落库时服务端本来就要把暂存对象流式算一遍 sha,访客不算也就省掉了手机上的一段等待。

**名字在落库时才定。** 匿名访客撞名很常见(都叫 `IMG_0001.jpg`),而 init 时挑的名字到落库时可能已被占。落库事务先锁链接行,同一链接的落库串行,挑出来的名字不会被另一个访客抢走;万一是属主同时建了同名文件,整笔回滚、下一轮重挑,不算终态失败。

**中文搜索不装扩展,词项切在应用层。** 官方 Postgres 镜像没有中文分词,pg_trgm 对两个字的查询用不上索引,而"合同""发票"这种两字词最常见。内容与关键词按同一规则切成 CJK 二元组 + 字母数字三元组,存 `text[]` 建 GIN;查询词项取交集得候选,再按原文子串复核。用 `text[]` 而不是 tsvector:不受 tsvector 1MB 上限约束,也用不上它的分词。语义因此就是"文字里包含这个关键词",与文件名搜索一致;代价是关键词至少两个汉字或三个字母。

**提取按 blob,不信 mime。** 内容寻址,同一份内容只提一次;类型靠嗅探文件头,`blobs.mime` 来自第一个上传者的文件名。内容本身的问题(坏 PDF、加密、解不出编码)记为 failed / unsupported 算任务完成,只有基础设施错误才重试,回填不会在坏文件上打转。

## 验证

- 服务端:collect 集成测试 10 个、httpx 边界测试、MCP 收集与内容工具(含访问目录限制、审计不含密码)、fulltext 单测(含 zip 炸弹、真 pdftotext)、worker 提取九种格式与回填、内容搜索的权限 / 分页 / 片段 / 页码 / 子树;全部服务端测试在服务器上跑测试二进制通过(本机经隧道 RTT 190ms,跑不动);CI(装了 poppler)全绿。
- 网页:访客上传器单测 9 个、高亮切段与预览页码单测;本机 Edge(CDP)跑通收集全流程(属主建链接 → 手机尺寸访客留名上传 12 MB 分片文件与同名文件 → 收件记录 → 跳到上传者子文件夹 → 结束收集 → 带密码链接)与内容搜索(中文命中高亮、PDF 第 2 页且预览直达)。
- 安卓:见 doc/20 第七节 C2 / S3。
- 生产(2026-10-21):迁移到 22;`/gopan/` 响应带上 CSP sandbox 与 nosniff;被引用的 60 份内容约一分钟提完,文字 2.1 MB、表连索引 4.2 MB,gopan 常驻 40 MB;镜像 +98 MB。

## 回滚注意

迁移只加不减,旧二进制能跑在新 schema 上;唯一例外是 `upload_sessions` 里 sha256 为空的访客会话——旧二进制的清理查询扫到它会报错。真要回滚,先 `DELETE FROM upload_sessions WHERE sha256 IS NULL`(都是没传完的访客上传)。

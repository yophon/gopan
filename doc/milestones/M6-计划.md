## 任务分解

### 6.1 refresh_tokens 过期清理(P0,后端)

- **现状**:`DeleteExpiredRefreshTokens` 查询(过期超 30 天的行)M1 就进了 queries,sqlc 也生成了,但从没被调用——表只增不清。
- **方案**:worker 挂第四个周期任务 `refresh-cleanup`(每 24 小时,复用 periodic 模式),调用即可;顺手把删除条件参数化验证一遍(保留 30 天余量是为了重用检测的取证窗口,过期即删会丢"被偷 token 再现"的证据)。
- **验收**:集成测试拨库时钟造过期行 → 清理后只剩活跃行;重用检测语义不受影响。

### 6.2 service 层测试补齐(P0,后端)

- **现状**:auth/node/share 有集成测试;upload/preview/pack 零测试,行为全靠 smoke 端到端兜底——回归能力有,失败定位慢。
- **方案**:延续"测真的"路线,**集成测试直连真 MinIO**(dev compose 常驻 9000),不做接口化 mock 重构——mock 换来的是测试快,丢掉的是对 multipart/预签名真实行为的覆盖,这个项目里后者更值钱。
  - 测试基建:`TEST_S3_ENDPOINT` 环境变量(未设则跳过相关用例),测试专用 bucket `gopan-test`,每次运行 setup 时清空;
  - **upload**:Init 的输入校验矩阵(sha 格式/大小/配额/会话上限)、未 verified 不秒传、verified 秒传建引用、Complete 状态机(非 uploading 拒绝、缺片报 MISSING_PART、etag 回填)、Abort 幂等;
  - **preview**:`ClassifyPreview` 纯函数表驱动单测(不碰网络,mime×扩展名×大小的边界全覆盖);ForList 乐观 URL 生成、ForNode 的 OFFICE 状态机(无产物无任务 → status 空;有任务映射四态);
  - **pack**:Collect 的鉴权分流/2GB 上限/多根重名解冲突/空目录项,Stream 出的 zip 用 archive/zip 反读校验结构与字节。
- **验收**:`go test -race ./...` 全绿;service 包内每个导出方法至少被一个测试触达(以 `go test -cover` 的包覆盖率对比 M5 基线,目标 service 包 ≥70%)。

### 6.3 /pack 限速与并发上限(P0,后端)

- **现状**:验密有按 IP 限速,但访客拿到 30 分钟 token 后可反复打 /pack——zip 是全项目唯一过 Go 的字节流,刷起来烧的是服务器 IO 和带宽。
- **方案**:两层,都在 PackHandler 入口:
  - **频率**:按身份 key(`user:{id}` / `share:{shareId}`)令牌桶,每 30 秒回填一个、突发 3——正常人打包是低频动作;超限 429 + Retry-After;
  - **并发**:全局 semaphore(容量 2),满了直接 429 而不是排队——打包是分钟级长请求,排队只会堆积。
  - 限速器从 Auth/Shares 里的重复实现抽成 `service` 包内共享的 `keyedLimiter`,三处(登录、验密、打包)统一,顺手消重复。
- **验收**:集成测试注入小参数验证 429;并发上限用两个慢流占坑后第三个立即 429。

### 6.4 GraphQL 深度限制(P1,后端)

- **现状**:doc/05 写了"深度限制 8、复杂度限制 300",实现只有后者。本项目 schema 无递归类型(Node 没有 children 字段),实际风险低,但设计承诺要么兑现要么改文档——选兑现,一个 OperationMiddleware 的事。
- **方案**:gqlgen 无现成深度扩展,自定义:解析后的 AST 递归量 SelectionSet 深度(fragment 展开跟进),超 8 直接拒 `QUERY_TOO_DEEP`。
- **验收**:单测构造 9 层嵌套查询被拒、8 层通过。

### 6.5 /metrics 指标暴露(P1,后端)

- **现状**:运行状态只有 healthz(活着/死了)和 pprof(出事后剖析),日常"任务失败了没有、上传量多大"零感知。
- **方案**:引 `prometheus/client_golang`(唯一新增依赖),`/metrics` 挂在 **pprof 那个内网端口**(127.0.0.1:6060)——不对外、不用鉴权、反代永不转发,与 pprof 同一安全边界。指标从省着来:
  - `gopan_http_requests_total{path,status}` + `gopan_http_duration_seconds`(WithLogging 中间件顺手埋);
  - `gopan_tasks_total{kind,status}`(worker execute 处);
  - `gopan_gc_purged_total{job}`(三个周期清理各自计数)。
  - 不建 Grafana 不配抓取——单机自用,`curl :6060/metrics` 能看就是目标;真要接监控时指标已经在了。
- **验收**:smoke 后 curl /metrics 断言核心指标非零。

### 6.6 安全响应头(P1,后端)

- **现状**:SPA/落地页响应裸奔,一个头都没有。
- **方案**:httpx 加一个 SecurityHeaders 中间件包在最外层:`X-Content-Type-Options: nosniff`、`Referrer-Policy: same-origin`、`X-Frame-Options: DENY`(分享页在微信里是直接打开不是 iframe 嵌入,DENY 不影响)。CSP 单独评估:SPA 无 inline script,但预签名图片/视频是跨域资源,给一条宽松的 `img-src/media-src https: http:` 起步,**dev 模式跳过 CSP**(vite 注入的开发脚本会撞)。
- **验收**:curl -I 断言头存在;m3/m4 smoke 回归确认预览与分享页不受 CSP 误伤。

### 6.7 前端最小测试(P2,前端)

- **方案**:引 vitest(只跑 node 环境纯逻辑,不上组件测试/jsdom——SPA 组件测试的维护成本对单人项目不划算):`utils/format`(字节/时间格式化边界)、`api/errors`(错误码映射与 overrides)、uploader 里可剥离的纯函数(分片切割计算)。目标是建立"前端也有测试关卡"的下限,不是覆盖率。
- **验收**:`pnpm test` 进 Makefile 的 `make test`。

### 6.8 备份异地(P2,运维)

- **方案**:backup.sh 尾部加可选 rclone 步骤(`BACKUP_REMOTE` 环境变量非空则 `rclone copy` 到远端,任意 S3/网盘均可),doc/09 补配置说明与恢复演练步骤。不引新服务,一台机器的事。
- **验收**:本地跑通 rclone 到 MinIO 自身的另一个 bucket(模拟远端)。

## 风险与对策

1. **集成测试连真 MinIO 的状态污染**:测试专用 bucket + setup 清空;CI 没有 MinIO 时 `TEST_S3_ENDPOINT` 未设自动跳过,不红。
2. **CSP 误伤**:预签名资源跨域、pdfjs worker、Element Plus 动态样式都可能撞 CSP。对策:从宽松基线起步 + smoke 回归把关,宁可 CSP 松也不上线一个白屏。
3. **限速器重构**(6.3 抽 keyedLimiter):动 Auth/Shares 已测代码,靠既有集成测试兜底,重构不改行为。
4. **prometheus 依赖**:只引 client_golang 本体;若引入后二进制膨胀超预期(>10MB 增量),退回手写文本格式暴露(指标就十来个,exposition format 很简单)。

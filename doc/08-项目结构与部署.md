# 08 · 项目结构与部署

## 仓库布局(monorepo)

```
gopan/
├── doc/                    本设计文档
├── server/
│   ├── cmd/gopan/          main:装配、embed 前端、启动
│   ├── internal/
│   │   ├── graph/          gqlgen 生成物 + resolver(薄,只调 service)
│   │   ├── service/        业务层:node/upload/share/auth/preview
│   │   ├── store/          sqlc 生成物 + 手写查询(CTE 等)
│   │   ├── objstore/       Storage 接口 + MinIO 实现(预签名、multipart)
│   │   ├── worker/         任务池:verify/thumb/cover/pdf/gc/cleanup
│   │   ├── httpx/          中间件(auth、限速、日志)、/s/:token、/pack
│   │   └── config/
│   ├── db/                 goose 迁移 + sqlc 的 queries/*.sql
│   ├── graph/schema.graphqls   ← 唯一接口事实源(05 的 SDL)
│   └── go.mod
├── web/
│   ├── src/{api,stores,components,views,uploader,utils}
│   ├── codegen.ts          指向 ../server/graph/schema.graphqls
│   └── package.json
├── Makefile                dev / gen / build / lint / test
└── docker-compose.yml
```

依赖方向:`graph → service → store/objstore`,service 不 import graph;接口(Storage、Converter)定义在使用方 service 里,MinIO/Gotenberg 是实现。

## 开发流

```
make gen    # gqlgen + sqlc + 前端 codegen,三个生成器一次跑
make dev    # compose 起 postgres/minio/gotenberg + go run + vite(proxy /query → :8080)
make build  # vite build → 产物拷进 server/cmd/gopan/dist → CGO_ENABLED=0 go build(embed)
```

schema 或 SQL 改动只改源文件,生成物不手编、不 review(CI 校验 `make gen` 后 git diff 为空)。

## docker-compose(生产)

```yaml
services:
  gopan:
    image: gopan:latest          # 多阶段构建:node→vite,golang→build,distroless/static 运行
    ports: ["8080:8080"]
    environment:
      GOPAN_DB_URL: postgres://gopan:***@postgres:5432/gopan
      GOPAN_S3_ENDPOINT: http://minio:9000
      GOPAN_S3_PUBLIC_ENDPOINT: https://pan.example.com/s3   # 预签名 URL 用的外部地址
      GOPAN_GOTENBERG_URL: http://gotenberg:3000
      GOPAN_JWT_SECRET_FILE: /run/secrets/jwt
    depends_on: [postgres, minio]
  postgres:
    image: postgres:16-alpine
    volumes: [pgdata:/var/lib/postgresql/data]
  minio:
    image: minio/minio
    command: server /data
    volumes: [miniodata:/data]
  gotenberg:
    image: gotenberg/gotenberg:8
    networks: [internal]         # 无出网
```

要点:

- **预签名的域名问题**:浏览器直传要能访问 MinIO,反代把 `/s3/*` 转发到 minio:9000,预签名用 `GOPAN_S3_PUBLIC_ENDPOINT` 生成(minio-go 初始化两个 client:内部操作用内网地址,签名用公网地址)。这是自部署 MinIO 最常见的坑,设计期就定死。
- 反代(nginx/Caddy)只做 TLS + 域名路由:`/` → gopan:8080,`/s3/` → minio:9000;`client_max_body_size` 只影响 /pack 上行(无)——分片直传不过反代的 Go 路径,但过反代到 MinIO,所以该值 ≥ 单片 16MB,留 32MB。
- ffmpeg 装进 gopan 镜像(distroless 装不了则该镜像换 debian-slim,或 ffmpeg 独立 sidecar 容器 exec 走共享卷——v1 直接 debian-slim,简单优先)。

## 配置清单(全部环境变量,GOPAN_ 前缀)

DB_URL、S3_ENDPOINT、S3_PUBLIC_ENDPOINT、S3_KEY/S3_SECRET、S3_BUCKET、GOTENBERG_URL、JWT_SECRET_FILE、LISTEN(:8080)、PPROF_LISTEN(127.0.0.1:6060)、REGISTER_OPEN(bool)、DEFAULT_QUOTA、PART_SIZE、LOG_LEVEL。十来个,flag + env 双读,env 优先。

## 运维

- 日志:slog JSON → stdout,交给 docker/journald;请求日志带 user_id、耗时、GraphQL operation name。
- 备份:pg_dump 每日 + MinIO 数据目录 rsync/restic;**恢复演练**:元数据和对象必须同点位恢复,blob 缺失时 node 变"损坏"标记而不是 500。(实际落地为 `scripts/backup.sh`:全量 tar + `KEEP_DAYS` 保留期 + 磁盘水位预检 + 可选 `BACKUP_REMOTE` rclone 异地,见 doc/09。)
- 升级:goose 迁移在进程启动时自动跑(单机无并发迁移问题);二进制替换 + systemd/compose 重启,优雅退出(NotifyContext + Shutdown,排空 worker)。
- 监控 v1:健康检查 /healthz(查 DB + MinIO 连通)+ pprof;~~metrics(Prometheus)v2~~ /metrics 已在 M6 提前落地(prometheus client 挂 pprof 内网端口,HTTP/任务/清理三组指标)。

## 里程碑建议

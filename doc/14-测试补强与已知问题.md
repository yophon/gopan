## 二、已知问题(未修,按关注度排序)

### 1. `trash_nodes` 对他人/不存在的节点静默"成功"

`service.Nodes.Delete` 走 `SoftDeleteSubtree`,按 owner_id 过滤,匹配 0 行不算错——所以 MCP 的 `trash_nodes` 用别人的 node_id 调用会返回 `success: true`,实际什么都没删。**无安全问题**(数据动不了),但与 rename/move/restore 返回 NOT_FOUND 不一致,对 agent 有误导:它会以为删成功了。mcpserver 集成测试已固化该现状并注释。要改的话在 service 层区分"删了 0 行",顺带查 dav/GraphQL 调用方是否依赖现状。

### 2. `requestBaseURL` 无条件信任 X-Forwarded-Proto/Host

oauthserver 和 mcpserver 构造 metadata/issuer URL 时直接取转发头。标准部署(Caddy 反代)没问题;若哪天绕过反代直接暴露端口,客户端可用伪造头污染 OAuth metadata 里的 endpoint URL。低危(只影响 metadata 响应内容),修法是配置"信任代理"开关。

### 3. 前端 `loadRecords` 漏校验 `parentId`

`web/src/stores/uploads.ts` 的断点记录过滤器校验了 sessionId/fileName/size/lastModified/sha256,唯独漏了 `parentId`。localStorage 里的脏记录会让 `undefined` 流入 `task.parentId`(类型声明是 `string | null`)。轻微健壮性问题,补一行校验即可。

### 4. 前端 `uploadOnePart` 403 分支的退化路径

`web/src/uploader/manager.ts` 分片 403 后刷新会话,若该片既不在已传列表也没拿到新签名 URL,会**不带退避**地拿过期 URL 快速重试 3 次才失败。边缘场景,行为可接受但不理想。

### 5. GraphQL 非业务错误被统一打码成"内部错误"

`httpx.NewGraphQLHandler` 的 ErrorPresenter 把所有非 `service.Error` 改写为 INTERNAL/"内部错误"并记 error 日志——**用户查询拼错字段也会看到"内部错误"并刷一条 slog.Error**。防泄露的初衷是对的,但校验/语法错误可以放行原文,减少日志噪音。测试跑 httpx 包时 stderr 里的 error 日志就是这个,属预期。

### 6. OAuth 若干设计取舍(记录备考,均非漏洞)

- `Refresh` 先消耗后校验 client_id:错 client_id 的刷新会烧掉合法 refresh_token。防窃取是优点,但客户端配错会导致整条刷新链失效。
- verifier **格式非法**的兑换尝试不消耗授权码(格式合法但值错误的会消耗)。与 OAuth 2.1"失败即作废"的最严格解读略有差距,实际风险极低。
- 内部错误(如 DB 故障)返回 400 invalid_request 而非 500 server_error,已正确脱敏。

### 7. 杂项

- `transferOutput`(mcpserver):session 带 node_id 时回填的 NodeOutput 只有 ID/Name/Kind,`updated_at` 是空串——严格解析 RFC3339 的客户端可能报错。
- 反代后若不配转发头信任,`ClientIP` 拿到的是反代地址,**所有客户端共享同一个限速桶**(现状是"宁可保守也不信头",httpx 测试已锁定)。
- `derive.go` 的 `lastLine` 有个不可达分支(`strings.Split` 永不返回空切片),死代码。
- 前端 `formatBytes` 负数输出 `-5 B`;`openPreview` 传 NaN 会把 index 置为 NaN(现有调用方都传合法值)。

## 二、已知问题(未修,按关注度排序)

### 1. GraphQL 非业务错误被统一打码成"内部错误"

`httpx.NewGraphQLHandler` 的 ErrorPresenter(`presentError`)分三档:`service.Error` 透出业务 code 与文案;gqlgen 在 resolver 之前产出的语法/校验错误(`GRAPHQL_PARSE_FAILED` / `GRAPHQL_VALIDATION_FAILED`)原文透出、只记 info——客户端拼错字段能看到是哪个字段,日志里不再刷 error;其余一切(panic 恢复、DB/对象存储故障)仍统一 INTERNAL/"内部错误"并记 error 日志,兜底必须打码。生产模式下 introspection 被禁用的提示不带这两个 code,所以仍显示为"内部错误"。测试跑 httpx 包时 stderr 里剩下的 error 日志来自故意触发的 panic 用例,属预期。

### 2. OAuth 若干设计取舍(记录备考,均非漏洞)

- `Refresh` 先消耗后校验 client_id:错 client_id 的刷新会烧掉合法 refresh_token。防窃取是优点,但客户端配错会导致整条刷新链失效。
- verifier **格式非法**的兑换尝试不消耗授权码(格式合法但值错误的会消耗)。与 OAuth 2.1"失败即作废"的最严格解读略有差距,实际风险极低。
- 内部错误(如 DB 故障)返回 400 invalid_request 而非 500 server_error,已正确脱敏。

### 3. 移动端(v2.3.0 交付后的遗留)

- **iOS 切后台会丢上传**:只有 `beforeunload` 守卫,没有 `visibilitychange`/`pagehide`;runtime 里的 `File` 句柄不持久化。标签页被回收后任务静默死亡,下次打开要重新选文件。
- **断点续传在 iOS 上易失效**:按 `文件名 + size + lastModified` 匹配(`stores/uploads.ts`),iOS「文件」App 重新选择同一文件时名字或 mtime 常变。
- **网格视图缩略图只有 256 档**:更小的档位没做,网格里是直接用 thumb256 缩放显示。
- **真机手测未跑**:iOS 主屏(standalone)的安全区与键盘、Android 安装横幅、微信内置浏览器打开分享页,都只在桌面 Chromium 的 390×844 仿真里验过。
- **本地环境**:`TestMakeOfficePDF` 在本机依赖免 root 的 Gotenberg + LibreOffice,冷启动常超过接口超时而 503;与代码无关,CI/服务器上的容器化 Gotenberg 不受影响。

### 4. v2.4 交付后的遗留

- **异地备份失败无人告警**:`backup.sh` 会打警告、写 `.offsite-fail`、并以退出码 9 收尾,但服务器没配 MTA 时 cron 不会发信,只能靠 `./scripts/backup.sh --status` 人查。要闭环得另外接一个告警通道(用户本轮明确不做)。
- **备份不是同一瞬间的快照**:db dump 与 minio tar 之间有缝隙,恢复后可能有极少数 blob 行找不到对象。`doc/16` 的演练把这个差值量化了(2026-09-18 那次是 0 缺失、0 孤儿),但没有消除它。
- **两处配置错了不报错、只是静默不准**:`GOPAN_TRUSTED_PROXIES`(IP 变成网关地址)与分享统计的 180 天保留窗口。上线后应人工确认一次"设备页显示的是真实公网 IP"。
- **预览预加载的时间窗**:预签名 URL 只有 15 分钟寿命,预取只在当前图加载完之后触发。在一张图上停留超过 15 分钟再翻页,那一页的预取就白做了(功能不受影响,只是没省到)。
- **回收站可能短暂显示"已到期"**:清理任务每小时才跑一次,过期条目最多滞留一小时。
- **"我的设备"这个说法搬家了**:侧栏指向 `/chat` 的入口与页面内全部文案都叫「传输助手」,`/devices` 才是字面意义的登录设备。数据库里那个自动建的文件夹仍叫「我的设备」——它是用户数据,不做迁移;MCP 工具描述也沿用这个名字。

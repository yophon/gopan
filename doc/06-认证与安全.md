# 06 · 认证与安全

## 浏览器登录双 token

| | access token | refresh token |
|---|---|---|
| 形态 | JWT(HS256,服务端单密钥) | 32 字节随机串,不透明 |
| 寿命 | 15 分钟 | 14 天 |
| 存储(服务端) | 不落库,无状态 | sha256 后存 refresh_tokens 表 |
| 存储(前端) | Pinia 内存,**不进 localStorage** | httpOnly + Secure + SameSite=Lax cookie,path 限 /query |
| 携带方式 | `Authorization: Bearer` | cookie 自动带,仅 refresh/logout 用到 |

**JWT claims**:`sub`(userID)、`scope`(`user` 或 `share:{shareId}`)、`exp`、`iat`。不塞别的——权限实时查库,JWT 只证明"你是谁"。

**旋转与重用检测**:每次 `refresh`,旧 token 标记 `used_at` 并签发同 `family_id` 的新 token。若一个 `used_at` 非空的 token 再次出现 = token 被偷且双方都在用 → 吊销整个 family,两端都被踢去重新登录。**例外是 10 秒宽限期**(`refreshReuseGrace`):旋转后 10 秒内旧 token 再来,按"同一浏览器两个标签页同时刷新、第二个请求发出时 Set-Cookie 还没落地"处理——再签一枚同 family 的新 token,不吊销;超过 10 秒才按泄露处理。前端同时用 Web Locks + BroadcastChannel 让多标签只刷新一次(doc/07),宽限期是兜底。登出、改密码 = 吊销该用户全部 family。

**前端配合**(细节见 07-前端设计):401 → 单飞刷新(并发请求共享同一个刷新 Promise)→ 重放原请求;刷新也 401 才跳登录页。

## MCP OAuth 2.1

Remote MCP 的默认入口是 OAuth Authorization Code + PKCE,不是让 Agent 先调用受保护 GraphQL 自助创建 token。

- `/mcp` 未带凭据时返回 `401` 和 `WWW-Authenticate: Bearer ... resource_metadata="..."`。
- `/.well-known/oauth-protected-resource` 与 `/.well-known/oauth-authorization-server` 提供标准发现;`/oauth/register` 动态注册 public client,不签发 client secret。
- `/oauth/authorize` 只接受已注册 redirect URI、`response_type=code` 和 PKCE `S256`;HTTP callback 仅允许 loopback,其他地址必须 HTTPS。
- 浏览器进入 `/oauth/consent`,使用现有用户登录态确认 client 名称和 scope;同意后签发 5 分钟一次性 authorization code。
- `/oauth/token` 用 code + verifier 兑换 1 小时 Access Token 和 30 天 Refresh Token;Refresh Token 每次使用立即标记 used 并轮换。
- Access Token 每次认证都联查账号是否禁用、grant 是否吊销,并取 token scope 与 grant scope 的交集。用户撤销授权后,已签发 token 立即失效。

OAuth code/access/refresh 均为 `crypto/rand` 高熵随机串,数据库只存 SHA-256。单实例只有一个 MCP resource(`/mcp`),当前接受但不依赖 OAuth `resource` 参数。

## MCP API Key

不支持 OAuth 的 Headless Agent/CI 使用 `gopan_key_*` API Key(兼容早期 `gopan_mcp_*` 前缀)。Key 由已登录用户在“Agent 接入”中创建,明文只展示一次,数据库只存 SHA-256,最多 20 条活跃 Key,可单独吊销。

OAuth 与 API Key 共用五档 scope,且在每个 MCP tool handler 进入业务层前检查:

| Scope | 能力 |
|---|---|
| `files:read` | 列目录、搜索、读元数据 |
| `files:download` | 读文本、签发文件/ZIP 下载 |
| `files:upload` | 创建、查询、完成、取消 Agent 上传 |
| `files:write` | 建目录、重命名、移动、复制 |
| `files:delete` | 移入回收站、恢复 |

永久删除不暴露给 MCP。API Key/OAuth 凭据只认证 `/mcp`,不能调用 GraphQL、WebDAV 或直接枚举 MinIO。

## WebDAV 应用密码

WebDAV 使用每设备独立的应用密码做 Basic Auth,不接受主密码。应用密码同样是随机高熵串、仅存 SHA-256、明文只显示一次、可单独吊销;成功认证不扣防爆破令牌,只有失败尝试限速,避免 rclone/Finder 的高请求频率误触 429。

## 访客授权

- `verifySharePassword`(无密码分享则直接 `shareInfo` 后请求访客 token)签发 `scope=share:{shareId}` 的 JWT,30 分钟,无 refresh——过期让访客重验,成本可接受。
- 鉴权中间件按 scope 分流:`user` 走属主校验(node.owner_id = sub);`share:*` 走子树校验(IsDescendant)+ 分享有效性(未过期未吊销)。两条路径都在业务层统一入口做,resolver 不散落权限判断。
- 访客只读:Mutation 白名单里只有 `verifySharePassword`。

## 收集链接的访客(v3.1)

- `openFileRequest` 验密码、记名字,签发 `scope=collect:{链接 id}:{访客 id}` 的 JWT(sub 仍是属主),12 小时;每次请求都回表复查链接(撤销、文件夹进回收站、属主被禁用立即失效),所以有效期只决定"多久要重新输一次密码"。
- **只写不读靠 fail closed**:所有读接口的访客分支都汇到 `Shares.Authorize` / `ValidateScope`,它们只认 `share:` 前缀;`initUpload` 等登录用户接口走 `UserFrom`;`/pack` 同样走 `Authorize`。新 scope 不用逐个接口加判断就全部被拒,`httpx` 有一条测试逐个调这些接口确认。
- 会话按 `(id, request_id, visitor_id)` 查:同一链接的另一个访客、属主自己的会话,按 id 都碰不到。
- 没有秒传:匿名访客能用秒传探测"某份内容是否有人存过";访客也不传 sha256,落库时服务端算。
- 分片预签名把 `Content-Length` 签进去(MinIO 校验),一片声称 5MB 的分片塞不进几个 G;落库时再复核总大小。
- 限速:打开链接按 IP(6 秒回一个、突发 10);错密码按**链接**计数(一小时最多 20 次,换 IP 也躲不过);开会话按访客(每秒 1 个、突发 60)。会话数每链接 20、每访客 4,不占属主自己的 20 个。
- 对访客只说"收件已满",不透露属主剩余空间;`fileRequestInfo` 不含属主信息。

## 预签名 URL 的边界

- PUT(上传分片):1 小时,绑定具体 key + uploadId + partNumber,拿到 URL 也只能写那一片。
- Agent PUT:单 PUT 或 multipart 都绑定服务端生成的 staging/blob key;Agent 不能指定 object key。上传完成后服务端复核实际大小、SHA、目录权限和配额。
- GET(下载/预览):15 分钟。**泄露风险窗口 = 15 分钟内知道 URL 的人可下载该文件**,对云盘可接受;不可接受时改走 Go 中转(牺牲带宽换控制),留配置开关。
- Agent ZIP ticket:10 分钟,claims 只含 userID 与允许打包的 node IDs,不能用作通用登录凭据。
- MinIO 桶全私有,不开任何匿名策略;`derived` 与 `blobs` 同待遇。
- **预签名地址与站点同源,响应不经过 Go**(反代把 `/gopan/*` 直接转 MinIO),对象类型又来自上传者起的文件名。所以内联预签名一律显式改写响应类型(`objstore.InlineOverrides`:图片 / 音视频 / PDF 保留,svg 加 attachment,其余按纯文本),反代另给 `/gopan/` 加 `Content-Security-Policy: sandbox; default-src 'none'; …` 与 `nosniff` 兜底。否则上传的 svg / html 被「查看原图」顶层打开时,脚本以站点身份运行,能带着 refresh cookie 换到 access token(v3.0.1 修复,doc/20 P0)。

## 离线下载与压缩包(v3.3)

离线下载等于让用户指挥服务器去访问任意地址;gopan 容器同时连着内网(postgres、minio、gotenberg)和外网,必须把内网挡住(doc/21 三.3):

- **按真实连接的 IP 检查**:在 `net.Dialer.Control` 里判断要连的地址,DNS rebinding 绕不过去;每次重定向重新检查,最多 5 次、只能是 http / https。
- **拒绝**:回环、私有网段、链路本地(含云元数据 169.254.169.254)、CGNAT、组播、保留地址、IPv6 ULA / 链路本地、NAT64、IPv4 映射的 IPv6;外加 `GOPAN_FETCH_DENY`(部署时填 VPS 自己的公网 IP:容器访问宿主机公网地址可能绕过只防外部的防火墙)。`GOPAN_FETCH_ALLOW_PRIVATE=true` 放开私有网段与 fake-ip 代理用的 198.18.0.0/15,回环和链路本地照样拒。
- **不走系统代理**(经代理时 IP 检查失效);关掉 Go 的自动 gzip(存下的字节要与源文件一致)。
- 日志、任务错误信息与 MCP 审计只记主机名,不记路径和查询串(下载链接常带签名)。

压缩包:

- **单个文件 `/arc` 经过 Go**:鉴权同 `/pack`(token 走查询串或 Bearer 头),访客走 `Shares.Authorize`;响应类型同内联预签名(`InlineOverrides`,html / xml 按纯文本、svg 加 attachment),自己带 CSP sandbox 与 nosniff;全站同时 2 路,单个文件 ≤ 100 MB,要先解掉的数据 ≤ 256 MB。
- **解码有上限**:7z 的 LZMA / LZMA2 / PPMD / zstd、rar、xz 在建解码器前按属性检查字典 / 模型内存,超过 64 MB 拒绝(解码内存约等于字典,精简档容器只有 384 MB);实际解出的字节超过条目声明的大小即停;条目超过 10 万只列前 10 万;压缩的 tar 超过 4 GB 不建索引。
- **不解危险条目**:路径带 `..` 的(zip slip)、软链接、硬链接、设备文件一律跳过并计数;解压只建新文件夹,不覆盖已有文件;解压前按条目声明的总大小预检配额。

## 直链、图床与推送(v3.4)

直链是公开的:拿到地址的任何人都能访问,而且和网页同域。

- **字节经 Go 中转**(不跳转到对象存储的签名地址),所以吊销、暂停即时生效,流量记得准、上限拦得住。查找只看 token(10 位 base58,同分享),处理时不读 Cookie、不认登录态。
- **响应类型由服务端定**:图片、音视频、PDF 内联;SVG 内联但带 `CSP: sandbox`,直接打开也跑不了脚本;HTML、XML、JavaScript 一律 `application/octet-stream` 下载;其余下载。都带 nosniff、`X-Robots-Tag: noindex`、`Access-Control-Allow-Origin: *`(公开内容,不带凭据)。
- **防滥用**:来源白名单(按主域名,含子域;可选拒绝无来源);每 IP 每分钟 120 次;全站同时 16 路;每条每天、全站每月流量上限。突增(一小时超过 max(300, 平时 10 倍))、陌生站点一小时引用超过 100 次、单 IP 十分钟 600 次都提醒属主,可设异常时自动暂停。每次访问记 IP、客户端、来源,明细留 30 天。
- **图床密钥**:scope `img:upload` 的 API Key,只能往图床文件夹上传并生成直链,读不了、列不了网盘;不收 URL 里的密钥(会进日志)。新建任何凭据(应用密码、API Key、图床密钥、Agent 授权)都会发「新的访问凭据」通知,泄露时能第一时间发现。
- **照片位置**:图床上传默认就地抹掉 JPEG EXIF 的 GPS 与 XMP 里的位置(不重新压缩、长度不变);给已有照片生成直链时检测到位置会提示。
- **推送出站**与离线下载同一道拦截(按真实连接 IP 拒内网、本机公网 IP,不走系统代理,10 秒超时);内网自建的 ntfy 要 `GOPAN_NOTIFY_ALLOW_PRIVATE=true`。渠道的令牌 / device key / bot token 发送时要用原值,只能明文存库;GraphQL 只写不读(只回末 4 位),失败回应里出现的密钥打成 `***`。
- **登录提醒**:每次密码 / Yophon ID 登录都发通知,带设备与 IP;不是自己就去「登录设备」吊销。

## 密码与凭据

- 用户密码、分享密码:bcrypt(cost 12)。
- 分享 token:10 位 base58(≈58^10 ≈ 4×10^17),防枚举足够;验密接口按 token 限速(见下)。
- 所有对外随机值(refresh、分享 token、应用密码、API Key、OAuth 凭据)用 crypto/rand,不用 math/rand。

## 限速与防滥用

- 登录、verifySharePassword:每 IP 每分钟 10 次,超限指数退避。v1 用进程内令牌桶(golang.org/x/time/rate 按 key 分桶),单机够用。
- initUpload 做配额预检 + 单用户并发 session 上限(如 20),防恶意开会话耗 MinIO multipart 资源。
- Agent 上传同样做配额预检,单用户最多 20 个活跃 transfer session;`idempotency_key` 防重试重复占用资源,worker 清理过期 single PUT/multipart/staging。

## 其他清单

- CORS:同源部署(前端 embed),生产不需要 CORS;开发期 Vite proxy 同样规避。
- Remote MCP 使用 Go `CrossOriginProtection`,拒绝不可信浏览器跨源请求;原生 MCP Host 不带 Origin 的请求正常通过。
- CSRF:refresh 在 cookie 里,`SameSite=Lax` + 自定义头(`X-Requested-With`)双保险;其余接口靠 Bearer 天然免疫。
- GraphQL:生产关 introspection 与 playground;深度/复杂度限制见 05。
- pprof 只绑 127.0.0.1 内网端口,反代永不转发。
- 日志里不打 token、密码、预签名 URL(slog 封装 redact helper)。
- Gotenberg 处理的是用户文件,容器跑在内网、无出网权限(compose 里 internal network),防 SSRF 型文件。

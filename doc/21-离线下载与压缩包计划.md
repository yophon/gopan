# 21 · 离线下载与压缩包计划

> 结论先行:两件事都是"服务端替用户干的长活"。**离线下载**:给一个链接,服务器自己把文件拉进网盘;**压缩包**:不下载就能看里面有什么、预览其中的文件、一键解压到网盘。两者都是字节流经过 Go 的显式例外(同 WebDAV、`/pack`),共用一张后台任务表、一条流式落库路径和一块「后台任务」界面。坚持轻:不加系统包、不加常驻组件,闲时零开销,镜像只多二进制里几 MB 的解码库。顺序:J0 共同底座 → F 离线下载 → A 压缩包 → 安卓。

## 一、目标与边界

### 离线下载

**目标**:网页、安卓和 MCP 都能提交 http(s) 链接(一次最多 10 条),服务器在后台把文件下进指定文件夹;看得到进度和速度,能取消、重试;下载中途断线时,源站支持的话用 Range 接着下。在安卓浏览器里把一个链接「分享」给 gopan,传输助手里一点就能存;目标是传输助手文件夹时,下完自动在会话里出现文件卡片。

**不做**:

- BT / 磁力 / ed2k(吃资源、要开端口、版权说不清)。
- 需要登录的链接:网盘分享页(百度、阿里云盘等拿不到真实文件地址)、要 Cookie 的站点;视频网站解析(yt-dlp 一类)。
- 网页存档(连同页面里的图片、样式一起存)。
- 服务重启后的断点续传:重启后整个任务重下,只有进程内的断线才续。
- 定时下载、订阅。

### 压缩包

**目标**:zip、7z、rar、tar(含 `.tar.gz` / `.tgz` / `.tar.bz2` / `.tar.xz`)不用下载就能浏览目录、预览其中的图片 / PDF / 文本;整包或选中的部分解压到网盘;Windows 打出来的 zip 里 GBK 编码的文件名正常显示;分享访客能浏览分享里的压缩包。Agent 能列目录、解压。

**不做**:

- 在线打包或修改压缩包(多选打包下载 `/pack` 已有)。
- 加密包解密:文件名没加密时能列目录,但不能预览和解压(见第八节决策 4)。
- 压缩包里的视频 / 音频在线播放;包中包的浏览;内容搜索索引压缩包里的文字。
- 分卷(`.part1.rar`、`.7z.001`、`.z01`)与单独的 `.gz` / `.bz2` / `.xz`(不是 tar 的)。

**两者都坚持**:精简档(2 核 2G、gopan 容器 384 MB)完整可用;不加系统包、不加常驻组件,闲时零开销;经过 Go 的字节流都有并发闸和内存上限。

## 二、共同底座(J0)

### 1. 后台任务表(迁移 00023)

现有 `tasks` 是按 blob 的(校验、派生物),没有属主、没有进度。离线下载和解压是"某个用户的一次操作",另开一张 `user_jobs`:

| 列 | 内容 |
|---|---|
| `id`、`owner_id`、`kind` | kind 为 `fetch_url` / `extract_archive` |
| `status` | `queued` / `running` / `done` / `failed` / `canceled` |
| `params` | jsonb。离线下载:`url`、可选 `name`;解压:`node_id`、`entries`(空表示整包) |
| `parent_id`、`result_node_id` | 目标文件夹;下好的文件或解出来的文件夹 |
| `bytes_done`、`bytes_total` | 进度;总量未知时为空 |
| `files_done`、`files_total`、`files_skipped` | 解压用 |
| `error_code`、`error_message`、`attempts`、`source` | source 为 web / android / mcp |
| `heartbeat_at`、`created_at`、`started_at`、`finished_at` | |

- **执行**:独立于 `tasks` 的一组 runner(`GOPAN_JOB_WORKERS`,默认 1),长活不占缩略图和 hash 校验的 worker。`FOR UPDATE SKIP LOCKED` 领任务;每 5 秒写一次进度与心跳,同时读回状态,被取消就停下并清掉暂存。
- **收尾**:心跳超过 2 分钟的 running 任务(进程崩溃、重启)退回 queued,第 3 次仍中断记 failed(与 `tasks` 的收尾做法相同)。`tmp/jobs/` 下超过 1 天的暂存对象周期清理。
- **保留**:结束的任务保留 7 天,也可手动清除。每人同时排队 + 进行中的任务不超过 10 个。

### 2. 流式落库

WebDAV 的 `CommitStreamed`(暂存 → sha → 秒传或提升为内容寻址对象 → 锁用户行扣配额 → 建节点)已在生产上跑着。抽出一个带选项的版本,三方共用:

- **撞名**:WebDAV 照旧覆盖;离线下载与解压自动改名。
- **校验**:sha 是服务端边写边算的,blob 直接记为已校验(与浏览器暂存一致),`verify_hash` 只负责触发派生物,不再把对象重读一遍。
- **传输助手**:目标是传输助手文件夹时照常 `attachChatMessage`,会话里自动出现文件卡片。

### 3. 接口与界面

- GraphQL:`myJobs(active, cursor)`、`job(id)`、`cancelJob(id)`、`retryJob(id)`、`clearFinishedJobs`。
- 网页:上传抽屉加「后台任务」分组(离线下载、解压),显示进度、速度、失败原因,能取消、重试、打开所在位置。有进行中的任务时每 2 秒轮询,没有就不轮询。
- 安卓:「传输」页加同一分组。
- MCP:`get_job`、`list_jobs`(`files:read`)。

## 三、离线下载(F1)

### 1. 流程

1. **提交**:`fetchUrls(urls, parentId)` 校验协议(只收 http / https)、长度、条数,写 `user_jobs`。
2. **请求**:用安全客户端(见 3)发 GET。文件名依次取 Content-Disposition(含 `filename*`,非 UTF-8 时按 GB18030 兜底)、URL 最后一段(百分号解码)、主机名;没有扩展名就按 Content-Type 补。有 Content-Length 时先查配额与单文件上限,不够直接失败。
3. **写入**:边读边算 sha,边 `PutStream` 到 `tmp/jobs/{id}`(16 MB 一片,内存可控)。没有长度时边写边对剩余配额计数,超了就停。
4. **断线**:首个响应带了 ETag 或 Last-Modified、且声明 `Accept-Ranges: bytes` 时,带 `Range` + `If-Range` 接着读,管道另一头的 `PutStream` 和 sha 都不中断;不满足就整个重来(计入 attempts)。
5. **落库**:走二.2 的流式落库,撞名改名;暂存对象成功失败都清。

关掉 Go Transport 的自动 gzip(`DisableCompression`),否则存下来的字节与源文件不一致。

### 2. 限制

| 项 | 默认 |
|---|---|
| 单文件上限 | `GOPAN_FETCH_MAX_SIZE`,20 GiB(同时受配额约束) |
| 同时下载 | `GOPAN_JOB_WORKERS`,1 |
| 重定向 | ≤ 5 次 |
| 超时 | 连接 10 s、TLS 10 s、响应头 30 s;60 s 读不到字节算断线 |
| 单次提交 | ≤ 10 条链接 |
| 限速 | `GOPAN_FETCH_RATE`,默认不限(与别的服务共用带宽的机器可以设) |
| 开关 | `GOPAN_FETCH`,默认开;`false` 全站关掉,入口隐藏 |

### 3. 防 SSRF

gopan 容器同时连着内网(postgres、minio、gotenberg)和外网。离线下载等于让用户指挥服务器去访问任意地址,必须把内网挡住:

- **按真实连接的 IP 检查**:在 `net.Dialer.Control` 里判断要连的地址,不在 DNS 解析阶段判断,这样 DNS rebinding 绕不过去;每次重定向都重新检查。
- **拒绝的地址**:回环、私有网段、链路本地(含云元数据 `169.254.169.254`)、CGNAT `100.64.0.0/10`、组播与保留地址、IPv6 ULA 与链路本地、IPv4 映射的 IPv6。
- **本机公网 IP**:容器访问宿主机自己的公网 IP,可能绕过只防外部的防火墙,碰到只想对本机开放的服务(同一台机器上还跑着 sub2api)。`GOPAN_FETCH_DENY` 可追加网段,doc/09 写明部署时把 VPS 自己的 IP 加进去。
- **不走系统代理**:忽略 `HTTP_PROXY` 等环境变量,经过代理时 IP 检查就失效了。
- **局域网例外**:自部署在家里、要从局域网 NAS 拉文件的,用 `GOPAN_FETCH_ALLOW_PRIVATE=true` 显式打开。
- **日志与审计只记主机名**:下载链接常带签名,路径和查询串不落日志。

### 4. 入口

- **网页**:文件页工具栏「离线下载」→ 粘贴链接(一行一个)→ 存到当前文件夹。
- **安卓**:文件页「+」→「离线下载」。从别的 App 分享进来的文字里有链接时,传输助手草稿上方出现「离线下载这个链接」,存到传输助手文件夹,下完在会话里出现文件卡片。
- **MCP**:`fetch_url(url, folder_id 或 path, name?)` 返回任务 id,用 `get_job` 查进度;要 `files:upload`。

## 四、压缩包

### 1. 格式与库

| 格式 | 列目录的代价 | 单个文件预览 | 库 |
|---|---|---|---|
| zip(含 zip64) | 只读文件末尾的中央目录,范围读几十 KB | 随机读,便宜 | 标准库 `archive/zip`;MinIO 对象本身支持 `ReadAt` |
| 7z | 读文件末尾的头部 | 非固实随机读;固实要从块头解到它 | `bodgit/sevenzip` |
| rar4 / rar5 | 逐个读文件头 | 顺序读到它 | `nwaples/rardecode/v2` |
| tar、`.tar.gz` / `.tgz` / `.tar.bz2` / `.tar.xz` | 整包读一遍,压缩的要整包解一遍 | 顺序读到它 | 标准库 + `ulikunitz/xz` |

全部是纯 Go,不装系统包;`klauspost/compress` 已是间接依赖。A1 实测二进制增量并写进 doc/09。不用 `mholt/archives`:它一次拉进十几种用不上的编解码器。rar 读文件头时能否靠 Seek 跳过数据区,A1 先验证;不能的话按压缩 tar 同样处理大小上限。

### 2. 目录索引(同在迁移 00023)

按 blob 建一次索引(内容寻址,同一个包只读一次),worker 任务 `archive_index`:

| 表 | 内容 |
|---|---|
| `blob_archives` | `blob_id`(主键,→ blobs ON DELETE CASCADE)、`format`、`status`(done / truncated / unsupported / failed)、`solid`、`encrypted`、`entry_count`、`total_size`(解压后总大小)、`indexer`(版本号)、`error`、`updated_at` |
| `archive_entries` | `blob_id`、`idx`(包内序号)、`path`、`parent`、`name`、`is_dir`、`size`、`packed_size`、`mtime`、`encrypted`、`unsafe`;主键 `(blob_id, idx)`,索引 `(blob_id, parent, name)`。包里没有显式目录条目的(zip 常见),建索引时补出目录行 |

- **文件名**:不是合法 UTF-8 的按 GB18030 解(zip 没标 UTF-8 时、tar),复用 `fulltext` 的编码识别。路径统一成 `/` 分隔,去掉开头的 `/`、盘符、`.`;含 `..` 的条目标记 `unsafe`,能看不能解。
- **上限**:超过 10 万条只存前 10 万条,记 truncated;压缩的 tar 超过 4 GB 不建索引(整包解一遍太久),记 unsupported,界面提示下载。
- **入队**:blob 校验通过后,引用它的文件名是压缩包扩展名、文件头魔数也对得上,才入队。docx / apk / epub 也是 zip,按扩展名排除。存量每分钟回填 30 个,与内容索引一样细水长流;优先级与 `extract_text` 相同(最低)。

### 3. 浏览与预览

- **接口**:`PreviewKind` 加 `ARCHIVE`;`archiveInfo(nodeId)` 返回格式、状态、条目数、解压后总大小、是否加密;`archiveEntries(nodeId, path, cursor)` 返回该目录下的条目(目录在前、按名字排)。分享访客令牌在分享子树内可用,收集令牌不行。
- **单个文件预览**:`GET /arc/{nodeId}/{idx}?token=<access>`(同 `/pack`,预览地址没法带 Authorization 头),Go 解压后流式返回。响应类型走 `InlineOverrides`(html、svg 不以可执行类型返回);这条响应经过 Go,自己带上 CSP sandbox 与 nosniff。
- **限制**:单文件 ≤ 100 MB;要先解掉前面的数据(固实 7z、rar、压缩 tar)且超过 256 MB 时返回 `ARCHIVE_ENTRY_TOO_DEEP`,界面提示解压后再看;全站同时进行的预览 ≤ 2 路(同 `/pack` 的并发闸)。只预览图片、PDF、文本。

### 4. 解压

- **提交**:`extractArchive(nodeId, entries, parentId)`,entries 为空即整包。默认解到压缩包所在目录下的新文件夹「包名去掉扩展名」,已存在就改名,不与已有文件合并。
- **预检**:选中条目解压后的总大小不超过剩余配额,否则直接拒;一次最多 2 万个文件。
- **执行**:顺序读包(zip 按条目偏移排序,读起来是顺序的),每个文件 `PutStream` 到暂存、算 sha、走流式落库;子文件夹按需建;同内容已存在只加引用,不占存储。
- **跳过并计数**:`unsafe` 条目(zip slip)、软链接、硬链接、设备文件、名字不合法的。
- **炸弹**:实际解出的字节超过条目声明的大小就停;7z、rar、xz 的字典超过 64 MB 拒绝(解码内存约等于字典大小)。
- **中途失败**(配额被别的上传占满、包损坏):已经解出的文件保留,任务记失败和已完成的个数。

### 5. 入口

- **网页**:预览压缩包时进入包内浏览(面包屑、条目列表、勾选),「解压选中的」「全部解压到…」(复用移动对话框的文件夹选择);右键菜单加「解压到…」。
- **分享访客页**:能浏览、预览,不能解压。
- **安卓**:同网页。
- **MCP**:`list_archive(node_id, path?)`(`files:read`)、`extract_archive(node_id, entries?, folder_id?)`(`files:upload`,返回任务 id)。

## 五、资源账

- **闲时**:零。runner 空闲时睡眠;索引回填每分钟一次查询。
- **镜像**:不加系统包,二进制多几 MB(A1 实测)。
- **内存**:离线下载每个任务一片 16 MB 缓冲;解压是一片 16 MB 缓冲加解码字典(≤ 64 MB);预览最多 2 路。默认只跑 1 个任务,精简档 384 MB 的容器放得下。
- **CPU**:下载和 zip 解压只有 sha、TLS、deflate 的开销;压缩 tar 建索引、固实包解压是 CPU 活,靠单 runner 加 4 GB 上限兜住。
- **磁盘**:本地不落盘,全部流式进 MinIO;解压出来的重复内容按 sha 只存一份。索引每个条目约 150 字节,10 万条约 15 MB。
- **流量**:离线下载进来的字节算 VPS 入站,用户再下走又是一遍出站。

- **F2 / A3**:模拟器上从浏览器分享链接 → 传输助手点「离线下载」→ 会话里出现文件卡片;App 里浏览 zip、预览图片、解压。

## 七、风险与对策

- **SSRF 是新的攻击面**:三.3 逐条写进测试;F1 上线后在生产上拿内网地址实测一遍被拒。
- **流量翻倍**:下进来、再被下走;doc/11 写明,共用带宽的机器设 `GOPAN_FETCH_RATE`。
- **机房 IP 被网站拒**:常见结果是拿到一个 403 或验证码页面。状态码非 2xx 记失败;2xx 但 Content-Type 是 text/html、而链接看起来是文件时,任务照常完成,界面标出「拿到的是网页,不是文件」。
- **纯 Go 解码库的边角**(rar5 的特殊过滤器、7z 的 BCJ2 等):读不了的记 unsupported、提示下载,不影响别的包;样本集进测试。
- **固实包、压缩 tar 慢**:预览限 256 MB 深度、建索引限 4 GB,超过就提示解压或下载。
- **解码内存**:字典上限 64 MB,默认单 runner。
- **schema 变化**:只加不减;新表旧二进制不读,回滚不需要额外处理(A2 前再核一遍)。

## 八、需要拍板的决策(括号里是建议)

1. 离线下载对所有用户开放(建议如此:定位是小圈子;管理员可用 `GOPAN_FETCH=false` 全站关掉)。
2. 只做 HTTP / HTTPS 直链,不做 BT 和网盘分享页(建议如此,见第一节)。
3. 解压到压缩包旁边的新文件夹,不合并、不覆盖(建议如此:解错了删掉一个文件夹就行)。

# 30 · 搜索筛选

> 文件名搜索与内容搜索加上筛选:类型、修改时间、大小、只搜某个文件夹(含子文件夹)、排序。网页、安卓、服务端一起,3.15.0 发布。

## 一、用的人看到的

- 搜索页结果上面一排:类型(多选)、修改时间、大小、排序(文件名标签);在某个文件夹里点搜索,默认带上「只在『这个文件夹』里」,点 × 搜全部。
- 设了条件就可以不填关键词:「大于 1 GB 的视频」「今年改过的文档」直接列出来。内容搜索仍然要关键词(至少两个汉字或三个字母)。
- 网页:条件写进地址(`type=image,video`、`t=7d` 或 `t=2026-01-01~2026-01-31`、`size=gt1g`、`sort=size`、`folder=<id>`;标签照旧是 `in=content`),刷新、返回都还在。修改时间多一个「自己选…」日期范围。
- 安卓:搜索框下面一排小标签,点开选;从文件夹里点搜索带上范围。

## 二、接口

```graphql
searchNodes(q: String!, cursor: String, filter: SearchFilter): NodePage!
searchContent(q: String!, cursor: String, filter: SearchFilter): ContentHitPage!

input SearchFilter {
  types: [SearchType!]          # FOLDER IMAGE VIDEO AUDIO DOCUMENT ARCHIVE TEXT OTHER
  modifiedAfter: Time           # [after, before)
  modifiedBefore: Time
  minSize: Int64                # 含两端;设了就只剩文件
  maxSize: Int64
  folderId: ID                  # 只搜这个文件夹的子树
  order: SearchOrder            # UPDATED(默认)/ NAME / SIZE
}
```

- 类型的划分与空间分析共用 SQL 函数 `gopan_file_category(name, mime)`(迁移 00027),所以「文档」在两边是同一批文件;FOLDER 是文件夹本身。
- 不带 filter(或只是默认值)时文件名搜索照旧走按修改时间的键集翻页,旧客户端的游标不受影响;带了走 `SearchNodesFiltered`:可选条件全是 `sqlc.narg`,排序方式多,翻页用偏移(最多翻到 1 万条),同一组条件另有 `CountSearchNodesFiltered` 给总数。
- 只搜某个文件夹:递归 CTE 取子树,子树根要是本人的(`owner_id` 条件写在 CTE 里),文件夹本身不算结果。
- 内容搜索的两个查询(全盘、子树)加同样的可选条件;内容搜索只按修改时间排,忽略 order,也没有文件夹。MCP 的 `search_file_contents` 不带筛选。
- 分享访客的搜索(分享子树内)忽略 filter。
- 不认识的类型、负数大小、不认识的排序回 `INVALID_INPUT`。

## 四、没做的

- 按「创建时间」「上传者」「分享状态」筛:用得少,真有需要再加参数。
- 保存常用的筛选:地址能收藏,够用。
- 安卓自己选日期范围:手机上用预设足够。

# 23 · 动态、空间、订阅与剪藏计划

> 结论先行:四件事。**动态与撤销**:网页、App、WebDAV、Agent、收集链接、后台任务对网盘做的每一次改动都记一笔(谁、什么时候、对哪个文件做了什么),移动 / 改名 / 删除 / 新建能单条或整批撤回;WebDAV 和 Agent 短时间内大量删除时提醒你。**空间分析**:类型分布、最大的文件夹和文件、盘里的重复文件、很久没动的大文件、空文件夹、没人用的分享与直链,勾选后进回收站;顺手把文件列表改成自然顺序(「第2集」在「第10集」前面)。**订阅**:RSS / 播客 / GitHub Releases,有新内容自动下进网盘并通知。**剪藏**:把网页正文存成 Markdown(图片一起存),网页、书签栏、安卓分享菜单、Agent 都能存;Markdown 文件在网盘里直接渲染着看。坚持轻:不加系统包、不加常驻组件,闲时零开销,镜像只多几 MB 的 Go 库。四件一起作为 v3.5.0 上线,安卓 App 3.5.0 同步。

## 一、目标与边界

### 动态与撤销

**目标**:一个「动态」页面,按时间列出所有改动,能按来源(哪台设备、哪个应用密码、哪个 Agent、哪条收集链接、哪个后台任务)、按操作、按文件筛选;文件详情里能看这个文件的历史。移动、改名、删除、新建能撤回,同一次操作(一次多选移动、Agent 的一次工具调用、一次解压)能整批撤回,某个来源在某段时间里的全部改动也能一次撤回。WebDAV 客户端或 Agent 10 分钟内删了很多东西时发提醒,点进去就能撤回。

**不做**:

- 覆盖的内容撤不回、彻底删除撤不回(没有版本,这是 2026-10-20 定下的;doc/12 写明)。
- 文件被谁看过、下载过(分享和直链的访问记录已经有,自己的浏览不记)。
- 重做(撤回本身也是一次普通改动、也记进动态,想恢复再对它撤回即可)。

### 空间分析

**目标**:一页看清空间花在哪:按类型、按文件夹逐层、最大的文件、重复文件、很久没动的大文件、空文件夹、回收站;过期或没人访问的分享、直链、收集链接。所有清理都是移进回收站(30 天内能还原),也记进动态。管理端看每人用量、去重省下的空间、缩略图等派生文件的占用。文件列表按名字排序时改成自然顺序,中文按拼音。

**不做**:

- 按「最后访问时间」找冷文件(不记访问;只能按修改时间)。
- 相似图片 / 相似视频(要算特征,太耗性能)。

### 订阅

**目标**:订阅 RSS / Atom(包括播客)和 GitHub 仓库的 Releases。服务器定时检查,新内容按订阅的方式处理:**下载附件**(播客的音频、视频,GitHub Release 里匹配的安装包)、**剪藏正文**(博客文章存成 Markdown)、或**只记录**(列出来,想要哪条手动下)。可以设关键词过滤、只留最近 N 集;导入 / 导出 OPML。新内容和连续失败都走通知。

**不做**:

- YouTube、B 站等视频站(要 yt-dlp,Python 运行时让镜像大 100 MB 以上,且常需要跟着网站改版更新)。
- 网页变化监控、需要登录的 RSS(私有 token 写在地址里的除外)。
- 在线阅读器那种已读未读管理(条目只是下载来源,读在网盘里读)。

### 剪藏

**目标**:给一个网页链接,服务器抓下来提取正文,转成 Markdown,图片下到旁边的 `.assets` 文件夹,存进「剪藏」文件夹,自动进内容搜索。入口:网页「剪藏」页、浏览器书签栏小工具(看到哪篇点一下)、安卓分享菜单、订阅、Agent。需要登录才能看的页面,书签栏小工具可以把当前页面的内容一起送过来。Markdown 文件(不只是剪藏)在网页和 App 里直接渲染,相对路径的图片能显示。

**不做**:

- 整页快照(保存原样的 HTML / 截图 / PDF);只存正文。
- 编辑 Markdown(在线编辑在 doc/12 的不做清单里)。
- 浏览器扩展(书签栏小工具不用装东西,各浏览器都能用)。

**四者都坚持**:精简档(2 核 2G、gopan 容器 384 MB)完整可用;不加系统包、不加常驻组件,闲时零开销。

## 二、动态与撤销

### 1. 记录(A1,迁移 00027)

| 表 | 内容 |
|---|---|
| `activities` | `id`(bigserial)、`owner_id`、`at`、`actor_kind`、`actor_ref`、`actor_label`、`batch_id`、`action`、`node_id`(不设外键:节点彻底删了记录还在)、`node_kind`、`name`、`parent_path`(当时所在位置)、`detail`(jsonb:原 / 新文件夹及路径、原 / 新名字、子树文件数与字节、撤回的是哪条)、`undone_at`;索引 `(owner_id, id DESC)`、`(owner_id, actor_kind, actor_ref, id DESC)`、`(node_id, id DESC)`、`(owner_id, batch_id)` |

**来源**(`actor_kind` / `actor_ref` / `actor_label`):

| 来源 | ref | 显示 |
|---|---|---|
| 网页 / App(GraphQL) | 登录会话 | 设备名(「Edge · Windows」「安卓 App · Pixel 8」),与「登录设备」一致 |
| WebDAV | 应用密码 | 应用密码的名字 |
| Agent(MCP) | API Key / OAuth 授权 | 凭据名字;`batch_id` = 那次工具调用 |
| 图床上传 | 图床密钥 | 密钥名字 |
| 收集链接 | 收集链接 | 「作业收集 · 张三」(访客留的名) |
| 后台任务 | 任务 | 离线下载 / 解压 / 订阅 / 剪藏,带任务标题 |
| 系统 | — | 回收站到期清理 |

来源由各入口放进 `context`(`service.WithActor`),服务层写操作统一记一笔;`batch_id` 每次请求 / 工具调用 / 任务一个。设备名快照写进行里(会话过期删掉后还能看)。

**记哪些**:新建文件夹、上传(新建 / 覆盖)、改名、移动、复制、删除(进回收站)、还原、彻底删除、清空回收站、离线下载落库、解压、收集收件、传输助手发文件、订阅下载、剪藏、图床上传、回收站到期清理。同一次操作涉及多个节点(多选移动、复制整个文件夹)按顶层节点一条一行,子树只在 `detail` 里记个数和字节,不逐个展开;一次批量写一条多值 INSERT,与业务同一事务。

**保留**:90 天,每日清理。

### 2. 撤回(A2)

| 操作 | 撤回 = | 什么时候撤不了 |
|---|---|---|
| 移动 | 移回原文件夹;原位置有同名的,自动改名「xxx (撤回 1021-1530)」 | 原文件夹已删除(提示放回根目录还是放弃) / 节点已不在 |
| 改名 | 改回原名 | 之后又改过名 / 原名已被占用 |
| 删除 | 从回收站还原 | 已彻底删除 / 已被还原 |
| 新建、上传、复制、解压、离线下载、订阅下载、剪藏、收集收件、图床上传 | 移进回收站 | 节点已不在 |
| 还原 | 再删进回收站 | 节点已不在 |
| 覆盖、彻底删除、清空回收站、到期清理 | — | 永远撤不了,列表上标「不可撤回」 |

- **单条**:动态里每行一个「撤回」。
- **整批**:同一个 `batch_id`(一次多选、一次 Agent 调用)折叠成一组,一个「撤回这一组」。
- **按来源**:筛出「某个 Agent 今天的改动」「rclone 这 10 分钟的删除」后「全部撤回」(一次最多 1000 条)。
- **先预览**:整批 / 按来源撤回先列出「会撤回 N 项,M 项撤不了(原因)」,确认后从新到旧逐条执行,每条各自成败,最后给结果。
- 撤回本身记为新的动态(来源是你当前的设备,`detail.undo_of` 指回原记录),原记录标「已撤回」。

### 3. 大量删除提醒

WebDAV 与 Agent(以及图床密钥)这类不需要你在场的来源,同一个凭据 10 分钟内删除 ≥ 200 个文件或 ≥ 2 GiB(按子树算):发一条严重通知「rclone(WebDAV)10 分钟内删除了 312 个文件,共 4.2 GB」,默认推送,点开是动态页按这个凭据和时间段筛好的结果,上面就是「全部撤回」。同一凭据每小时最多一次。网页和 App 上是你自己点的,不提醒。

### 4. 入口

- **网页**:侧栏「动态」(`/activity`):按天分组、同一批折叠、来源 / 操作 / 时间筛选、撤回;文件详情抽屉加「历史」(这个节点的动态)。
- **安卓**:「我的 → 动态」:列表、按来源筛选、单条与整批撤回(按来源撤回在网页上)。
- **MCP**:`list_activity`(scope `audit:read`):Agent 能查自己或别人做过什么,不提供撤回工具(撤回由人来点)。

## 三、空间分析

### 1. 空间页(S1)

网页侧栏用量条可点,进 `/space`;安卓「我的 → 空间」。全部现查(只读查询,单人十万个文件在一秒内),不建新表。

| 区块 | 内容 | 操作 |
|---|---|---|
| 总览 | 已用 / 配额、回收站占用、按类型(图片 / 视频 / 音频 / 文档 / 压缩包 / 代码与文本 / 其他)的条形图 | 清空回收站 |
| 文件夹 | 从根开始逐层看哪个文件夹最大(用已有的子树统计),点进去下钻 | 打开 |
| 大文件 | 前 100 个,可按类型筛 | 勾选进回收站 |
| 重复文件 | 同一份内容在你盘里出现多次的(按内容指纹,查起来几乎不花代价),按「删掉多余的能省多少」排序,每组列出所有位置,默认留最早的一份 | 勾选进回收站 |
| 很久没动 | 一年以上没改过的大文件(≥ 100 MB) | 勾选进回收站 |
| 空文件夹 | 子树里没有任何文件的文件夹 | 勾选进回收站 |
| 分享与直链 | 已过期的分享与收集链接、90 天没人访问的分享与直链 | 吊销 / 删除 |

页面上写明:**服务器上同一份内容本来就只存一份,删重复文件省的是你的配额,不是服务器磁盘**。

### 2. 管理端(S2)

管理端概览加「存储」卡片:全站逻辑用量(各人加起来)与物理占用(去重后真正存的)、去重省下多少;缩略图 / 转换的 PDF / 视频封面这类派生文件占多少;正文索引多大;等待回收的内容;每人用量与配额排行。

### 3. 自然顺序(S3,同在 00027)

- 迁移里建 ICU 排序规则 `natural`(`zh-u-kn-true`:数字按数值比、中文按拼音、大小写挨在一起),文件列表按名字排序的首页查询、两条翻页查询和对应索引都换成它。生产与 CI 的 `postgres:17-alpine` 带 `icu-data-full`(已确认);Postgres 没有 ICU 时回退成现在的字节序,迁移不失败。
- WebDAV 列表(客户端自己排)、搜索、回收站不变;连播的 `playlist` 本来就是自然顺序。
- 旧的翻页游标会回到首页(已有的游标校验),无害。

## 四、订阅

### 1. 数据(F1,迁移 00028)

| 表 | 内容 |
|---|---|
| `feeds` | `id`、`owner_id`、`kind`(rss / github)、`url`(RSS 地址;GitHub 是 `owner/repo`)、`title`、`site_url`、`folder_id`(→ nodes,删了就暂停订阅)、`mode`(download / clip / none)、`include` / `exclude`(标题关键词)、`asset_pattern`(GitHub 资源文件名通配,如 `*.apk`、`*linux-amd64*`)、`prerelease`、`keep_last`、`interval_minutes`、`etag`、`last_modified`、`next_check_at`、`last_checked_at`、`last_ok_at`、`last_error`、`fail_count`、`enabled` |
| `feed_items` | `id`、`feed_id`(级联)、`guid`(每个订阅内唯一)、`title`、`url`、`enclosure_url` / `type` / `size`、`published_at`、`state`(new / skipped / queued / done / failed)、`job_id`、`node_id`、`error` |

### 2. 检查与处理(F2)

- **检查**:worker 每 5 分钟取到期的订阅(每轮最多 5 个),条件请求(`If-None-Match` / `If-Modified-Since`,没变就 304),文档 ≤ 5 MB、20 秒超时,出站走离线下载的 `fetcher.Guard`。默认每 6 小时一次,最短 1 小时。
- **解析**:RSS 2.0(含 iTunes 播客扩展)、Atom,自己用 `encoding/xml` 写,不加库。GitHub 用 API `GET /repos/{owner}/{repo}/releases`(匿名每小时 60 次,每个仓库 6 小时一次,上百个仓库也够),资源按 `asset_pattern` 过滤,默认不要预发布。
- **第一次**:只处理最新 1 条(可改),更早的标「已跳过」,列表里能手动下载。
- **下载**:新条目建离线下载任务(来源「订阅」),文件名用「日期 标题.扩展名」(播客)或资源原名(GitHub,放进 `tag` 子文件夹)。后台任务排满(每人 10 个)时留到下一轮。下好后播客直接用 v3.4 的播放器连播、续播。
- **剪藏**:建剪藏任务(见五),存进订阅的文件夹。
- **只留最近 N 条**:下载完成后,超出的旧文件移进回收站(来源「订阅」,记进动态)。默认不删。
- **失败**:`fail_count` 加一,检查间隔翻倍(最长 24 小时);连续 3 次失败发提醒(每天最多一次);成功一次就恢复。
- **保留**:每个订阅留最近 300 个条目;每人最多 100 个订阅。

### 3. 通知

| 事件 | 级别 | 默认推送 |
|---|---|---|
| 订阅有新内容下好了(同一订阅合并) | info | 不推 |
| 订阅连续 3 次检查失败 | warn | 推 |

### 4. 入口

- **网页**:侧栏「订阅」(`/feeds`):列表(名字、类型、最后更新、新条目、错误);「添加」:贴地址先预览(标题、最近几条、看出是播客就建议「下载附件」),选文件夹、方式、过滤、保留条数;详情抽屉:条目与状态、单条下载 / 剪藏、立即检查、编辑、退订(已下的文件不动);导入 / 导出 OPML。
- **安卓**:「我的 → 订阅」:列表、条目、贴地址添加、立即检查、单条下载;编辑与 OPML 在网页上。
- **MCP**:不加工具。

## 五、剪藏与 Markdown

### 1. 剪藏任务(C1,同在 00028)

- **任务**:`user_jobs` 加 `clip_url`。剪藏单独一路 runner(同时最多一个),不排在大文件下载后面。
- **步骤**:抓网页(≤ 5 MB,只收 HTML,`fetcher.Guard`)→ 识别编码 → 提取正文(`codeberg.org/readeck/go-readability/v2`:标题、作者、站点、发布时间、摘要)→ 转 Markdown(`github.com/JohannesKaufmann/html-to-markdown/v2`,带表格)→ 下图片(最多 50 张,每张 ≤ 10 MB、合计 ≤ 50 MB,下不了的保留原地址)到 `标题.assets/`,文中改成相对路径(Typora / Obsidian 的约定)→ 写 `标题.md`,开头一段 YAML(标题、原地址、作者、站点、发布与剪藏时间)→ 存到剪藏文件夹(默认 `/剪藏/年-月/`),撞名改名。
- **带内容**:书签栏小工具可以把当前页面的 HTML 一起发来(≤ 5 MB,先存进暂存对象,不进任务参数),这时不再抓取,只用发来的内容和它的地址;解决要登录、靠 JS 渲染、拦服务器 IP 的页面。
- **去重**:同一个地址剪过,默认直接给出已有的那篇(可选「重新剪藏」)。
- **表** `clips`:`id`、`owner_id`、`url`、`title`、`site`、`byline`、`excerpt`、`published_at`、`node_id`(→ nodes ON DELETE CASCADE)、`words`、`images`、`read_at`、`created_at`。
- **搜索**:`.md` 本来就进内容搜索,不用改。

### 2. Markdown 渲染(C2)

- **接口**:`GET /md/{nodeId}?token=<access>&theme=light|dark`(同 `/arc`、`/sub` 的鉴权,分享访客在分享子树内也能看),服务端用 `github.com/yuin/goldmark` 渲染成一页完整的 HTML(GFM 表格、任务列表、删除线、自动链接、脚注;开头的 YAML 显示成一张来源卡片)。≤ 2 MB。
- **安全**:不渲染 Markdown 里的原始 HTML,`javascript:` 等危险链接丢掉;响应带 `CSP: sandbox allow-popups allow-popups-to-escape-sandbox; default-src 'none'; img-src 'self' data: https:; style-src 'unsafe-inline'`、nosniff、`no-store`,脚本无论如何跑不起来;外链新窗口打开。
- **图片**:相对路径(`标题.assets/1.jpg`、`../图/a.png`)改写成 `/md/{nodeId}/f/<相对路径>?token=`,按 md 所在文件夹解析到节点后 302 到对象存储的签名地址(大图给 2048 缩略图);出了自己网盘的范围(或分享子树)就 404。
- **网页**:`.md` / `.markdown` 预览默认渲染(沙箱 iframe),可切回源文件;剪藏页点一篇就是这个阅读视图,加「标记已读」「打开原网页」。
- **安卓**:同一个地址用 WebView 显示(关掉 JavaScript),可切回文本预览。

### 3. 入口

- **网页**:侧栏「剪藏」(`/clips`):顶部贴链接剪藏;列表是卡片(标题、站点、摘要、日期、未读),可筛未读、按站点;书签栏小工具(拖到书签栏,看到哪篇点一下,弹一个小窗显示进度,勾「连同页面内容」走带内容的方式)。剪藏文件夹在「默认设置」里改。
- **安卓**:系统分享菜单多一个「剪藏到 gopan」(分享网址时);「我的 → 剪藏」列表与阅读。
- **MCP**:`clip_url(url, folder?)`(scope `files:write`,支持幂等键),返回任务;Agent 可以之后用读文件的工具读 Markdown。

## 六、资源账

- **闲时**:动态零;订阅每 5 分钟一条查询,只有到期的才出站;空间分析不跑后台任务。
- **镜像**:不加系统包;Go 库 goldmark、go-readability、html-to-markdown 及依赖(cascadia、dateparse、chardet 等),二进制约多 3 MB。
- **内存**:剪藏解析一页 ≤ 5 MB 的 HTML,峰值几十 MB,同时只跑一个;订阅文档 ≤ 5 MB;Markdown 渲染 ≤ 2 MB。
- **CPU**:全是一次性的解析与转换;空间分析是按需查询。
- **磁盘**:动态每行约 300 字节,单人日常每天几百行,90 天远低于 50 MB;订阅与剪藏下的东西占你的配额(「只留最近 N 条」与空间 90% 提醒兜住)。
- **网络**:订阅每个每 6 小时一次条件请求;剪藏只在你点的时候。

## 七、里程碑

## 八、风险与对策

- **撤回把东西弄乱**:撤回本身只是移动 / 改名 / 还原 / 进回收站,不会真删东西;批量先预览;每条各自成败,撤不了的说明原因。
- **记录拖慢写操作**:同事务一条多值 INSERT,单次几十微秒;复制整个文件夹按顶层一行,不逐个展开。
- **来源漏记**:所有写路径在服务层记录而不是在各入口记;测试覆盖每个入口的来源。
- **排序规则**:ICU 不可用时回退字节序,迁移照样成功;改了索引的表达式,写进测试确认翻页不重不漏。
- **剪藏被拦、正文提取不准**:很多站点拦服务器 IP 或要登录,书签栏「连同页面内容」兜底;提取失败时保存整页文字而不是报错。
- **订阅撑满空间**:下载前查配额(离线下载已有),「只留最近 N 条」,空间 90% 提醒(已有)。
- **同域渲染用户内容**:`/md/` 不渲染原始 HTML,CSP sandbox 禁脚本,与 `/x/` 的 SVG 同一做法。
- **出站面变大**:订阅、剪藏和图片下载都走同一个 `fetcher.Guard`,内网拦截写进测试。
- **schema 变化**:两个迁移只加表、加索引、放宽 `user_jobs.kind` 的约束;回滚旧二进制不受影响(旧代码不读新表;按名字排序回到旧索引需要的只是旧查询,新索引多一个无害)。

## 九、决策(按建议执行,有不同意见随时改)

1. 能撤回的是移动、改名、删除、新建类操作;覆盖和彻底删除撤不回(不做版本,沿用 2026-10-20 的决定)。
2. 动态保留 90 天,子树不逐个展开(一次删一个大文件夹是一行,带文件数与大小)。
3. 大量删除提醒只针对 WebDAV、Agent、图床密钥这类无人值守的来源,阈值 10 分钟 200 个文件或 2 GiB。
4. Agent 只给 `list_activity`,不给撤回工具(撤回由人来点)。
5. 文件列表按名字排序改成自然顺序,中文按拼音(和 Windows 资源管理器一致);WebDAV、搜索不变。
6. 订阅默认 6 小时检查一次,第一次只下最新 1 条,默认不删旧的。
7. 不做 YouTube / B 站(yt-dlp 太重)。
8. 剪藏存成 Markdown + 同名 `.assets` 图片文件夹,不存整页快照。
9. Markdown 在服务端渲染,网页沙箱 iframe、安卓 WebView 共用一套,不在前端加 Markdown 库。
10. 书签栏小工具可以把当前页面内容一起发过来(只在你点的时候发生,用来存要登录的页面)。

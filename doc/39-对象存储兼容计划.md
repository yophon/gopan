# 39 · 对象存储兼容计划

> 结论先行：gopan 的对象存储本来就只说 S3 协议（`internal/objstore` 一层，minio-go 当通用 S3 客户端用），换存储主要是**验证和配置**，不是重写。这里把「只验过 MinIO」变成「有一张兼容表」：收拢 objstore 的边界，补两个配置项、修一处推断，测试能指向任意 S3，加一个存储自检；CI 在 MinIO 之外再跑一种自建实现，R2 走真机与定时验收。部署分「同源反代」和「跨源直连」两种模式写清楚。数据库不在本计划内，继续只支持 Postgres（见七）。

## 一、为什么做

- **MinIO 的分发收紧了**：`ci.yml` 的注释写着 2025 年起 `docker.io/minio/minio`、`quay.io/minio/minio` 都不能匿名拉取，CI 已改用 `bitnamilegacy/minio`；但两份 compose 还是 `minio/minio`（gopan#2）。长期只靠 MinIO 有风险。
- **容量**：文件放在 VPS 本地，2 核 2G 的机器磁盘通常也小，扩容就得换机器。
- **流量**：下载、播放是最大的流量；R2 这类出流量免费的存储能把这部分成本拿掉。
- **部署**：doc/09 最容易出错的是 `/gopan/*` 的反代约定（透传 Host、请求体上限、CSP 与 nosniff 头）。跨源直连时这一节整个不需要。

doc/02 早就写了「代码只依赖 S3 协议，可换任何兼容存储」，但从没验证过。这份计划就是把这句话做实。

## 二、部署的人看到的

- `.env` 里的 `GOPAN_S3_*` 指向任意 S3 兼容存储即可；新增两项（见四.2）。
- `gopan storage check` 一条命令告诉你这个存储能不能用、哪些功能要关（见四.4）；服务启动时也跑一遍，结果进日志和管理端概览。
- doc/09 新增「存储」一节：两种模式怎么选、MinIO / SeaweedFS 或 Garage / R2 / AWS S3 的配置样例、存储桶 CORS 样例、每种存储验证到哪个版本、从 MinIO 迁出的步骤。
- compose：MinIO 照旧是默认；用外部存储时叠一份 `docker-compose.external-s3.yml`（去掉 minio 服务与 gopan 对它的 `depends_on`）。不把 minio 改成 profile：老部署的 `.env` 里没有这个 profile，升级后 MinIO 会悄悄不启动。

## 三、两种模式

| | 同源反代（现状，MinIO 默认） | 跨源直连（R2、AWS S3、另一台机器上的自建存储） |
|---|---|---|
| 预签名地址 | `https://站点/gopan/…` | `https://存储域名/…` |
| 反代 | `/gopan/*` 转存储：透传 Host、请求体上限、加 CSP 与 nosniff | 不需要 |
| 存储桶 CORS | 不需要 | 需要：只允许站点 origin 的 `GET`、`PUT`、`HEAD` |
| 上传的 html / svg | 与站点同源，靠两层挡：`InlineOverrides` 改写响应类型 + 反代 CSP | 在存储域名下，碰不到站点的 cookie；`InlineOverrides` 照旧 |
| 站点 CSP | 不用改 | 不用改：`img-src` / `media-src` / `connect-src` 已放行 `http: https:`（`httpx/server.go:213`） |
| Service Worker | 不碰 `/gopan/*` | 不碰跨源请求（`web/public/sw.js:98`） |
| 前端 | 不用改 | 不用改：分片 PUT 不读 ETag（`uploader/parts.ts:113`），文本预览、版本对比的 `fetch` 有 CORS 即可 |
| 国内访问 | 与站点一致 | 取决于存储域名；R2 的 S3 端点在国内可能不稳，要实测 |

**模式由配置推出，不新增开关**：`S3_PUBLIC_ENDPOINT` 的主机与 `PUBLIC_URL` 的主机相同即同源，否则跨源。

## 四、要改的

### 1. 收拢 objstore 的边界

- 加 `objstore.IsNotFound(err)`、`objstore.IsNoSuchUpload(err)`；`service/browser_upload.go:99`、`:399` 改用它们。之后 service 层不再 import minio-go。
- **不抽 interface**：所有 S3 兼容存储共用一个实现，差异用配置表达。真要做本地磁盘后端时再从现有方法提炼接口（见八）。
- 数据库列 `minio_upload_id` 不改名：改名要迁移，收益只是好看。

### 2. 配置

- `GOPAN_S3_BUCKET_LOOKUP` = `auto`（默认）| `path` | `dns`，传给两个 client 的 `minio.Options.BucketLookup`。现在依赖 minio-go 的自动判断（自定义域名走 path-style），有的存储要强制指定。
- `GOPAN_S3_CREATE_BUCKET` = `true`（默认，保持现状）| `false`。托管存储的 key 常常没有建桶权限；`false` 时 `EnsureBucket` 只检查存在，不存在就报错说明。
- `GOPAN_S3_REGION` 已有。R2 一般写 `auto`，以实测为准。
- **修正 `PUBLIC_URL` 的推断**（`config.go:178`）：现在 `PUBLIC_URL` 留空、且内外地址不同时，会把 S3 外部地址当作站点地址。这在同源模式下成立；跨源模式下要么推断错（直链、推送里的链接指向存储域名），要么内外地址相同、推断不出（直链只给站内路径、推送不带链接）。改成：跨源模式必须显式配置 `PUBLIC_URL`，没配就启动报错。

### 3. 健康检查

`Ping` 现在用 `BucketExists`（HeadBucket）。只授权到对象级别的 token 可能没有这个权限。失败时退回 `ListObjects(maxKeys=1)`；两者都失败才算不健康。是否需要以实测为准。

### 4. 存储自检（新）

`gopan storage check`（仿照 `cmd/gopan/main.go:52` 的 `admin` 子命令）与启动时各跑一遍，在临时 key 下逐项验证，跑完清理：

1. 建分片 → 预签名 PUT 一片 → `ListParts` 能看到 → `Complete` → `Stat` 大小对得上
2. 签了 Content-Length 的预签名 PUT，发错长度应被拒
3. 预签名 GET 带 `response-content-type` / `response-content-disposition`，响应头确实被改写
4. `Copy`；Range GET；未知长度的流式 PUT
5. 同源模式：经站点地址请求 `/gopan/` 下的对象，检查 CSP 与 nosniff 头（doc/09 现在让人手动 `curl -sI`）
6. 跨源模式：带站点 `Origin` 发预检，检查 CORS 放行

结果的处理见六。管理端概览显示存储主机、模式和每项结果。

### 5. 测试

- 6 个集成测试文件里写死了 `gopan-minio-dev` 等凭据。新增 `TEST_S3_KEY` / `TEST_S3_SECRET` / `TEST_S3_BUCKET` / `TEST_S3_REGION` / `TEST_S3_BUCKET_LOOKUP`，缺省值保持现状；测试里构造存储的代码收拢到一个共享 helper。
- 自检本身也是测试：CI 里对每种存储都跑一遍 `gopan storage check`。

### 6. CI

- `server` job 改成按存储跑矩阵：`minio`（现状）+ SeaweedFS 或 Garage（先跑通哪个用哪个）。
- R2 单独一个 workflow：`workflow_dispatch` + 每天定时，凭据放 secrets，不阻塞 PR。

### 7. 部署与文档

- compose 的 MinIO 镜像换成能拉到的，并固定版本，不用 `latest`（gopan#2）。
- 新增 `docker-compose.external-s3.yml`。
- doc/09 加「存储」一节；Caddyfile 与 `deploy/nginx` 模板注明「跨源模式不需要 `/gopan/`」。
- doc/02 的「可换任何兼容存储」改为指向本文的兼容表。

## 六、安全

- **响应头改写不生效**：同源模式下等于重新打开 doc/20 二.6 的同源脚本问题，**自检失败就拒绝启动**；跨源模式下只告警（对象在别的域名下，碰不到站点）。
- **签名的 Content-Length 不被强制**：匿名访客能往收集链接里塞超大分片。这种存储上**自动关闭收集链接**，管理端说明原因；服务端完成时按 `Stat` 的实际大小核对的逻辑照旧。
- **CORS** 只放行站点的 origin，不写 `*`。预签名地址本身就是凭证，`*` 不会直接出事，但没必要放宽。
- **存储凭据最小化**：只授权到这一个桶；`GOPAN_S3_CREATE_BUCKET=false` 时不需要建桶权限。

## 七、数据库：这次不做

不做「可换数据库」。gopan 大量用到 Postgres 的特有能力：

| 能力 | 用在哪 |
|---|---|
| `WITH RECURSIVE`（14 条查询） | 目录树、子树统计 |
| `FOR UPDATE SKIP LOCKED` | 后台任务队列 |
| `pg_advisory_xact_lock`（4 处） | MCP 写入、传输助手的串行化 |
| 事务内 `pg_notify` + `LISTEN` | 自动刷新（doc/32） |
| `pg_trgm` + GIN | 按名字搜索 |
| `text[]` + GIN + `@>` | 内容搜索（doc/20） |
| ICU 排序规则 `natural_sort`（15 处） | 自然顺序、中文按拼音 |

370 条 sqlc 查询全部基于 pgx v5。换成 SQLite 或 MySQL 等于重写数据层，之后每个功能都要在两种数据库上测，而部署的痛点并不在 Postgres。

**这次顺带做的**：把「支持托管 Postgres」写进 doc/09，并在启动时检测两件事：

- **`LISTEN` 收不到通知**（经过事务级连接池，比如 Supabase 的 pooler、Neon 的 pooled 地址）：启动时自己 `pg_notify` 一条、等 2 秒，收不到就告警「自动刷新不可用，请改用直连地址」。不检测的话，这个问题不报错，只表现为列表不刷新。
- **ICU 不可用、`natural_sort` 退回了 `C`**（迁移 00027 的兜底）：查 `pg_collation` 看 provider，退回时告警「自然顺序与拼音排序不可用」。

要求写明：`pg_trgm` 扩展；已验证 Postgres 16、17。

## 八、不做的

- **本地磁盘后端**：能把 MinIO 也省掉，但字节要经过 Go，等于推翻「主传输路径字节流不过 Go」，还要自己模拟预签名地址。有人要时再做，到时候再从 objstore 抽接口。
- **可换数据库**：见七。
- **多存储并存、按冷热分层**。
- **迁移工具**：key 是内容寻址的（`blobs/`、`derived/`），数据库只存 key 和 sha256，迁移就是「rclone 同步桶 → 改配置 → 重启」，写成 doc/09 里的步骤。注意两点：迁移前停服或等进行中的分片上传结束（未完成的分片不跟着走）；staging key 不用迁。

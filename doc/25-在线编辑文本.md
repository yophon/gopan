# 25 · 在线编辑文本与 App 替换上传

> 状态:**已交付**(v3.11.0,2026-10-24)。接口见 doc/05「在线编辑文本」,用法见 doc/11「在线编辑」「上传」「安卓 App」。

## 一、为什么做

- 网盘里的 `.md`、`.txt`、配置文件改一个字也得下载、改完再传回来,传回来还要选「替换」。剪藏、会议纪要这类本来就在网盘里写的东西尤其别扭。
- 3.10 有了历史版本,改坏了能找回来,在线编辑的风险小了很多。
- 3.10 的替换上传只做了网页,App 传同名文件照旧多出一个 `xxx (1)`。

## 二、做法与取舍

### 在线编辑

- **整份读、整份存**,不做协同编辑与增量保存。上限 2 MB(`service.MaxTextEdit`),再大的文本在浏览器输入框里也卡,请下载后改。App 上限 512 KB:Compose 的输入框内容更长就明显卡顿,超过的提示到网页上改。
- 只编辑 **UTF-8 文本**:读的时候不是合法 UTF-8 或含 NUL 字节就报 `NOT_TEXT`。客户端只在预览类型是文本(包括 Markdown)时给「编辑」入口。GBK 的老文件能预览、不能编辑,免得存回去变成乱码。
- **保存 = 覆盖**,走和替换上传、WebDAV 一样的 `overwriteFileTx`:还是同一个节点(分享、收藏、直链不变),旧内容进历史版本,动态记一条 `OVERWRITE`(`note` 是「在线编辑」),所以也能撤回。内容没变的保存什么都不做。
- **冲突**:打开时记下内容的 sha256,保存时带上(`baseSha256`)。对不上说明打开后在别处改过(另一个标签页、WebDAV 同步、App),报 `EDIT_CONFLICT`,客户端问「仍然保存」。仍然保存就不带 `baseSha256` 再存一次,被盖掉的那次改动留在历史版本里。事务里锁住节点后再比一次,读与锁之间被改的也算冲突。
- **新建文本文件**:`createTextFile` 在当前文件夹建一个(默认 `未命名.md`,同名自动改名),建好直接进编辑。动态记成上传。
- 离开保护:有没保存的修改时退出编辑、关预览、翻到别的文件、关标签页都会先问;正在保存时按退出会先等它存完,存成功就直接走、不再问。
- **Markdown 边写边看**(3.16.0,网页):编辑 `.md` 时右边是预览,停手 0.4 秒刷新。预览由服务端按和普通预览同一套规则渲染(`POST /md/{node}/preview`,请求体是编辑框里还没保存的文字,相对路径照样按这篇所在的文件夹解析,只给登录用户),放进 `srcdoc` 的沙箱 iframe:不许跑脚本;给 `allow-same-origin` 只是为了让预览跟着编辑框滚动。手机上「看预览」「回到编辑」切换。

### App 替换上传

- 上传队列在本地 Room 库里,任务加一列 `replaceExisting`,数据库升到 v3,带迁移 `MIGRATION_2_3`(旧任务默认 false,照旧自动改名)。
- 选完文件,和当前文件夹里的**文件**比名字(同名的是文件夹照旧改名),有同名的就问一次「替换 / 保留两者」;替换的那几个在 `initUpload` 时带 `replace = true`,其余照常。行为和网页一致。
- 只在文件页「+」的「上传文件」「上传照片和视频」时问;拍照上传和传输助手里发文件不问。

## 三、改动范围

- 服务端:`service/textedit.go`(`ReadTextFile` / `SaveTextFile` / `CreateTextFile`);schema 加 `TextFile`、`textFile`、`saveTextFile`、`createTextFile`。
- 网页:`components/preview/TextEditor.vue`(等宽编辑框、Ctrl+S、Tab 缩进、状态与冲突处理);预览里的「编辑」按钮,编辑时禁用左右翻页与滑动;文件页「新建文件夹」下拉、空白处右键、手机「新建」里的「新建文本文件」;`ElConfigProvider` 的 z-index 基数调到 3000,让确认框压在预览层上面。
- 安卓:`feature/textedit`(编辑页与 ViewModel)、`core/data/text`;预览顶栏的编辑按钮,回到预览时重新加载;文件页「+」里的「新建文本文件」;上传的「有同名文件」对话框;Room v3。

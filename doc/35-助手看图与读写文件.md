# 35 · 助手看图与读写文件

> doc/33 的助手只能读文字:网盘里的图片它看不到,对话里也发不了图;它能读文档,却不能新建一份笔记、改一段 Markdown;找到的文件只能报个名字,用的人还得自己去翻。这里补四件事:看图、对话里发图、写文本文件、回答里引用文件。读写文件不另起炉灶,直接用 tau 内核自带的 `read` / `write` / `edit`(Claude Code 那一套),底下接 gopan 的网盘。

## 一、用的人看到的

- **看图**:「这张截图里报的什么错」「这几张发票哪张是餐饮」——助手自己打开图片看。视频、PDF、Office 文件也能看封面。
- **对话里发图**:网页面板里粘贴、拖进来或点附件按钮;App 里从相册选。一条消息最多 4 张,和文字一起发出去;对话记录里显示缩略图。
- **写文件**:「把会议要点记成一份 Markdown 放到『笔记』」「把 README 里的版本号改成 3.2」——助手新建文本文件,或者改其中一段。改动是「修改文件」这一类权限,默认先问你;确认卡上写文件名和改了几处。
- **读文件**:文本、PDF、Office、图片、视频都用 `read` 这一个工具:文字给文字,图片给图,视频给封面;扫描件 PDF 抽不出文字时给第一页的图。
- **引用文件**:助手回答里提到的文件、文件夹是能点的:点文件夹直接跳过去,点文件打开预览。找到的图片、视频直接显示在回答里(图片缩略图,视频封面点了就播)。
- **规则不变**:权限三态、目录范围、动态来源「助手」、整批撤回,对新工具同样生效。
- **模型**:要能看图的模型(站点提供的 DeepSeek `deepseek-flash` 能看)。看不了图的模型,图片换成一句「这个模型看不了图」,其余照常。

## 二、整体结构

```
模型看到的工具
  read / write / edit               ← tau 内核自带(Claude Code 那一套)
     │  FileSystem 接口
     ▼
  GopanFs(web/src/assistant/gopan-fs.ts,三种宿主共用)
     │  经同一条 /mcp 连接调底层工具(带 X-Gopan-Assistant / X-Gopan-Turn)
     ▼
  gopan MCP:resolve_path、list_files、read_text_file、read_document_text、
            view_image(新)、write_text_file(新)
     │  权限、目录范围、动态来源、整批撤回都在这一层
     ▼
  Nodes / Uploads(在线编辑那套 TextFile / SaveTextFile / CreateTextFile)
```

- **为什么经 MCP 而不是 GraphQL**:助手的权限三态、目录范围、动态里记「助手」、按一轮回答合成一批撤回,都在 MCP 这一层做(doc/33 三)。`GopanFs` 走 GraphQL 就全绕过去了。
- **为什么用 tau 的工具而不是只加 MCP 工具**:`read` 的分页与行号、`edit` 的「原文必须唯一匹配、全部成功才写」、图片按扩展名走附件、看不了图的模型自动换成说明,这些 tau 都做好了也测过;照搬 Claude Code 的工具形状,模型最熟。底层 MCP 工具照样加,外部 MCP 客户端(Claude Desktop 等)也能用。
- **三种宿主都有**:网页、App(QuickJS)、服务器(qjs)跑的是同一份 `runtime.ts`,`GopanFs` 只用 fetch,不碰浏览器 API。

## 三、模型看到的工具

改完以后,助手手里的工具是这些(权限一栏是「MCP 访问 → 助手」里的那几组):

| 工具 | 来自 | 做什么 | 权限 |
|---|---|---|---|
| `read` | tau,gopan 包一层 | 文本按行读(分页、行号);PDF / Office 读抽出的文字(扫描件给第一页的图);任何格式的图片(含 HEIC、RAW)作为图片附件;视频给封面 | 查看文件 |
| `write` | tau | 新建或整份覆盖一个文本文件 | 修改文件 |
| `edit` | tau | 按原文替换一处或几处;原文必须唯一匹配,全部成功才写 | 修改文件 |
| `list_files` `resolve_path` `get_file_info` `search_files` `search_file_contents` `list_archive` `list_trash` `storage_status` `get_job` `list_jobs` | gopan | 列目录、按路径找、看详情、搜文件名与内容、看压缩包、看回收站、看空间、看后台任务 | 查看文件 |
| `create_folder` `create_directories` `rename_node` `move_nodes` `copy_nodes` | gopan | 建目录、改名、移动、复制 | 修改文件 |
| `trash_nodes` `restore_nodes` | gopan | 放进回收站、从回收站恢复 | 删除文件 |
| `batch_nodes` | gopan | 一次做多种改动 | 修改文件 + 删除文件 |
| `extract_archive` `fetch_url` `clip_url` | gopan | 解压、下载网址到网盘、剪藏 | 存入文件(外发) |
| `list_shares` `list_links` `list_file_requests` | gopan | 看分享、直链、收集 | 查看分享 |
| `create_share` `revoke_share` `create_link` `revoke_link` `create_file_request` `revoke_file_request` | gopan | 建、撤分享 / 直链 / 收集 | 管理分享(外发) |
| `chat_list` / `chat_send` | gopan | 读 / 发传输助手 | 读传输助手 / 发传输助手 |
| `list_activity` `list_audit` | gopan | 看动态 | 查看动态 |

看不到的:

- 底层的 `read_text_file`、`read_document_text`、`view_image`、`write_text_file`:`read` / `write` / `edit` 底下就是它们,两套都给模型会挑错;外部 MCP 客户端照样能看到。
- 上传、下载那几个(`prepare_upload`、`prepare_download` 等):和现在一样,助手手里没有本地文件,下载地址给它只可能被拿去外发。
- tau 的 `ls`:只给名字,没有 id;移动、改名、分享都要 id,列目录用 `list_files`。
- tau 的 `grep` / `find`:要把目录树整个走一遍、每个文件读一次,网盘上太慢;`search_files`、`search_file_contents` 是服务端索引。
- tau 的 `bash` / `powershell` / `apply_patch`:没有 shell;改文件有 `edit` 就够了。

路径:`read` / `write` / `edit` 用网盘里的绝对路径 `/笔记/会议.md`(系统提示里写明);相对路径从根目录算。三个工具成功的结果末尾附一行 `[gopan id: …]`,模型在回答里引用这个文件用得上(六)。

## 四、GopanFs(tau 的 FileSystem 接口)

- `stat(path)` / `listDir(path)`:`resolve_path`、`list_files`(tau 的工具内部要用,模型不直接用)。
- `readTextFile(path)`:按文件类型分流——
  - 文本:`read_text_file` 连读到底(上限 2 MB,和在线编辑一样),记下内容的 sha256(下面写回时用)。
  - PDF / Office:`read_document_text` 连读到底(上限 2 MB 文字)。
  - 别的(压缩包、可执行文件……):报错「这是 <类型>,读不了」。图片和视频到不了这里(见下面「read 包一层」)。
- `readBinaryFile(path)`:只有 `read` 读图片时用,调 `view_image` 取回 JPEG 字节。
- `writeTextFile(path, content)`:`write_text_file`。读过这个文件的,带上读时的 sha256,中途别处改过就报冲突(「这个文件在你读之后被改过,重新 read 一遍再改」);没读过的新建;已存在又没读过的,和 Claude Code 一样拒绝(「先 read 再改」)。
- `appendFile` / `remove`:tau 这几个工具用不到,直接报不支持(删除走 gopan 的回收站工具)。

### read 包一层

tau 的 `read` 按扩展名分流:只有 `png/jpg/gif/webp/bmp` 当图片,别的都当文本读。HEIC、RAW、视频封面、扫描件它处理不了,所以 gopan 给它包一层(`web/src/assistant/gopan-read.ts`),模型看到的还是同一个 `read`(参数不变,说明里加一句「任何格式的图片和视频都能读」):

1. 先 `resolve_path` 拿到网盘里的类型。
2. 图片(任何格式)、视频 → `view_image`,返回「Read image file [image/jpeg]」+ 图片(视频加一句「视频封面」)。
3. PDF / Office 抽出的文字是空的(扫描件)→ `view_image` 给封面,加一句「扫描件,抽不出文字,这是第一页」。
4. 其余交给 tau 原来的 `read`(文本分页、行号、`allow_large`)。
5. 模型看不了图时,图片换成 tau 的那句说明(`NON_VISION_IMAGE_NOTE`),和 tau 自己的行为一致。

以后要是把「按文件类型认图片」做进 tau 的 FileSystem 接口(比如 `stat` 带上 MIME),这一层就能拿掉。

## 五、服务端

### view_image(新 MCP 工具)

- 入参 `node_id` 或 `path`。
- 图片:已有的派生图 `thumb2048`(JPEG)缩到长边 1568、质量 80 再给(模型那边再大也是缩了看,存进对话记录也小);派生图还没生成的,原图是 JPEG / PNG / GIF / WebP 且不超过 20 MB 就当场缩;都不行报「这张图还在处理,稍后再看」。
- 视频、PDF、Office:用封面派生图 `cover`,同样缩;没有封面就报错。
- 返回 MCP 的 `ImageContent`(`image/jpeg`,base64)加一行文字(文件名、原始尺寸)。
- scope `files:download`(和 `read_text_file` 一样),受目录范围限制。

### write_text_file(新 MCP 工具)

- 入参 `path`(或 `parent_id` + `name`)、`content`、可选 `base_sha256`。
- 不存在就建(`CreateTextFile`,父目录要已存在);存在就存(`SaveTextFile`,带 `base_sha256` 时做冲突检测,不带时只允许原来是空文件)。
- UTF-8、不超过 2 MB;名字规则与重名处理和在线编辑一样。
- scope `files:write`,动态记「助手」,进这一轮的那一批,可以整批撤回(存的是新版本,旧版本在「版本历史」里)。
- `read_text_file` 的结果加 `sha256`(读到文件末尾时给,整份内容的),给写回时对版本用。

### 对话记录

- 图片(工具读回来的、用户发的)跟着消息存进 `ai_entries`,base64。每条记录上限 1 MB 不变,所以:
  - `view_image` 给的图长边 1568、质量 80,一般 150–300 KB;
  - 用户发的图在客户端先缩到长边 1568、JPEG 质量 80,一条消息合计超过 700 KB 就再降质量,还超就不让发。

## 六、回答里引用文件

- **助手怎么写**:系统提示要求它提到网盘里的文件、文件夹时写成 Markdown 链接 `[名字](gopan:<id>)`,id 来自工具结果(gopan 工具的结果里有 id,`read` / `write` / `edit` 的结果末尾附 `[gopan id: …]`);手里没有 id 时写 `[名字](gopan:/完整路径)`。想让人直接看到的图片、视频,链接单独占一行。
- **怎么显示**:
  - 句子里的链接 → 一个小标签(图标 + 名字)。点文件夹跳到那个文件夹;点文件打开预览(和文件列表里点开一样)。面板不关。
  - 单独成段的一个或几个链接 → 卡片:图片显示缩略图,点开大图;视频显示封面加播放键,点了用现有的播放器放;别的文件显示图标、名字、大小、所在文件夹。
  - 显示时按 id 现查(用这个人自己的登录凭证),所以名字、位置总是最新的;查不到(删了、没权限)就显示成普通文字「名字(已不在)」。模型编的 id 也只会落到这一种。
- **只认 `gopan:`**:别的协议照旧当普通外链(或不渲染)。
- **对话记录里存的就是这段文字**,换设备、隔几天打开都能点。
- **GraphQL**:加 `nodesByIds(ids: [ID!]!): [Node!]!` 与 `nodesByPaths(paths: [String!]!): [Node!]!`(查不到的不报错、直接不返回),一段回答里的引用一次查完。缩略图地址是预签名的,客户端 10 分钟后再用到会重新查。
- **App**:Compose 里同样两种样子;点文件夹进那个文件夹,点文件走现有的预览 / 播放页。

## 七、客户端

- **网页**:输入框加附件按钮;支持粘贴、拖放。发之前在浏览器里用 canvas 缩图。消息气泡里显示缩略图。
- **App**:输入框加「图片」按钮,系统相册选图(Photo Picker,不要存储权限);用 `ImageDecoder` / `Bitmap` 缩图。
- **服务器上跑**:`startAiRun` 加 `images: [String!]`(data URL,服务端只认 JPEG / PNG / WebP / GIF,最多 4 张、合计 1 MB),原样交给运行时。推给各个设备的事件里用户的图只给张数(每次推的都是整份对话);设备上已有的图(刚发的、打开对话时从记录读的)接着显示。
- **确认卡**:`write` 写「新建 / 覆盖 <文件名>」,`edit` 写「改 <文件名>(N 处)」,详情里给改前改后的几行。
- **工具那一行的人话**:`read` →「读了 a.md」/「看了 photo.jpg」,`edit` →「改了 a.md」,`ls` →「看了『笔记』里有什么」。

## 八、不做的

- tau 的 `grep` / `find` / `bash`:见三。
- 写二进制文件(让助手生成图片、表格文件):以后有需要再说。
- 视频里任意时间点截图、PDF 任意一页转成图:先只有封面;扫描件 PDF 要看第 N 页,以后再加。
- 本机文件(doc/33 里说的「以后 App 与桌面端读本机文件」):这次不做,但 `GopanFs` 同一个接口,以后换一个本机实现就能接上。

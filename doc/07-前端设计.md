# 07 · 前端设计

## 路由与页面

```
/login                    登录/注册
/drive/:folderId?         主界面(文件列表,无 folderId = 根目录)
/trash                    回收站
/shares                   我的分享管理
/admin                    管理端(管理员)
/s/:token                 访客分享页(独立布局,无侧边栏)
/oauth/consent            OAuth 授权确认(独立布局,登录后回跳)
```

主界面一个页面承载全部核心交互:面包屑、多选、拖拽上传、新建文件夹。右键菜单只有两项(下载/打包下载、分享),重命名/移动/复制走工具栏按钮;手机上长按菜单才是完整操作集。列表/网格切换 **只在手机上有**(桌面固定表格)。预览是全局模态(`PreviewModal`),不占路由——从列表、搜索、访客页都能唤起。

## 组件结构

```
AppShell(侧边栏 + 顶栏 + 上传队列抽屉)
├─ DriveView
│  ├─ Breadcrumb
│  ├─ NodeTable(桌面 el-table)/ NodeCardList(手机卡片,list 或 grid)
│  │  ├─ NodeIcon(缩略图,失败回落图标)/ NodeActionSheet(长按菜单)
│  ├─ ContextMenu(桌面右键)/ MoveDialog(目录树选择器)/ ShareDialog
│  └─ UploadDropzone(整页拖拽层)
├─ PreviewModal
│  ├─ ImageViewer(v-viewer)  PdfViewer(pdfjs-dist)
│  ├─ MediaPlayer(video/audio)  TextViewer
│  └─ OfficePending(转换中轮询态)
├─ TrashView / SharesView
├─ MCPAccessDialog(API Key + OAuth grant 管理)
├─ AppPasswordsDialog(WebDAV 应用密码)

```

`OAuthConsentView` 不放进 `AppShell`:MCP Host 打开浏览器后只需要看到请求应用、权限列表和允许/拒绝,不应暴露云盘操作界面。路由守卫仍要求正常用户登录;未登录时带完整 query 跳 `/login`,成功后原路返回。

## Pinia store 划分

| store | 职责 |
|---|---|
| auth | user、accessToken(内存)、login/refresh/logout;单飞刷新锁 |
| uploads | 全局上传队列:任务列表、状态机、并发调度;跨路由存活 |
| ui | 手机视图偏好(list/grid,localStorage 持久化)与触屏多选态 |

> 注:规划里的 `selection` store、虚拟滚动 NodeList、`useMagicKeys` 快捷键**都没有实现**——多选是视图内的 `ref`,列表按 200/页分页。别照这份文档的旧描述去找它们。

服务端数据(目录、分享、回收站)**不进 Pinia**,全归 vue-query 管——store 只放客户端状态,这条边界不破。

## 数据层

- codegen 产出 typed document + hooks;查询 key 约定:`['children', parentId, order]`、`['node', id]`、`['trash']`、`['shares']`。
- mutation 后精准失效:改名/移动/删除 → 失效旧父与新父的 `children`;上传完成 → 失效目标目录。不做乐观更新(v1 不值得,失效重拉 200ms 内)。
- 上传队列的进度不进 vue-query(高频本地态),完成事件才触发失效。
- Agent 凭据查询 key 为 `['mcpAPIKeys']` / `['oauthGrants']`;创建或吊销后只失效对应 key。API Key 明文只放组件局部内存,对话框关闭即清空。

## 上传器(唯一自研重点)

任务状态机:

```
queued → hashing → initiating → uploading → completing → done
                     │(instant)────────────────────────↗
   任一态 → paused(用户)/ failed(重试 3 次后)/ canceled
```

- **hashing**:hash-wasm 在 Web Worker 流式算 SHA-256(File.stream() 分块喂),不卡 UI;>4GB 文件照样恒定内存。
- **uploading**:全局并发 = 同时 2 个文件 × 每文件 3 片(避免几十个 PUT 抢带宽);fetch + AbortController,每片失败独立指数退避重试。
- **进度**:片粒度累计;fetch 上传无进度事件,用 XMLHttpRequest 发分片拿 `upload.onprogress`(这是全项目唯一一处 XHR,封装在 uploader 内部)。
- **断点**:sessionId + 文件指纹(name+size+lastModified)记 localStorage;页面重开时列出可恢复任务,恢复时经 `uploadSession(id)` 拿 `uploadedParts` 续传。
- **folder 上传**:webkitdirectory 取相对路径,先批量建目录树再入队文件。
- **nodeId 回填**:秒传路径取 `initUpload.node.id`,分片路径取 `completeUpload.id`,写进 `UploadTask.nodeId`。`finishDone` 先调 `uploadDoneListener(task)` 再清空该字段,防止重复消费。

## 传输助手页(ChatView,v2.5 重写)

`/chat` 路由与侧栏项在 AppShell 里原样保留;文件夹在数据库里仍叫「我的设备」,界面文案一律「传输助手」。页面围绕 vue-query 组织,纯逻辑全部抽到 `src/utils/chat.ts`(Vitest 覆盖):

- **消息列表**:`useQuery({ queryKey: ['chatMessages'] })` 每次全量拉最近 200 条,与本地列表经 `mergeChatMessages` 合并;`refetchInterval` 页面可见时 2s、不可见时停,回到前台与窗口聚焦立即 refetch。轮询连续失败两次显示「离线,重连中」,恢复后回到「已连接」。
- **翻历史**:滚到顶部 40px 内用 `before: 最旧 id` 取 100 条,插入后按 `scrollHeight` 差值把视口钉回原位;一页不足 100 条即到头。
- **乐观上屏**:发送先插本地 `PendingMsg`(`pending-` 前缀 id,sending / failed 两态),成功后换成服务端消息,失败标红可重试/移除。发送中不禁用输入框,只靠 `isPending` 防重复提交。
- **输入**:`textarea` autosize 1~6 行;桌面 Enter 发、Shift+Enter 换行,输入法组合中的 Enter 不发;手机 Enter 只换行、按钮发。超过 4000 字节的文本自动存成 `文本 YYYY-MM-DD HH-mm.txt` 上传,不报错丢掉。
- **气泡**:`white-space: pre-wrap`;`linkify` 先整体 HTML 转义再把 `http(s)://` 包成 `<a rel="noopener noreferrer">`,`v-html` 渲染;超过 8 行折叠;悬停出复制/删除,手机长按、桌面右键出操作面板(复制 / 下载 / 删除)。删除经 `ElMessageBox` 确认,成功后本地移除并加入 tombstone 集合,防止先于删除落地的轮询把它合并回来。
- **文件**:点回形针 / 粘贴(`clipboardData.files`,截图命名 `截图 YYYY-MM-DD HH-mm.png`)/ 拖进页面(页面级 dragenter/leave 计数,整页「松开发送」遮罩)都走 `sendFiles`:先 `ensureChatFolder` 拿文件夹 id,再 `enqueueFiles`,并把全局上传抽屉收起。进行中的任务从 `useUploadsStore` 按 `parentId === chatFolderId` 筛出来,在列表底部渲染进度卡片(取消 / 重试 / 移除);完成后服务端已自动落消息,`uploadDoneListener` 只负责 `invalidateQueries`。
- **渲染**:按天分组,分隔线 今天 / 昨天 / M月D日 / 跨年 YYYY-MM-DD;图片、视频卡片直接显示缩略图(最高 240px,保持比例),其他文件小卡片。点击经 `openPreview` 唤起全局 PreviewModal,预览列表是当前列表全部文件节点。
- **滚动**:首屏、自己发送后、新消息到达且距底 80px 内自动滚底;用户在上方翻历史时改为浮出「N 条新消息」按钮。
- **搜索**:header 搜索框 300ms 防抖后以 `query` 参数查询,结果就地替换列表;清空回到正常列表。
- **系统分享**:manifest `share_target`(GET,`/chat?title&text&url`),页面挂载时把它们拼进草稿并 `router.replace` 清掉 query。只收文本;文件分享要 POST + SW,未做。
- 会话指针只读:页面挂载时 `chatFolder` 查询读回指针(用户此前已传过文件时),不触发创建。

## token 处理层

`src/api/client.ts` 封装唯一 GraphQL 请求出口:

1. 带上 `Authorization: Bearer <accessToken>`。
2. 响应含 `UNAUTHENTICATED` → 进入刷新流程:模块级 `refreshing: Promise | null` 保证**单飞**,并发 401 共享同一个 Promise。刷新体包在 `navigator.locks.request('gopan-auth-refresh')` 里跨标签互斥;拿到锁后若 store 里的 access token 已不是拿到 401 的那个(别的标签刚刷新并经 `BroadcastChannel('gopan-auth')` 广播过来),直接复用不再请求。`setAuth` 与主动登出都广播,其他标签直接采用;刷新失败只清本标签。
3. 刷新成功重放原请求;失败清 auth store,`router.push('/login')`(带 redirect 回跳参数)。
4. 访客页持访客 token,同一封装,`scope` 对前端透明。

OAuth consent 不把 MCP Access Token 带回前端。页面只调用 `oauthAuthorizationRequest` 校验展示内容,再调用 `decideOAuthAuthorization`;后端返回 MCP client 的 callback URL,浏览器直接跳转。code 兑换与 refresh 全由 MCP Host 对 `/oauth/token` 完成。

## 体验细节(v1 就做的)

- 列表虚拟滚动 + 缩略图懒加载(IntersectionObserver,vue-virtual 自带可见性)。

## 响应式与移动端(v2.3.0)

断点两个:`≤767` 手机(卡片列表 + 抽屉导航)、`768–1023` 紧凑(仍是表格,隐藏次要列)、`≥1024` 桌面(现状)。CSS 管样式、composable 管分支:

- `composables/breakpoints.ts`:`resolveBreakpoint(width)` 纯函数 + 模块级单例 `useBreakpoints()`(detached effectScope,免得首个调用方卸载后监听被销毁)。
- `styles/responsive.css`:安全区变量 `--sat/--sab`、`--touch-target`,`.el-dialog`/`.el-message-box` 窄屏钳宽,`only-mobile/only-compact/only-desktop`。断点数字与 `breakpoints.ts` 的一致性由 `responsive.test.ts` 读源码断言。
- 触屏语义:轻点 = 进目录/预览(多选态下改为勾选),长按 = 底部操作菜单,预览里左右滑动切换、双指缩放。
- 加新操作必须改公用的 `components/nodes/nodeDisplay.ts` 与视图里的 mutation,不能只改一处模板 —— 桌面表格与手机卡片是两套渲染。

详见 `doc/milestones/M10-移动端与PWA.md`。

# 07 · 前端设计

## 路由与页面

```
/login                    登录/注册
/drive/:folderId?         主界面(文件列表,无 folderId = 根目录)
/trash                    回收站
/shares                   我的分享管理
/admin                    管理端(管理员)
/s/:token                 访客分享页(独立布局,无侧边栏)
/oauth/consent            OAuth 授权确认(独立布局,登录后回跳)
```

主界面一个页面承载全部核心交互:面包屑、列表/网格切换、多选、右键菜单(下载/重命名/移动/分享/删除)、拖拽上传、新建文件夹。预览是全局模态(`PreviewModal`),不占路由——从列表、搜索、访客页都能唤起。

## 组件结构

```
AppShell(侧边栏 + 顶栏 + 上传队列抽屉)
├─ DriveView
│  ├─ Breadcrumb
│  ├─ NodeList(虚拟滚动;列表/网格两种渲染)
│  ├─ ContextMenu / MoveDialog(目录树选择器)/ ShareDialog
│  └─ UploadDropzone(整页拖拽层)
├─ PreviewModal
│  ├─ ImageViewer(v-viewer)  PdfViewer(pdfjs-dist)
│  ├─ MediaPlayer(video/audio)  TextViewer
│  └─ OfficePending(转换中轮询态)
├─ TrashView / SharesView
├─ MCPAccessDialog(API Key + OAuth grant 管理)
├─ AppPasswordsDialog(WebDAV 应用密码)
└─ ShareVisitorView(/s/:token,复用 NodeList + PreviewModal)
```

`OAuthConsentView` 不放进 `AppShell`:MCP Host 打开浏览器后只需要看到请求应用、权限列表和允许/拒绝,不应暴露云盘操作界面。路由守卫仍要求正常用户登录;未登录时带完整 query 跳 `/login`,成功后原路返回。

## Pinia store 划分

| store | 职责 |
|---|---|
| auth | user、accessToken(内存)、login/refresh/logout;单飞刷新锁 |
| uploads | 全局上传队列:任务列表、状态机、并发调度;跨路由存活 |
| selection | 当前目录的多选集合、剪切板(移动/复制引用) |

服务端数据(目录、分享、回收站)**不进 Pinia**,全归 vue-query 管——store 只放客户端状态,这条边界不破。

## 数据层

- codegen 产出 typed document + hooks;查询 key 约定:`['children', parentId, order]`、`['node', id]`、`['trash']`、`['shares']`。
- mutation 后精准失效:改名/移动/删除 → 失效旧父与新父的 `children`;上传完成 → 失效目标目录。不做乐观更新(v1 不值得,失效重拉 200ms 内)。
- 上传队列的进度不进 vue-query(高频本地态),完成事件才触发失效。
- Agent 凭据查询 key 为 `['mcpAPIKeys']` / `['oauthGrants']`;创建或吊销后只失效对应 key。API Key 明文只放组件局部内存,对话框关闭即清空。

## 上传器(唯一自研重点)

任务状态机:

```
queued → hashing → initiating → uploading → completing → done
                     │(instant)────────────────────────↗
   任一态 → paused(用户)/ failed(重试 3 次后)/ canceled
```

- **hashing**:hash-wasm 在 Web Worker 流式算 SHA-256(File.stream() 分块喂),不卡 UI;>4GB 文件照样恒定内存。
- **uploading**:全局并发 = 同时 2 个文件 × 每文件 3 片(避免几十个 PUT 抢带宽);fetch + AbortController,每片失败独立指数退避重试。
- **进度**:片粒度累计;fetch 上传无进度事件,用 XMLHttpRequest 发分片拿 `upload.onprogress`(这是全项目唯一一处 XHR,封装在 uploader 内部)。
- **断点**:sessionId + 文件指纹(name+size+lastModified)记 localStorage;页面重开时列出可恢复任务,恢复时经 `uploadSession(id)` 拿 `uploadedParts` 续传。
- **文件夹上传**:webkitdirectory 取相对路径,先批量建目录树再入队文件。

## token 处理层

`src/api/client.ts` 封装唯一 GraphQL 请求出口:

1. 带上 `Authorization: Bearer <accessToken>`。
2. 响应含 `UNAUTHENTICATED` → 进入刷新流程:模块级 `refreshing: Promise | null` 保证**单飞**,并发 401 共享同一个 Promise。
3. 刷新成功重放原请求;失败清 auth store,`router.push('/login')`(带 redirect 回跳参数)。
4. 访客页持访客 token,同一封装,`scope` 对前端透明。

OAuth consent 不把 MCP Access Token 带回前端。页面只调用 `oauthAuthorizationRequest` 校验展示内容,再调用 `decideOAuthAuthorization`;后端返回 MCP client 的 callback URL,浏览器直接跳转。code 兑换与 refresh 全由 MCP Host 对 `/oauth/token` 完成。

## 体验细节(v1 就做的)

- 列表虚拟滚动 + 缩略图懒加载(IntersectionObserver,vue-virtual 自带可见性)。
- 快捷键:Del 删除、F2 重命名、Ctrl/Cmd+A 全选、Esc 关预览(VueUse useMagicKeys)。
- Office 预览轮询 `node.preview.status`,2s 间隔、指数退避、模态关闭即停(vue-query 的 refetchInterval 函数式控制)。
- 上传队列抽屉常驻右下角,关闭页面前有未完成任务时 beforeunload 提示。

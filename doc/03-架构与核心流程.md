# 03 · 架构与核心流程

## 组件图

```
浏览器(Vue SPA) ── GraphQL /query ───────────┐
Agent(MCP Host) ── Streamable HTTP /mcp ─────┼──▶ gopan(Go 单二进制)
WebDAV 客户端 ──── /dav ─────────────────────┘      │
                                                     ├──▶ PostgreSQL
gopan 内部:                                          ├──▶ MinIO
  GraphQL(gqlgen) / MCP(go-sdk) / OAuth 2.1          ├──▶ Gotenberg(可选)
  WebDAV(x/net/webdav) / HTTP handlers               └──▶ ffmpeg(exec)
  service → sqlc / objstore / worker pool

浏览器、Agent ◀──── 预签名 PUT/GET ────▶ MinIO
```

MinIO 两类 key:`blobs/{sha256}`(原始文件)、`derived/{sha256}/{kind}`(预览产物,kind = thumb256 / thumb2048 / pdf / cover)。派生物按源 hash 命名,去重顺带让预览结果也去重。

## 上传(秒传 / 分片 / 断点续传)

```
客户端                          gopan                        MinIO
  │ Worker 算 SHA-256
  │ ①initUpload(hash,size,name,parentId)
  │ ────────────────────────────▶ 配额检查
  │                               blob 已存在? ──是──▶ 直接建 node,返回 done(秒传)
  │                               否:建 upload_session ──▶ NewMultipartUpload(blobs/{hash})
  │ ②←── sessionId + 各分片预签名 PUT URL(16MB/片,1h 有效)
  │ ③分片并发 PUT(3~4 路) ────────────────────────────────▶ UploadPart
  │ ④completeUpload(sessionId,各片 ETag)
  │ ────────────────────────────▶ CompleteMultipartUpload
  │                               建 blob(status=pending_verify) + node,更新配额
  │                               投递任务:hash 校验、预览派生
  │ ⑤←── node
```

- **断点续传**:客户端把 sessionId 记 localStorage;重新进入时查 `uploadSession(id)`,服务端 `ListObjectParts` 返回已完成分片号,客户端只传缺的。session 48h 过期,过期由 worker 调 AbortMultipartUpload 清理。
- **hash 校验**:客户端报的 hash 不可信。complete 后 worker 流式重算 SHA-256,不符则删对象、删 node、标记会话失败(前端下次轮询看到)。校验完成前该 blob 不参与秒传命中。
- **同名冲突**:`(owner_id, parent_id, name)` 活跃节点内唯一,冲突时后端自动改名 `xxx (1).ext`。

## Agent 上传与下载(Remote MCP)

Agent 通过 `/mcp` 调工具,文件字节不进入 MCP JSON:

1. `prepare_upload` 可带 SHA-256:命中已验证 blob 时直接秒传;不带或未命中时创建 `transfer_sessions`。
2. 小文件返回单 PUT URL,大文件返回 multipart URL;Agent 用自身 HTTP/shell 工具直接传 MinIO。
3. `complete_upload` 后服务端流式计算或复核 SHA-256,最终迁移到 `blobs/{sha256}`、去重并创建 node;Agent 轮询 `get_upload_status`。
4. `prepare_download` 对单文件返回短期 GET URL;文件夹/批量返回只授权指定节点的 `/mcp-download/{ticket}` ZIP 票据。

`idempotency_key` 防 Agent 重试重复建任务。Agent 传输会话与浏览器 `upload_sessions` 分开:前者允许未知 SHA、单 PUT 和 staging key,但最终都汇入同一 blob/node/配额不变量。完整工具合同见 docs/MCP.md。

## 下载

- 单文件:GraphQL 返回预签名 GET URL(15 分钟),浏览器直连 MinIO,Range 原生支持。`response-content-disposition` 参数控制下载文件名(对象 key 是 hash,没有原名)。
- 文件夹:浏览器走 `/pack?nodes=...`,Agent 走 `/mcp-download/{ticket}`;Go 服务端流式 zip(zip 是打包不压缩,CPU 便宜),单次限 2GB。WebDAV 传输同样按协议经过 Go;其余浏览器/Agent 原始文件传输直连 MinIO。

## 预览管线

| 类型 | 触发 | 产物 |
|---|---|---|
| 图片 | 上传完成即派生 | thumb256(列表格子)、thumb2048(预览大图) |
| 视频 | 上传完成即派生 | cover(ffmpeg 抽第一秒帧)+ ffprobe 时长写入 blob 元数据 |
| Office | 首次请求预览时(requestPreview)惰性触发 | derived/{hash}/pdf,Gotenberg 转换,任务状态前端轮询 |
| PDF / 文本 / 原生音视频 | 无需派生 | 直接预签名 GET 原文件 |

派生任务记录在 tasks 表:worker pool 消费,失败重试 3 次,重启后扫 `status IN (pending, running)` 恢复。同一 (hash, kind) 幂等——已存在即跳过。

## 分享与访客

1. 属主 `createShare(nodeId, password?, expiresAt?)` → 生成 10 字符 token(base58)。
2. 访客打开 `/s/{token}`:Go 对这个路由**服务端模板直出**带 og:title / og:image 的 HTML(微信/群聊出卡片预览),随后加载 SPA。
3. SPA 调 `shareInfo(token)`(公开查询,返回名称、是否需密码);需要密码则 `verifySharePassword(token, pwd)`。
4. 服务端签发**访客 JWT**:`scope=share:{shareId}`,30 分钟,只读。
5. 访客后续用同一套 GraphQL 查询/预览/下载,鉴权层校验:目标 node 必须在分享根的子树内(递归 CTE),且分享未过期未吊销。

## 删除、引用计数与 GC

- 删除 = 软删(`nodes.deleted_at`),进回收站;还原清空该字段。
- 彻底删除/30 天到期:删 node 行,事务内 `blobs.ref_count - 1`,扣减用户 used_bytes。
- GC worker:每小时扫 `ref_count = 0` 且宽限 24h 的 blob,删 MinIO 对象(blobs + derived)后删行。宽限期防止「删了马上又秒传」的抖动。
- 配额记账按**逻辑大小**:两个用户存同一文件,各扣各的配额,物理只存一份。

## 目录树操作的两条规则

- 移动:目标不能是自己或自己的后代(递归 CTE 校验),否则成环。
- 子树体积/数量统计不实时算,列表只展示文件自身大小;需要时异步任务算(v2)。

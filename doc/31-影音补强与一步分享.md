# 31 · 影音补强与一步分享

> 3.17.0 的四件事:网页能放 mkv(服务器只换封装)、歌词、桌面端用电脑上的播放器放、一步把文件变成分享链接;3.18.0 把「最近播放」并进「最近」。

## 一、网页放 mkv

### 用的人看到的

- 网页(和桌面端窗口)里点开 mkv / avi / ts / flv / wmv / mpg 这类视频:浏览器能直接放的(mkv 里是 H.264 + AAC 之类、没有内嵌字幕)照旧直接放;放不了的显示「正在转成浏览器能放的格式」和进度,几十秒后自动开始放,之后再打开秒开。
- 文件里内嵌的文字字幕(SRT / ASS)一起取出来,和同文件夹的外挂字幕放在同一个「字幕」下拉里(两边都有时内嵌的标「(内嵌)」),默认选中文。
- 画面编码浏览器放不了的(MPEG-4 Part 2 / XviD、WMV、10 位 H.264 等)直接说原因,给「下载」;桌面端多一个「用播放器播放」。
- 安卓 App 自己能放这些格式,不走这里。

### 怎么做的

- 只换封装、不转画面:`ffmpeg -c:v copy`,HEVC 打 `hvc1` 标签;音频 AAC / MP3 / Opus 原样拷,AC3 / DTS / FLAC 等转成 192k 双声道 AAC;文字字幕各转一份 WebVTT。一次只转一个,内存与 CPU 都很省(只有音频转码吃一点 CPU)。
- 转好的放在服务器本地缓存目录(`<sha256>/video.mp4`、`sub<N>.vtt`、`meta.json`),**不进对象存储、不占配额**;转的过程中在 `<sha256>.part/` 里,转完整个目录改名。重启、重新部署(容器重建)后缓存没了也没关系,再放一次重新转。
- 淘汰:每小时一次,删掉超过 `GOPAN_REMUX_TTL` 没放过的;要腾地方时按最近播放从旧到新删,总量不超过 `GOPAN_REMUX_CACHE`。播放时(最多一小时一次)刷新目录里 mp4 的修改时间当「最近播放」。转之前看磁盘:转完至少还要剩 3 GB(数据库、对象存储在同一块盘上),不够就不转。单个文件超过缓存上限也不转。
- 任务排在内存里(队列最多 8 个);失败、编码不支持的结果记一小时,过后再打开当没转过。
- 地址:`/remux/{sha256}/{video.mp4|subN.vtt}?e=<过期时刻>&s=<签名>`,HMAC 的钥匙每次启动随机生成,6 小时有效;`<video>` 带不了 Authorization 头,所以地址本身就是凭证。`http.ServeContent` 回,支持 Range,拖进度没问题。
- 判断能不能直接放:上传后的 `media_probe` 现在把主要流的编码也记进 `blobs.media_meta`(`vcodec`、`vpix`、`acodec`、`tsubs`)。老文件没有这些信息,一律先转。
- 来源地址给 ffmpeg 的是 12 小时的内网预签名(`PresignInternalGetFor`),并开了断线重连。

### 接口

```graphql
type PreviewInfo { … remux: RemuxInfo }   # 只在 node(id) 详情里;别的视频或没开转换时为空

type RemuxInfo {
  status: RemuxStatus!       # NONE / QUEUED / RUNNING / DONE / UNSUPPORTED / FAILED / UNAVAILABLE
  progress: Float            # RUNNING 时 0~1
  url: String                # DONE 时
  direct: Boolean!           # 先放原文件试试
  message: String
  subtitles: [EmbeddedSubtitle!]!
}

requestRemux(nodeId: ID!): RemuxInfo!   # 分享访客在分享范围内也能用
```

网页按 `pickVideoSource`(`web/src/utils/media.ts`)决定放原文件、放转好的,还是等转换;原文件放失败(格式不支持)时自动转。转换中每 1.5 秒查一次。

### 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `GOPAN_REMUX_DIR` | 系统临时目录下 `gopan-remux` | 缓存目录 |
| `GOPAN_REMUX_CACHE` | `8589934592`(8 GB) | 缓存总量上限,单个文件也不能超过它;`0` 关掉转换 |
| `GOPAN_REMUX_TTL` | `168h` | 多久没放就删 |

找不到 ffmpeg / ffprobe 时自动关掉(网页照旧提示下载)。

## 二、歌词

- 歌旁边放同名 `.lrc`(同文件夹,名字不分大小写:`晴天.mp3` 配 `晴天.lrc` / `晴天.LRC`),播放时滚动显示,当前句高亮,点一句跳过去;没有时间标签的歌词就静态显示。网页的播放条第二行显示当前这一句。
- 服务端统一解析(`internal/lyrics`):一行几个时间标签、`[offset:±毫秒]`、逐字时间 `<mm:ss.xx>` 去掉;编码按 UTF-8 / UTF-16 / GB18030 认(和外挂字幕同一套)。
- `GET /lrc/{歌的 nodeId}`(`Authorization: Bearer` 或 `?token=`)回 `{"synced":true,"lines":[{"t":12.3,"text":"…"}]}`,没有歌词 404,不是音频 415;分享访客在分享范围内可用,分享的就是这首歌本身时不给(同文件夹的歌词不在分享范围里)。
- 网页:`stores/player.ts` 换歌时取,`AudioPanel.vue` 显示;安卓:`LyricsRepository`(走播放器的客户端,`/lrc/` 和 `/sub/` 一样带 Bearer)、`LyricsBox.kt`。分享页的访客音频不显示歌词。

## 三、桌面端用播放器播放

- 视频、音乐的右键菜单与预览顶栏多一个「用播放器播放」;网页放不了的视频,提示里也有这个按钮。
- 外壳(`desktop/src-tauri/src/player.rs`)找播放器:这个扩展名的默认程序是认得的播放器(PotPlayer、VLC、mpv / mpv.net、MPC-HC / BE、KMPlayer、SMPlayer)就用它;否则依次在 App Paths 注册表、常见安装目录、PATH 里找;都没有用系统自带的旧版 Windows Media Player 兜底。Win11 默认的「媒体播放器」是商店应用,拿不到程序路径、也不收命令行地址。
- 地址用 `Node.streamUrl`:音视频的内联预签名,12 小时有效,播放器拖进度时重新请求不会因为签名过期失败。只给登录用户。
- 同文件夹的默认外挂字幕下到本地(原格式,ASS 的样式也保留),按各播放器的参数交过去:VLC `--sub-file=`、mpv `--sub-file=`、PotPlayer `/sub=`、MPC `/sub <路径>`。

## 四、一步变成分享链接

- 传上来的文件都放在根目录的「快传」文件夹(`quickShareFolder` 幂等地找或建;根目录已有同名文件时建「快传 (1)」)。分享 7 天有效、不设密码。
- 一个文件:传完分享这个文件本身(对方看到的是文件页)。多个、或有文件夹:先在「快传」里建一个文件夹(「报告.pdf 等 3 项」,重名自动加序号)装这一批,**全部传完再分享**,对方打开时不会看到传了一半的。
- 桌面端:资源管理器右键「上传并复制分享链接」、「发送到 → gopan 分享链接」。传完链接放进剪贴板,通知点一下用浏览器打开。等待中的批次只记在内存里:中途退出程序,文件照样续传,只是不会自动出链接(`desktop/src-tauri/src/quickshare.rs`,传输引擎顶层任务结束时回调)。
- 安卓:别的 App「分享 → 存到 gopan」的去处里多一个「生成分享链接」。传完链接放进剪贴板,并发一条通知,点一下选 App 发出去(`core/share/QuickShare.kt`,按上传引擎的完成 / 失败事件等)。
- 网页:分享框建好后多一个二维码,当面扫一下就打开。

## 五、「最近」并入接着看(3.18.0)

原来「最近」(打开过的文件)和「最近播放」(没看完的音视频与 PDF)是两个入口,一个看过的视频两边都有。现在只有「最近」:

- 每行写打开时间,有进度的接着写看到哪(「看到 23:15 / 1:42:00」「第 12 / 80 页」「已看完」);顶上一排「接着看」(没看完的,最多 12 个),点一下接着放,× 清掉进度;能按全部 / 影音 / 文档 / 图片筛。
- 还是每个文件一条、按最后打开的时刻排(不记每次打开的流水,免得一部剧刷出几十条);不记文件夹。最多 500 个(和进度表每人留的条数对齐)。
- `recentFiles` 的查询顺带关联 `play_progress`,每项的 `playProgress` 直接给(列表里别处仍不给,省查询);「从最近中移除」与「清空」连进度一起清。
- 网页侧栏底部的「最近播放」弹窗、安卓文件页菜单里的「最近播放」页去掉。
- 名字仍叫「最近」(和常见网盘一致)。

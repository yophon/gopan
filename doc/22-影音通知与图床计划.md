# 22 · 影音、通知与图床计划

> 结论先行:三件事。**影音**:让存在网盘里的视频、音乐真正好用——先补上生产环境认不出 mkv / mov / avi 的缺口,再做同名外挂字幕、跨端记住播放进度、文件夹连播。**通知**:收集链接收到文件、离线下载失败、空间快满、新设备登录、直链被盗刷这些"你没在看的时候发生的事",站内铃铛里能看到,也能推到 Webhook / ntfy / Bark / Telegram。**图床与直链**:任意文件一条永久公开地址,能贴进博客和 Markdown;PicGo / ShareX / uPic / Typora 能直接上传;每次访问都记账,有流量上限、来源白名单和异常提醒(提醒走通知)。坚持轻:不转码、不加系统包、不加常驻组件,闲时零开销。顺序:M1 媒体类型 → N 通知 → L 直链与图床 → M2–M4 影音 → 安卓,一起作为 v3.4.0 上线。

## 一、目标与边界

### 影音

**目标**:mkv、mov、avi、webm 等常见格式能被认成视频(网页放不了的给出提示,安卓 App 直接放);视频旁边同名的 `.srt` / `.ass` / `.vtt` 自动挂上,GBK 编码也正常;看到一半换设备接着看(PDF 记页码);音乐把文件夹当歌单连着放,网页切页面不断、手机锁屏能控制;视频播完自动下一集。

**不做**:

- 转码(浏览器放不了的格式提示下载或用 App,见 doc/12 能力边界)。
- 网页上显示 mkv 内封字幕(浏览器不支持;安卓能选内封字幕轨)。
- 字幕时间轴调整、在线搜字幕、ASS 的样式与特效(只保留文字和时间)、歌词。
- 播放器换皮:网页继续用浏览器原生控件,只补字幕选择、续播提示和下一集倒计时。

### 通知

**目标**:站内消息(网页铃铛、安卓「我的」里的通知列表)+ 外部推送;每个渠道能选推哪些事件、能发测试消息;同一件事短时间内重复发生时合并成一条。

**不做**:

- 邮件(见第八节决策 5)。
- Google 推送(FCM)与厂商推送通道;WebSocket 实时推送(网页本来就 30 秒轮询一次 `Me`)。
- 分享被访问的提醒(访问记录已经有,见 doc/12)。

### 图床与直链

**目标**:任意文件生成一条永久公开地址 `https://<域名>/x/<token>/<文件名>`,吊销即时生效;图片地址能直接贴进博客、论坛、Markdown;图床工具(PicGo、ShareX、uPic、Typora、curl)用专用密钥上传,返回直链和 Markdown;每条直链能看到访问次数、流量、来源站点、访问明细(IP、客户端);有每条每天、全站每月的流量上限,有来源白名单,突增、被陌生站点大量引用、单个 IP 狂刷时提醒。

**不做**:

- 图片处理(压缩、水印、格式转换);只提供已有的 256 / 2048 缩略图作为可选尺寸。
- 自定义域名、CDN 集成;前面套了 CDN 的,命中 CDN 缓存的访问不会被记到(doc/09 写明)。
- 访客上传(收集链接已经有)。

**三者都坚持**:精简档(2 核 2G、gopan 容器 384 MB)完整可用;不转码、不加系统包、不加常驻组件,闲时零开销。

## 二、影音

### 1. 媒体类型补全(M1,迁移 00024)

`blobs.mime` 只按扩展名定(`mimeByName` → `mime.TypeByExtension`),而运行镜像(debian-slim)里没有 `/etc/mime.types`,Go 内置表只认 mp4 / mp3 / m4a / flac / ogg / wav,还把 `.webm` 当成 `audio/webm`。结果:生产上 mkv、mov、avi、ts 被当成普通文件,不能预览、不生成封面,安卓 App 也不会去放。

- **内置表**:在 `mimeByName` 前查一张自带的表(不依赖系统文件):视频 `.mkv .mov .m4v .webm .avi .ts .m2ts .3gp .flv .wmv`,音频 `.aac .weba .wma .ape .aiff .mka`,字幕 `.srt .ass .ssa .vtt`。
- **存量回填**:迁移里按引用节点的扩展名把这些格式的 `application/octet-stream`(以及 `.webm` 的 `audio/webm`)改正,并给改过的 blob 补排 `media_probe` / `video_cover` 任务(`ON CONFLICT DO NOTHING`),由 worker 慢慢跑。
- **网页放不了**:`<video>` 报错时显示「浏览器放不了这个格式(mkv / HEVC 等),下载或用安卓 App 看」,不再是一个黑框。安卓 ExoPlayer 能放 mkv / ts / flv / avi。

### 2. 外挂字幕(M2)

- **匹配**:同一文件夹里,文件名是「视频名去扩展名」加 `.srt` / `.ass` / `.ssa` / `.vtt`,或中间多一段语言标记(`电影.zh.srt`、`电影.chs.ass`、`电影.en.vtt`),不分大小写。文件夹里只有一个视频时,所有字幕文件都算它的。语言标记换成显示名(zh / chs / sc / 简体 → 简体中文,cht / tc / 繁體 → 繁体中文,en / eng → English),默认选中文。
- **接口**:`PreviewInfo.subtitles: [SubtitleTrack!]!`(只在单个节点的预览里给,列表不查),每条有 `nodeId`、`name`、`label`、`lang`、`url`。分享访客在分享子树内也能拿到。
- **转换**:`GET /sub/{nodeId}?token=<access>`(同 `/arc`):读字幕(≤ 2 MB),用 `fulltext.DecodeText` 解码(UTF-8 / UTF-16 / GB18030),SRT 与 ASS / SSA 一律转成 WebVTT 返回;ASS 去掉 `{\...}` 样式标签、`\N` 换行、绘图指令。`text/vtt; charset=utf-8`,私有缓存 1 小时,带 nosniff 与 CSP sandbox。
- **网页**:`<video>` 里放 `<track>`,标题栏加「字幕:简体中文 / English / 关」。
- **安卓**:`MediaItem.SubtitleConfiguration` 挂同一个 `/sub` 地址;`PlayerView` 的字幕按钮里同时能选 mkv 内封的字幕轨。

### 3. 播放进度(M3)

- **表**(同在 00024):`play_progress(owner_id, node_id, position, duration, finished, updated_at)`,主键 `(owner_id, node_id)`,节点彻底删除时级联删掉。position 对音视频是秒,对 PDF 是页码。
- **记录**:`saveProgress(nodeId, position, duration)`,播放中每 15 秒、暂停、关闭时各报一次;PDF 翻页后 5 秒报一次。只记 5 分钟以上的音视频和 3 页以上的 PDF(第八节决策 7);剩余不到 3%(且不到 20 秒)记为看完,下次从头开始。访客不记。
- **续播**:`Node.playProgress` 随单个节点的预览返回;进度超过 10 秒就自动跳过去,提示「从 23:15 继续 · 从头播放」。
- **最近播放**:`recentPlays(limit)` 返回没看完的,网页侧栏与安卓文件页菜单各有一个入口。每人只留最近 500 条,每日清理。
- **签名过期**:预览地址 15 分钟有效,长视频中途重新请求会 403。网页播放出错时重新取地址、回到原位置接着放(安卓已经这样做)。

### 4. 连播(M4)

- **接口**:`playlist(nodeId): [Node!]!` 返回同文件夹里同类(视频或音频)的文件,按自然顺序排(「第2集」在「第10集」前面),最多 1000 个。
- **视频下一集**:播完时有下一个就显示「下一集:xxx(5 秒)· 取消」,倒计时结束切过去。网页和安卓都用 `playlist`,不依赖当前列表加载了多少。
- **网页音乐**:全站一个播放器(Pinia store + `AppShell` 里唯一的 `<audio>`)。在预览里点开音频就把整个文件夹排进队列,关掉预览后页面底部留一条迷你播放条(曲名、上一首 / 播放 / 下一首、进度、顺序 / 单曲循环 / 随机、关闭),切换页面不中断。接 `navigator.mediaSession`,手机锁屏和电脑媒体键能控制。每首开播前才去取地址,避免队列里的地址过期。
- **安卓音乐**:`PlaybackService` 已经是 `MediaSessionService`,改成 `setMediaItems(队列, 起点)`;地址在打开时才解析(`ResolvingDataSource`,mediaId 即节点 id),队列再长也不会过期;通知栏与锁屏的上一首 / 下一首由 media3 自带;主界面底部加迷你播放条。

## 三、通知

### 1. 数据与投递(N1,迁移 00025)

| 表 | 内容 |
|---|---|
| `notifications` | `id`、`owner_id`、`kind`、`level`(info / warn / alert)、`title`、`body`、`target`(jsonb:跳转到的节点 / 分享 / 收集链接 / 任务 / 直链)、`group_key`、`count`、`created_at`、`updated_at`、`read_at`;索引 `(owner_id, id DESC)` 与未读的部分索引 |
| `notify_channels` | `id`、`owner_id`、`kind`(webhook / ntfy / bark / telegram)、`name`、`config`(jsonb)、`events`(text[],推哪些事件)、`enabled`、`last_ok_at`、`last_error`、`last_error_at` |
| `notify_deliveries` | `notification_id`、`channel_id`、`status`(pending / sent / failed)、`attempts`、`next_at`、`error`、`sent_at` |
| `instance_state` | `key`、`value`(jsonb)、`updated_at`;放备份心跳等全站状态 |

- **写入**:`Notifier.Notify(ctx, q, owner, event)`。能放进事件本身事务的就放进去(收集落库、配额),否则在提交后写。
- **合并**:带 `group_key` 的事件(如「某条收集链接收到文件」),同一人 30 分钟内有未读的同组消息就把 `count` 加一、更新正文(「作业收集 收到 12 个文件:张三、李四…」),不另起一条;合并期间只推第一条。
- **投递**:写通知时按渠道订阅生成 `notify_deliveries`。worker 里一个投递循环(写入时进程内唤醒,另有 30 秒兜底),`FOR UPDATE SKIP LOCKED` 领取,10 秒超时,失败重试 3 次(30 秒 / 2 分钟 / 10 分钟),最后一次的错误显示在渠道上。每个渠道每小时最多推 20 条,超出的只留在站内。
- **出站安全**:用离线下载的 `fetcher.Guard`(按真实连接 IP 拦内网、不走系统代理、`GOPAN_FETCH_DENY` 同样生效)。推到自建在内网的 ntfy 要设 `GOPAN_NOTIFY_ALLOW_PRIVATE=true`。
- **保留**:通知 90 天且每人最多 1000 条;投递记录 30 天。

### 2. 渠道

| 渠道 | 填什么 | 怎么发 |
|---|---|---|
| Webhook | URL,可选签名密钥 | POST JSON(`kind`、`level`、`title`、`body`、`url`、`created_at`);有密钥时带 `X-Gopan-Signature: sha256=<HMAC>` |
| ntfy | 服务器(默认 `https://ntfy.sh`)、topic,可选访问令牌 | JSON 发布,带标题、点击跳转、按级别设优先级 |
| Bark | 服务器(默认 `https://api.day.app`)、device key | POST `/push`,分组 gopan |
| Telegram | bot token、chat id | `sendMessage` |

- 令牌、密钥这类字段只写不读:GraphQL 不返回原值,界面显示打码。数据库里是明文(发送时要用),doc/06 写明。
- 每个渠道有「发送测试」;点击推送跳到网页上对应的位置。

### 3. 事件(N2)

| 事件 | 触发点 | 级别 | 默认推送 |
|---|---|---|---|
| 收集链接收到文件 | 收集上传落库(`finalizeBrowserUpload`),同一链接合并 | info | 推 |
| 收集链接因空间不足拒收 | 访客上传被拒(`errCollectFull`),每条链接每天一次 | warn | 推 |
| 离线下载 / 解压完成 | `user_jobs` done | info | 不推 |
| 离线下载 / 解压失败 | `user_jobs` failed(含中断 3 次被收尾) | warn | 推 |
| 空间用到 90% / 100% | 用量增加时越过阈值,同一档 7 天只提醒一次 | warn | 推 |
| 新登录 | 每次密码 / Yophon ID 登录(设备、IP);改密码后的重新登录不算 | warn | 推 |
| 新的访问凭据 | 新建 WebDAV 应用密码、API Key、图床密钥;新授权的 Agent(OAuth) | warn | 推 |
| 直链异常 | 见四.2 | warn / alert | 推 |
| 备份失败、超过 36 小时没备份(只发管理员) | `backup.sh` 回报 | alert | 推 |

**备份回报**:备份脚本跑在宿主机的 cron 里,gopan 看不到备份目录。给 CLI 加 `gopan admin notify`(沿用 `gopan admin promote` 的方式,读 `GOPAN_DB_URL`),`backup.sh` 失败时执行 `docker compose exec -T gopan gopan admin notify --level alert ...`,成功时执行 `... --heartbeat backup` 写心跳;worker 每小时看一次,心跳超过 36 小时就提醒管理员(每天最多一次)。从没写过心跳的实例不提醒。

### 4. 入口

- **网页**:侧栏加铃铛与未读数(随 30 秒一次的 `Me` 带回 `unreadNotifications`,不新增轮询;手机版在顶栏)。点开是通知抽屉:按天分组、点一条跳过去、全部已读、清空;抽屉右上角「推送设置」管理渠道和每个渠道推哪些事件。
- **安卓**:「我的」页加「通知」(底栏「我的」带未读角标),列表与网页一致;推送渠道在网页上设。可选系统通知栏提醒:WorkManager 每 15 分钟查一次新的未读,发系统通知,点开进通知列表(第八节决策 6)。
- **MCP**:不加工具。

## 四、图床与直链

### 1. 直链(L1,迁移 00026)

| 表 | 内容 |
|---|---|
| `links` | `id`、`owner_id`、`node_id`(→ nodes ON DELETE CASCADE)、`token`(10 位 base58,同分享)、`source`(web / android / api / mcp)、`created_ip`、`created_ua`、`api_key_id`、`referer_hosts`(text[],空 = 用默认规则)、`allow_no_referer`、`daily_bytes_cap`、`auto_pause`、`expires_at`、`paused_at`、`pause_reason`、`revoked_at`、`hits_total`、`bytes_total`、`last_hit_at`;每个节点同时只有一条有效直链(部分唯一索引),「复制直链」重复点拿到的是同一条 |
| `link_prefs` | 每人一行:默认来源白名单、是否允许无来源访问、图床文件夹、是否抹 GPS |

- **地址**:`/x/{token}/{文件名}`。文件名只为好看和让论坛认出扩展名,查找只看 token;改名后旧地址照样能用。图片可加 `?s=256` / `?s=2048` 取缩略图,缩略图没生成时回落原图。
- **中转**:Go 从 MinIO 读出来经 `http.ServeContent` 返回(支持 Range、`If-None-Match`),ETag 用内容 sha,`Cache-Control: public, max-age=3600`。不跳转到对象存储的签名地址(第八节决策 1):只有经过 Go 才能精确记流量、按上限拦、吊销即时生效。
- **响应类型**:图片、音视频、PDF 内联;SVG 内联但带 `CSP: sandbox`(直接打开也跑不了脚本);其余一律附件下载,HTML 永远不内联。都带 nosniff、`X-Robots-Tag: noindex`、`Access-Control-Allow-Origin: *`(公开内容,不带凭据)。
- **状态**:token 不存在、已吊销、过期、文件在回收站(还原后恢复)、属主被禁用 → 404;来源不在白名单 → 403;单 IP 超速 → 429;暂停或超限 → 503 带 `Retry-After`。
- **闸门**:全站同时 ≤ 16 路,超出直接 503;每 IP 每分钟 120 次。现在的 `keyedLimiter` 从不清理 key,直链面向全网会让它一直长,这次给它加按时间淘汰。
- **长连接**:大文件直链照 `/pack` 的做法单独放开 60 秒写超时;`normalizePath` 加 `/x/`、`/sub/`、`/api/img/upload`,指标不再混进 `/spa`。

### 2. 审计与检测(L2)

**记账**(进程内聚合,每 30 秒批量写一次,退出时冲刷;崩溃最多丢 30 秒的计数):

| 表 | 内容 | 保留 |
|---|---|---|
| `link_stats` | `(link_id, hour)`:次数、字节、被拦次数、独立 IP 数 | 90 天 |
| `link_referers` | `(link_id, day, host)`:次数、字节;每条每天最多 50 个来源,其余记「其他」 | 90 天 |
| `link_hits` | 访问明细:时间、IP、客户端、来源、状态码、字节;每条每小时最多 200 条,超出只计数 | 30 天 |

**上限**(第八节决策 2):

- 每条直链每天 `GOPAN_LINK_DAILY_BYTES`(默认 5 GiB,单条可改),超了自动暂停到次日并提醒。
- 全站每月 `GOPAN_LINK_MONTHLY_BYTES`(默认 200 GiB),到 80% 提醒管理员,到 100% 所有直链 503 到月底(管理员调高即恢复)并提醒。

**异常**(每 5 分钟检查一次,同一条直链同类提醒 6 小时内只发一次):

- **突增**:最近一小时次数超过 max(300, 过去 7 天小时均值的 10 倍),提醒里带主要来源和主要 IP。
- **陌生来源**:不在白名单里的站点一小时内引用超过 100 次(「哪个站在用你的图」)。
- **单 IP 狂刷**:10 分钟超过 600 次,被限流,每天提醒一次。
- 单条直链可开「异常时自动暂停」(默认关,只提醒)。

**来源白名单**:按主域名匹配(写 `example.com` 包含 `www.example.com`),可选是否允许没有 Referer 的访问(直接打开、App 里看);`link_prefs` 设默认值,单条可覆盖。

### 3. 图床上传接口(L3)

- **接口**:`POST /api/img/upload`,`Authorization: Bearer <图床密钥>`。图床密钥是新 scope `img:upload` 的 API Key(复用 `mcp_tokens`,不能和别的 scope 混用),只能往图床文件夹上传并生成直链,读不了、列不了网盘里的任何东西;不收 URL 里的密钥(会进日志)。
- **请求**:multipart(取第一个文件字段,字段名随意)或直接把图片当请求体(`?name=` 给文件名)。只收图片:jpg、png、gif、webp、avif、bmp、svg,扩展名与文件头都要对得上;单张 ≤ `GOPAN_IMG_MAX_SIZE`(默认 20 MiB,在现有 nginx 32 MB 之内,不用改配置)。每把密钥每分钟 30 张、同时 2 张。
- **落库**:存到图床文件夹(默认 `/图床`)下的 `年-月/` 子文件夹,按需创建,撞名改名;剪贴板这类没名字的(`image.png`、`blob`)改成 `20261021-153012-a1b2.png`。走离线下载那条暂存 → sha → `CommitStaged`,同内容秒传。
- **GPS**:JPEG 里 EXIF 的 GPS 信息在原文件里直接抹掉(不重新压缩,方向等其他信息保留),默认开(第八节决策 4)。网页上给已有照片「复制直链」时,带 GPS 的会提示一句。
- **返回**:`{"url", "markdown", "html", "bbcode", "name", "size", "node_id", "link_id"}`;出错 4xx 带 `{"error": {"code", "message"}}`。
- **配置模板**:建密钥时只显示一次密钥,同时给出能直接复制的 PicGo(web-uploader 插件)、ShareX(下载 `.sxcu`)、uPic、curl 配置;Typora 通过 PicGo 用。

### 4. 入口

- **网页**:文件右键菜单「复制直链」(链接 / Markdown / HTML;多选时一行一条)。「分享」页加「直链」页签:列表(文件、今天 / 30 天的次数与流量、状态、最后访问)、详情抽屉(7 天按小时的柱状图,纯 CSS,不引图表库;来源排行;访问明细;白名单、日上限、有效期、自动暂停;暂停 / 吊销)、「上传接口」(图床密钥与配置模板)、「默认规则」;页面上直接粘贴或拖入图片 = 传进图床文件夹并复制 Markdown。
- **管理端**:概览加「直链流量」卡片(本月用量 / 上限),下面列全站流量前 10 的直链,能暂停、吊销任何人的。
- **安卓**:文件菜单「复制直链」;「分享」页加「直链」列表(次数、流量、状态,能复制、暂停、吊销);图表与设置在网页上。
- **MCP**:`create_link(node_id 或 path)`、`list_links`、`revoke_link`,scope 与分享工具相同(`shares:write` / `shares:read`)。
- **开关**:`GOPAN_LINKS`,默认开;`false` 全站关掉,入口隐藏,已有直链返回 404。

## 五、资源账

- **闲时**:零。投递循环空闲时睡眠;直链计数 30 秒冲一次,没访问就不写;异常检查与备份心跳检查各是每 5 分钟 / 每小时一条查询。
- **镜像**:不加系统包,不加依赖库(字幕转换、EXIF 处理、自然排序都是几百行 Go)。
- **内存**:直链中转每路一块 32 KB 拷贝缓冲,最多 16 路;计数缓冲按直链条数算,几百 KB。
- **CPU**:直链只有 TLS 与拷贝;字幕转换每次 ≤ 2 MB 文本。
- **磁盘**:直链明细每条每小时最多 200 行、保留 30 天;单人使用远低于 100 MB。
- **流量**:直链的出站流量就是 VPS 的出站流量,靠两档上限兜住;MinIO 在同一台机器,中转不多走外网。

## 七、风险与对策

- **直链被盗刷吃流量**:两档上限 + 三类异常提醒 + 每 IP 限流;最坏情况是本月直链全停,不影响网盘本身。
- **域名信誉**:有人把钓鱼页、恶意文件放在你的域名下,安全浏览类服务可能把整个域名标红。HTML 永远不内联,非媒体文件只能下载,`noindex`;管理员能看到并吊销全站直链,`GOPAN_LINKS=false` 一键关。实例基本只有自己用,风险主要来自密钥泄露,所以「新的访问凭据」默认推送。
- **同域下的用户内容**:`/x/` 与网页同域。直链处理不读 Cookie、不认登录态;SVG 带 sandbox;Content-Type 由服务端定,nosniff。
- **出站推送是新的 SSRF 面**:与离线下载同一个 Guard,渠道地址的拦截写进测试。
- **推送刷屏**:合并 + 每渠道每小时 20 条。
- **网页后台播放**:手机浏览器切到后台可能被系统暂停,这是浏览器限制;要稳定后台播放用安卓 App。
- **ASS 样式丢失**:只保留文字与时间,文档写明。
- **schema 变化**:三个迁移都只加表、改数据,不删列;00024 的 MIME 回填对旧二进制同样有效,回滚不需要额外处理。

## 八、需要拍板的决策(括号里是建议)

1. 直链走 Go 中转,不跳转到对象存储的签名地址(建议如此:只有这样才能精确记流量、按上限拦、吊销即时生效;代价是字节多过一遍 Go,图片场景可以忽略)。
2. 流量上限默认每条每天 5 GiB、全站每月 200 GiB,超了暂停并提醒(建议如此,`.env` 可调)。
3. 图床接口只收图片,单张 ≤ 20 MiB(建议如此:不用改 nginx;别的文件用「复制直链」)。
4. 图床上传默认抹掉照片的 GPS 位置(建议如此:公开出去的照片最容易泄露住址;不重新压缩,方向等信息保留,可在默认规则里关)。
5. 推送渠道做 Webhook / ntfy / Bark / Telegram,邮件先不做(建议如此:手机推送这四个够了;邮件要 SMTP 账号和发信信誉,以后需要再加)。
6. 安卓系统通知栏提醒每 15 分钟查一次,默认开、可关(建议如此;想要即时推送就装 ntfy App 配一个 ntfy 渠道)。
7. 播放进度只记 5 分钟以上的音视频和 3 页以上的 PDF,访客不记(建议如此:歌和短片不值得记)。
8. 每次登录都提醒,不做"是否新设备"的判断(建议如此:登录本来就少,一次登录能用很久;提醒里带设备与 IP,不是自己就去「登录设备」吊销)。

# 20 · 收集文件与内容搜索计划

> 结论先行:两件事,一件补"别人往我这儿传"(收集文件),一件补"按内容找"(内容搜索)。前者是 gopan 第一次开放**不登录的写入**,上线前要先堵一个现存的同源脚本问题;后者把"全文搜索"从能力边界里拿出来,但坚持轻:不加数据库扩展、不依赖 Gotenberg,中文靠应用层二元切词加原生 Postgres 全文索引。顺序:P0 共同前置 → 收集文件(v3.1)→ 内容搜索(v3.2)。

## 一、目标与边界

### 收集文件

**目标**:对任意文件夹生成一条收集链接发给别人;对方不用注册登录,打开链接就能往这个文件夹上传,大文件走与网页端相同的分片直传和断点续传。属主能设标题与说明、截止时间、密码、要求留名、按上传者分子文件夹、单文件 / 总量 / 个数上限,并能看到谁在什么时候传了什么。典型场景:收作业、收活动照片、让别人发一个大文件过来。

**不做**:

- 访客看文件夹里已有的内容(收集链接只写不读;要互相看,另发分享链接)。
- 访客删除或改名自己传过的文件(属主处理)。
- 往传输助手里发通知消息(见第六节),推送通知(没有推送通道)。
- 秒传(匿名访客能借秒传探测"某份内容是否有人存过",见二.4)。
- 安卓 App 里的访客上传页(访客不装 App,与分享访客页一样走浏览器)。

### 内容搜索

**目标**:网页、安卓和 MCP 都能按文件**内容**搜索:纯文本与代码、PDF、Word / Excel / PowerPoint(docx / xlsx / pptx)和 ODF;结果带命中片段与高亮,PDF 带页码,点开预览直接到那一页。Agent 多一个能力:不下载就能读 PDF / Office 里的文字。

**不做**:

- 扫描件与图片 OCR、音视频转写。
- 旧版二进制 Office(doc / xls / ppt)单独提取:只有开了 Office 组件、文件已经转出过 PDF 时才顺带索引。
- 相关度排序(结果按修改时间倒序,与文件名搜索一致)、同义词、拼音。
- 分享访客页里的内容搜索。

**两者都坚持**:精简档(2 核 2G,无 Gotenberg)完整可用;不引入新的常驻组件。

## 二、收集文件:设计

### 1. 为什么不复用 shares 表

分享的访客令牌 `share:{id}` 在所有读接口上都能用(列目录、搜索、下载、打包)。收集链接要是存进 `shares`、发同一种令牌,访客就能看到其他人传进来的文件。所以新开一张表、一种新的令牌 scope `collect:{linkId}:{uploaderId}`:现有读接口的访客分支都汇到 `Shares.Authorize` / `ValidateScope`,它们只认 `share:` 前缀,新 scope 天然被拒(fail closed),不用逐个接口加判断。

### 2. 数据模型(迁移 00021)

| 表 / 列 | 内容 |
|---|---|
| `file_requests` | `id`、`token`(10 位 base58,与分享同一生成器、不同表)、`owner_id`、`folder_id`(→ nodes,ON DELETE CASCADE)、`title`、`note`、`password_hash`、`require_name`、`group_by_uploader`、`max_file_size`、`max_total_bytes`、`max_files`、`expires_at`、`revoked_at`、`seen_at`(属主上次看收件记录的时间,用来算"新收到 N")、`created_at` |
| `file_request_uploads` | 每个送达的文件一行:`request_id`、`node_id`(ON DELETE SET NULL,文件删了记录还在)、`file_name`(快照)、`size`、`uploader_name`、`ip`、`user_agent`、`created_at`。个数与总量上限按这张表算,删掉文件不退额度 |
| `upload_sessions` 加列 | `request_id`、`uploader_id`、`uploader_name`、`uploader_ip`、`uploader_ua`:浏览器上传在 worker 里落库,请求上下文到不了那里,上传者信息只能跟着会话行走。`sha256` 改为可空(收集会话不传,见 4) |

链接失效沿用 `shareDead` 的做法集中判断:撤销、过期、目标文件夹进回收站、属主被禁用,任一成立即失效;属主重新启用后链接恢复(与分享一致)。

### 3. 接口

属主侧(登录用户):`createFileRequest(folderId, input)`、`updateFileRequest(id, input)`(标题、说明、截止时间、上限;密码不能改,要改就撤销重建)、`revokeFileRequest(id)`、`myFileRequests`(带已收个数 / 字节 / 人数 / 新收到)、`fileRequestUploads(id, cursor)`、`markFileRequestSeen(id)`。MCP 加 `create_file_request` / `list_file_requests` / `revoke_file_request`,沿用 `shares:write` / `shares:read`。

访客侧是新的一组接口,不复用 `initUpload` 等四个(它们继续只认登录用户):

| 接口 | 说明 |
|---|---|
| `fileRequestInfo(token)` | 公开:标题、说明、截止时间、要不要密码 / 留名、单文件上限、是否已关闭。不返回属主信息,也不返回属主剩余空间 |
| `openFileRequest(token, password, uploaderName)` | 验密码、记名字,发 12 小时的访客令牌(sub 仍是属主,scope `collect:{id}:{uploaderId}`,每次请求回表复查链接状态,撤销即时生效)。按 IP 限速,另按链接计错误次数 |
| `collectInitUpload(name, size)` | 返回会话与分片预签名。不收 sha256,没有秒传 |
| `collectUploadSession(id)` / `collectCompleteUpload(id, etags)` / `collectAbortUpload(id)` | 会话按 `(id, request_id, uploader_id)` 查,同一链接的其他访客碰不到别人的会话。complete 只返回最终文件名和大小,不返回 Node |
| `collectMyUploads` | 本次访问已送达的文件(名字、大小、时间),刷新页面后仍能看到 |

页面 `/c/{token}`:服务端注入 og 标签(标题用链接标题),与 `/s/{token}` 同一套做法;指标的路径归一化、前端路由守卫的免登录名单各加一条。

### 4. 上传链路:与登录用户上传的差异

复用 doc/15 的暂存隔离与异步落库,只在下面几处分叉:

| 环节 | 登录用户 | 收集链接 |
|---|---|---|
| sha256 | 客户端算,init 时带上,命中即秒传 | 客户端不算(手机上省一段等待,也不暴露秒传探测);落库时服务端本来就流式算一遍,已有同内容 blob 就直接引用、删掉暂存对象 |
| 目标位置 | `initUpload.parentId` | 链接的文件夹;开了按上传者分子文件夹就落到 `<文件夹>/<上传者名>/`,子文件夹在落库事务里按需建 |
| 同名 | init 时自动改名,落库撞名直接失败(`NAME_CONFLICT`) | 落库时再自动改名一次(匿名访客撞名很常见,比如都叫 `IMG_0001.jpg`) |
| 配额 | init 预检、落库复核,不预留 | 属主配额预留进行中的收集会话(参照 Agent 直传的 `SumActiveTransferBytes`);落库时锁链接行,复核链接自己的个数 / 总量上限 |
| 会话数 | 每人 20 个 | 不占属主的 20 个;每条链接 20 个、每个访客 4 个 |
| 错误文案 | 原样 | 属主配额不足和链接额度用完统一为"收件已满,请联系对方",不泄露属主的空间状态 |
| 截止时间 | — | init 必须在截止前;截止前已开始的上传允许传完(落库宽限到会话过期);撤销、属主被禁用立即拒绝落库 |
| 分片大小 | 预签名不限长度 | 预签名把 Content-Length 签进去(要验证 MinIO 是否校验);反代 `/gopan/` 设请求体上限(nginx 模板已有 32m,Caddyfile 补上) |

### 5. 前端

- **访客页** `CollectView.vue`:链接信息 → 密码 / 名字 → 选文件或拖拽(手机可多选相册)→ 每个文件的进度 → 已送达清单。上传中申请屏幕常亮(Wake Lock)并提示不要切走,缓解手机浏览器切后台丢上传(doc/14 第三节)。
- **上传器改造**:`uploader/manager.ts` 现在写死了登录用户的 `request` 和全局 store,遇到 `UNAUTHENTICATED` 还会跳登录页。把"调接口"抽成注入的传输层(参照 `PreviewModal` 的 `guestToken` 做法),访客页用一个独立实例;断点记录按链接 token 分开存,不和属主自己的记录混;访客页不走哈希 worker。
- **属主侧**:文件夹右键 / 长按菜单加「收集文件」;「分享」页分「分享」「收集」两个标签;收件记录列表(上传者、文件、大小、时间、IP),点文件跳到所在目录。
- **安卓**:创建对话框、收集列表、收件记录,与网页一致。

### 6. 安全

收集链接是 gopan 第一次开放**匿名写入**,下面几条是上线前提:

- **同源脚本(P0 必修)**。生产上预签名地址与站点同域名(`/gopan/*` 反代到 MinIO),这些响应不经过 Go,不带 CSP;内容类型取自第一个上传者的文件名,`.svg` / `.html` 会以可执行的类型返回;网页预览的「查看原图」是在新标签页顶层打开 `contentUrl`。今天要自己上传才会踩到;开了收集链接,就成了"陌生人往属主网盘里塞一个 SVG,属主点开,脚本以站点身份运行"——它能带着 refresh cookie 调 `/query` 换到 access token,等于接管账号。修两层:
  - 反代给 `/gopan/` 的响应加 `Content-Security-Policy: sandbox; default-src 'none'; img-src 'self' data:; media-src 'self'; style-src 'unsafe-inline'` 与 `X-Content-Type-Options: nosniff`(nginx 模板、Caddyfile、doc/09 同步改)。
  - 内联预签名对 html / xml / svg 等可执行类型改用 `response-content-type: text/plain` 或 attachment,不依赖反代配置。
  - 网页 PDF 预览走 pdf.js 拉字节,安卓用原生组件,都不受响应头影响。
- **缩略图解码炸弹**。现在只限文件大小(100 MB),不限像素。几万×几万的 PNG 压缩后可以很小,解码却要几个 G,而精简档 gopan 容器只有 384 MB。解码前先 `image.DecodeConfig` 看尺寸,超过上限(比如 1 亿像素)直接跳过缩略图。
- **猜密码**。安卓端默认生成的 4 位密码约 92 万种组合,现在只按 IP 限速,换 IP 就能接着猜。收集链接另按链接计数:一小时错 20 次锁 15 分钟。
- **滥用**。默认截止 7 天、默认有总量上限(创建时可改);属主随时撤销;收件记录保留 IP 与 UA。上传者名字是自填的,界面上标明。

## 三、内容搜索:设计

### 1. 提取什么、怎么提

| 类型 | 方法 | 依赖 | 精简档 |
|---|---|---|---|
| 纯文本、代码、Markdown、CSV、JSON 等 | 直接读;编码按 BOM → UTF-8 → GB18030 依次尝试(`golang.org/x/text`,已是间接依赖),与安卓 `TextFetcher` 同一策略 | 无 | ✓ |
| docx / xlsx / pptx / odt / ods / odp | `archive/zip` + `encoding/xml` 流式读正文 XML(`word/document.xml`、`xl/sharedStrings.xml`、`ppt/slides/*.xml`、`content.xml`) | 无 | ✓ |
| PDF | 调 `pdftotext -enc UTF-8`,按换页符 `\f` 记每页起点 | 运行镜像加 `poppler-utils` + `poppler-data`(中文 CMap) | ✓ |
| doc / xls / ppt | 已有 Office 派生 PDF 时从派生 PDF 提;不为索引专门触发转换 | Gotenberg | ✗ |

- **类型判断不信 `blobs.mime`**:它取自第一个上传者的文件名,而且运行镜像里大概率没有 `/etc/mime.types`,docx 之类会被记成 octet-stream(S1 先在生产上确认)。worker 先读头 4 KB 嗅探(`%PDF-`、zip 里有没有 `[Content_Types].xml`、文本特征),再参考引用这个 blob 的节点名。
- **按 blob 提取**:内容寻址,同一份内容只提一次,所有引用它的节点共享;blob 被回收时级联删除。
- **上限**:PDF 原文件 ≤ 200 MiB;zip 解压后的 XML 累计 ≤ 64 MiB(防 zip 炸弹);文本只读前 32 MiB;存下来的文字 ≤ 1 MiB(约 35 万汉字),超出截断并标记。单任务 60 秒超时;`pdftotext` 用 `prlimit` 限内存,恶意 PDF 只会让这一个任务失败。
- **门控**:`pdftotext` 不在 PATH 时 PDF 记为不支持,与 ffmpeg 的门控方式一致;以后装上、把提取器版本号加一就会补提。

### 2. 中文怎么索引

官方 Postgres 镜像没有中文分词(zhparser、pg_jieba、pg_bigm 都要自建镜像),现有的 pg_trgm 对 2 个字的查询用不上索引,而"合同""发票"这种两个字的搜索恰恰最常见。做法:

- **Go 侧切词**:NFKC 归一(全角转半角)、转小写;连续的汉字 / 假名 / 谚文切成重叠的二元组(单字成段时保留单字),字母数字按词切。结果用 `array_to_tsvector` 存成不带位置的 tsvector,建 GIN 索引。词项数封顶,保证不超过 tsvector 1 MB 的上限。
- **查询**:关键词按同一规则切词,词项取 AND 得到候选,最后一个英文词用前缀匹配;候选再用 `strpos(lower(content), lower(q))` 复核真实子串,去掉"二元组都在但不相邻"的假阳性。关键词至少 2 个字符。
- **片段**:只对当前页的结果截取命中位置前后各约 60 字,返回高亮区间;PDF 由命中位置和每页起点算出页码。

不选 pg_trgm 直接索引正文:2 字查询会退化成全表扫,而每行正文最长 1 MB。不选向量 / 语义搜索:要跑模型,和"轻"冲突。

### 3. 数据与任务

| 改动 | 内容 |
|---|---|
| 迁移 00022 | `blob_texts`:`blob_id`(主键,→ blobs ON DELETE CASCADE)、`status`(done / empty / truncated / unsupported / failed)、`extractor`(提取器版本)、`content`、`terms text[]`(GIN;实现时由 tsvector 改为 text[],避开 tsvector 1MB 上限)、`page_starts int[]`、`updated_at`。图片、视频也写一行 unsupported,回填时不用反复判断。`tasks.kind` 的 CHECK 加 `extract_text` |
| 入队 | blob 校验通过后(`enqueueDerivatives`)一律入队,由 worker 嗅探决定;秒传不用入队(blob 已处理过) |
| 存量回填 | 周期任务每分钟挑最多 30 个没有 `blob_texts` 行或提取器版本旧的 blob 入队,细水长流,不压垮 2 核机器;提取器升级只要把版本号加一 |
| 队列优先级 | 现在只有 2 个 worker、所有任务一条 FIFO,回填一跑起来,WebDAV / Agent 上传要等的 `verify_hash` 会被堵住。领任务改成 `verify_hash` 优先(放进 P0) |
| 管理端 | 概览加"内容索引":已索引 / 待处理 / 失败 / 不支持 / 文字总量 |
| 配置 | `GOPAN_CONTENT_INDEX`(默认开;`false` 关掉提取,内容搜索返回不可用)、`GOPAN_PDFTOTEXT_PATH`(默认 `pdftotext`) |

### 4. 接口

```graphql
searchContent(q: String!, cursor: String): ContentHitPage!

type ContentHit {
  node: Node!
  snippet: String!
  highlights: [TextRange!]!   # 片段内的命中区间
  page: Int                   # 仅 PDF / 派生 PDF
}
type TextRange { start: Int!, length: Int! }
type ContentHitPage { items: [ContentHit!]!, nextCursor: String }
```

不返回 total(要全量复核,代价高),"加载更多"靠 cursor。权限与文件名搜索相同:只搜自己的、未删除的节点;MCP 凭据限定了访问目录时只搜那棵子树。

MCP 加两个工具:`search_file_contents`(返回片段与页码)和 `read_document_text`(按偏移分段读提取出的文字,PDF / Office 也能读;权限与 `read_text_file` 相同,都要 `files:download`)。

界面:搜索页分「文件名」「内容」两个标签,内容结果显示片段与高亮;点开进预览,PDF 跳到命中页。安卓同样。

### 5. 资源账

- **磁盘**:按每份文档平均 50 KB 文字估,2000 份约 100 MB 原文,TOAST 压缩后约一半,GIN 索引同一量级;每日 `pg_dump` 跟着变大。S1 在生产数据的副本上实测,写进 doc/09。
- **内存**:提取在 gopan 进程里跑,`pdftotext` 是子进程,也计入 gopan 容器的内存上限;并发受 worker 数限制。Postgres 侧主要是 GIN 写入的 pending list,默认 4 MB。
- **镜像**:运行层加 poppler,增量 S1 实测。生产现在的上线方式只替换二进制(`Dockerfile.prebuilt`),运行层要一次性重建;只是 apt 安装,不在 2G 机器上编译,步骤写进 doc/09。

## 五、风险与对策

- **匿名写入是新的攻击面**。P0 不落地不开 C1;C1 上线前按二.6 逐条测一遍。
- **中文 PDF 提取质量参差**:没有 ToUnicode 映射的字体会提出乱码或空白,记为 empty,只能接受;扫描件同理。
- **2 核机器上的 CPU 争抢**:提取、缩略图、哈希校验共用 worker。回填限速加 `verify_hash` 优先;S1 实测后再定默认 worker 数。
- **手机浏览器丢上传**:收集场景的访客多在手机上,切后台丢上传会更常见。Wake Lock、页面提示,加断点续传(同一浏览器重开链接能接着传)。
- **镜像重建**:运行层一次性加 poppler,之后照旧只替换二进制。
- **schema 变化**:新增类型与查询都是加法,旧版 App 不受影响;安卓 Apollo 从同一份 schema 生成,CI 能发现漂移。

## 六、需要拍板的决策(括号里是建议)

1. 收到文件不往传输助手发消息,只在收集列表上显示"新收到 N"(建议如此:一次传 200 张照片会刷屏;现在也没有推送,发了只是多一个地方看)。
2. 收集链接只写不读,访客看不到文件夹已有内容(建议如此:想互相看就另发分享)。
3. 内容搜索默认开,精简档也开(建议如此:不依赖 Gotenberg,主要成本是磁盘)。
4. 先做收集文件,再做内容搜索(建议如此:收集文件不动镜像、自成一块;内容搜索要重建运行层、要先量数据)。

# 32 · 分享上传与自动刷新

> 3.19.0 的两件事:文件夹分享可以让对方也往里传;别处改了网盘,打开着的列表自己刷新(传输助手也是)。

## 一、分享允许对方上传

### 用的人看到的

- 分享文件夹时多一个开关「对方上传」(网页分享框、安卓分享对话框);建好以后在「我的分享」里也能随时打开 / 关掉。文件分享没有这个开关。
- 访客页的文件夹头部多一个「上传」:上传文件、上传文件夹、新建文件夹;电脑上也可以把文件、文件夹直接拖到列表上。传到访客当前所在的文件夹,传完列表自己刷新。
- 访客能做的只有往里加:**不能删、不能改名、不能覆盖**。同名的文件自动改名(`a (1).txt`);新建 / 传进来的文件夹和已有的同名文件夹合并。
- 第一次传之前问一句「留个名字」(可以不留),记在访客自己的浏览器里。名字出现在:动态(来源「分享访客」,显示「分享「旅行照片」 · 小王」)、访问记录(动作「上传文件」,带「小王 · IMG_0001.jpg」)、通知(「分享「旅行照片」收到新文件」,同一个分享 30 分钟内合并成一条,推送默认开)。
- 和收集链接的区别:收集链接是「只收不看」(访客看不到已有内容,能限个数 / 总量 / 截止);这个是「大家一起往一个文件夹里放、彼此都看得到」,适合聚会、旅行的照片合集。

### 怎么做的

- `shares.allow_upload`(只有文件夹分享能是 true;`createShare(allowUpload)`、`setShareUpload(id, allow)`)。关掉即时生效:进行中的访客上传落库时复核,失败。
- 访客的上传沿用浏览器分片会话,和收集链接一样只在开会话与落库两处分叉(`internal/service/share_upload.go`):
  - 开会话(`shareInitUpload(parentId, name, size, uploaderName)`):访客令牌指向的分享还有效、开着上传;目标是分享范围内没删除的文件夹;同一分享同时最多 20 个进行中的会话;属主配额把所有访客进行中的会话预留进去(和收集链接共用 `SumOwnerCollectPendingBytes`)。没有秒传、不收 sha256;分片地址把每片长度签进去。
  - 会话行带 `share_id`,来源(`actor`)里存着访客留的名字、开会话时的 IP 与客户端:落库在 worker 里,拿不到当时的请求。
  - 落库(`resolveShareTarget`):锁住分享行(同一分享的落库串行,挑出来的名字不会被另一个访客抢走),复核分享、开关、目标文件夹仍在范围里,再挑名字;写一条 `share_visits`(kind `upload`,`detail` = 「名字 · 文件名」)与通知。
  - 建文件夹(`shareEnsureFolder`):同样锁分享行;同名文件夹已在就返回它,同名的是文件就另取名字。
- 访客令牌 30 分钟过期:访客页拿验过的密码悄悄重领一张接着传(`call` 包一层),页面不跳回入口。
- 访问记录里多了 `uploadCount`,下载数只算 download / pack。
- MCP `create_share` 多一个 `allow_upload`。

## 二、自动刷新

### 用的人看到的

- 手机传完、网页上删了、WebDAV 拷进来、分享访客传了文件:另一台设备上正开着的那个文件夹列表自己刷新;回收站、「最近」、收藏、动态、传输助手同样。
- 网页和桌面端(窗口里就是网页)一直连着;安卓 App 在前台时连着,回到后台断开,切回来照旧刷新一次。
- 传输助手原来每 2 秒问一次服务器;连着推送时改成新消息到了就拉,轮询放慢到 30 秒兜底;推送断了自动回到 2 秒。

### 怎么做的

- **改动随事务发出**:`recordActs`(动态的记账,所有改网盘的入口都走它)、传输助手消息的增删、「最近」的打开 / 清空,在各自的事务里 `pg_notify('gopan_changes', …)`。Postgres 的通知在事务提交时才发出,回滚就不发,客户端不会拉到还没落库的东西。
- **内容只说「哪儿变了」**:`{"t":"files","f":["<文件夹 id>",""],"trash":true}`(`""` = 根目录;一次涉及超过 50 个文件夹时给 `all`)、`{"t":"chat"}`、`{"t":"recent"}`;服务端重连过数据库时发 `{"t":"resync"}`(断开期间的可能漏了,全部重拉)。文件夹本身改名、删除时它自己的 id 也在里面(正开着它的人要知道)。
- **分发**:`ChangeHub`(`internal/service/changes.go`)占一条数据库连接 LISTEN,按用户分发;断了退避重连(1 秒起,最长 30 秒)。每人同时最多 16 条推送连接;客户端读得慢就丢它的那条(下次拉照样是最新的)。关机时先关掉所有推送连接,不让 `Shutdown` 等满超时。
- **推送连接**:`GET /api/events`,Server-Sent Events,只认 `Authorization: Bearer`(不收 `?token=`,凭据不进访问日志),只给登录用户。25 秒一次心跳(nginx `proxy_read_timeout 300s`、Caddy 都不会当成闲置);`Cache-Control: no-transform` 让 Caddy 的 gzip 不攒着它,`X-Accel-Buffering: no` 让 nginx 不缓冲。连接最长 5 分钟由服务端断开,客户端带新凭据重连:移除设备、改密码最迟 5 分钟后连不上。
- **网页**(`api/realtime.ts`、纯函数在 `utils/realtime.ts`):fetch 读流(要带 Authorization 头,用不了 EventSource);事件攒 200 毫秒,按 `keysFor` 刷新对应的 vue-query 查询;页面进后台就断开;401 先刷新凭据再连;出错 2 秒起退避,最长 1 分钟。
- **安卓**(`core/network/ChangeStream.kt`):`MainActivity` 的 onStart / onStop 开关;OkHttp 读流,读超时 60 秒;收到 files 先让仓库的变更计数 +1(没开着的列表页回来时刷新),再发给订阅的页面:文件夹、回收站、「最近」/收藏、传输助手。
- 顺带修好:日志中间件包住的响应缺 `Unwrap`,打包下载、WebDAV、直链这些长响应放开 60 秒写超时的那一行从来没生效过,超过一分钟会被掐断;推送连接的 Flush 也靠它。

### 没做的

- 桌面端托盘的「新消息提醒」仍是外壳每 10 秒查一次(Rust 那边没接推送);小窗打开时已经是推送。
- 分享访客页不连推送(访客看到的是快照,刷新或进出文件夹时更新)。
